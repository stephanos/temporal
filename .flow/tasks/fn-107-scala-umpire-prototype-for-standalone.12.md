### The seam

- `AssessmentFactory{Binding() AssessmentBinding; New(ctx) (Assessor, error)}` and `Assessor{Observe(ctx, *RunEvent) error; Close(ctx, AssessmentClosure) (*AssessmentOutcome, error)}`.
- `AssessmentBinding{Case, Model, Query, Limits{MaxEvents, MaxProperties}}`. `Case` is `testpilot.CaseFingerprint(case)`. `WithAssessment` reads the binding once and keeps that copy.
- `AssessmentClosure{Disposition, Cleanup, EvaluationFailureSequence}`.
- `Assessment{Model, Query, Conformance, Properties, Failure}` with `ConformanceStatus` (conformant, nonconformant, inconclusive) and `PropertyStatus` (satisfied, violated, inconclusive), both string types.
- The Assessor gets every recorded event once, in order, each as its own clone, then the closure. Live, `Observed` feeds it each event the Contract's Monitor evaluated without error. When the Monitor stops being called (evaluation failure), the facade feeds the remaining events from the closed Run before `Close`. Replay feeds the whole closed Run. Both paths end in the same `conclude` on the same record.
- The Assessor cannot stop, fail or alter a Run: `EventObserver.Observe` returns nothing, and `Observed` returns the Monitor's own decision, error and Verdict.

If the owner adopts it later, `model/lean/Testpilot/Authoring.lean:716-720` builds a `Run` by field name and is the Lean site to check; `Protocol.lean` generates from the proto.
- **Persistence and the replay check move to the caller.** The caller stores the `Assessment` it got from `Run` (plain exported fields) and passes it to `Evaluate` as `recorded`, or nil when the Run has none. A different `Model` or `Query` is `ErrForeignAssessment`.
- **`AssessedCase` is a separate type.** `Run` must return the assessment and `PreparedCase.Run`'s signature is fixed, so the assessed path has its own type and `PreparedCase` gained no field. `prepare.go` is untouched.
- **`CaseFingerprint` is Testpilot's own identity of a Case**: hex SHA-256 of `"testpilot.case/v1"` followed by the deterministic protobuf encoding. `recordedrun.CaseIdentity` digests a producer's canonical JSON, which Testpilot never sees. The fingerprint is compared in process at `WithAssessment` and never stored.
- **Evaluation ceilings are the two the facade enforces**: `MaxEvents` (at most 100000) and `MaxProperties` (at most 10000). A model adapter's candidate ceilings stay in its factory; an adapter that wants a replay under other ceilings rejected should fold them into its `Query` identity.
- **Failure precedence.** After any assessment failure the Assessment keeps a nonconformant conformance and violated properties and reports every other conclusion as inconclusive. An outcome over the property ceiling keeps its violated properties up to the ceiling. A malformed outcome (unknown status, empty or repeated property id, support that does not ascend within the Run) is discarded whole.
- **A replay re-assesses.** It does not reproduce an Assessor failure the live Run had; with a healthy Assessor, live and replay are equal, which the tests pin.
- **State aliasing is detected by identity** for pointer, map and channel Assessors: against Assessors in flight and the last one finished, which the `AssessedCase` keeps referenced so its address cannot be reused. A value-typed Assessor that shares state through an inner pointer is not detectable, and pointers to zero-size types are exempt.
- **The live conclusion runs under a fresh bound** (`MaxTotalDurationMilliseconds`, cancellation of the caller's context ignored), as the Verdict does. `TestLiveAssessmentConcludesAfterTheRunsContextIsSpent` pins it.
- **Test-first, partly.** I recorded the red run against compile-only stubs for the first (proto-carrier) shape: 13 tests failed (`task12-logs/red.log`). After the pivot to Go values I ported those tests and wrote the implementation in the same step, so the final shape has no separate red run; the mutation check stands in for it.
