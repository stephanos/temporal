## Done summary
Qualified `TestUserTimersTestSuite` on darwin/arm64 with `gomad qualify --repeat 4` on seeds 11 and 17: identical canonical evidence per seed, every retained success replays exactly, zero watchdogs, zero `GOMAD_CAPABILITY_DENIED`. Two darwin channels were found and fixed. First, the suite never ran past schema load there: SQLite's WAL index mapping calls `sysconf(_SC_PAGESIZE)` and the darwin modernc libc adapter refused `Xsysconf` as a host capability, so every WAL database panicked; `gomadSysconf` now answers `_SC_PAGESIZE` (4096, the model's block and mapping granularity), `_SC_NPROCESSORS_ONLN` (1) and `_SC_GETPW_R_SIZE_MAX` (128) from the model, with the adapter template, darwin source-set pin and the four libc packs re-pinned/regenerated (the linux pack's replacement inventory is derived and still needs a linux/amd64 qualification run). Second, once the suite ran, same-seed runs diverged at the first run-queue decision after the first collection (ordinal 33 on seed 11, 28 on seed 17) with identical runnable sets but different physical order: a debug toolchain showed the first assist of a cycle draining different work because (a) the write barrier shaded a not-yet-marked `m` struct through `execute`'s `gp.m = mp`, and which M runs a goroutine after a syscall hand-off is host timing, and (b) an M parked through `findRunnable` kept `allpSnapshot`, so the allp array was greyed from the M in one run and from the globals in another; the assist that ends the mark phase stops on a work boundary, so the boundary moved and the runq order followed. The patch (regenerated via `patch-regenerate`) now greys every m/g0/gsignal/g at mark start in `startTheWorldWithSema` (`gomadGreyRuntimeStructures` in the overlay) and `snapshotAllp` returns `allp` without parking it in the M under Gomad; the choice-controller identity and derived wire codecs changed with the overlay. Regression fixtures: the core corpus gained `mount-reads-under-collection` (readers hand the P off through mount lookups while allocators drive collections; nondeterministic before, qualified after) and `sqlite-write-ahead-log` (Xsysconf refusal before, success after); CI now expects seven core workloads. Darwin numbers for the milestone record (task .2): seed 11 — 17 transcript records / 2176 bytes, 5774 decisions in 8140 records (781440 tape bytes), virtual time 4.008 s, wall 1.57–3.20 s, peak 663 goroutines; seed 17 — 17 / 2176, 5701 in 8008 (768768 bytes), 4.008 s, wall 1.52–1.85 s, peak 664; stderr 52 KB identical across repetitions. `TestActivityAPIBatchCancelClientTestSuite` now also qualifies on both seeds with `--repeat 2` (58.8k decisions, 4.5 s virtual, peak 1565). The manifest expectation, F5 status text and `make gomad3-qualification` CI assertion are left to task .2; the full darwin Temporal set was not rerun here.
