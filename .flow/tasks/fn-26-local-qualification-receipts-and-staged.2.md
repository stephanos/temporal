# fn-26-local-qualification-receipts-and-staged.2 Admit exact Case Runtime qualification subjects and load the Profiles

## Description
Add `tools/umpire/evaluation/admission.go`: `Admit(caseBytes, recordedRun []byte, catalog string) (*Subject, error)` (`catalog` the fingerprint to compare against: the command passes `NewWorkflowServiceCatalog().Identity()`, the goldens a fixed one) over the canonical Case (`casefile.Canonical`, then `testpilot.DecodeCaseProtoJSON`) and fn-22's recorded Run (`replay.DecodeRecordedRun`), rejecting by reason class before any assessment, in the fixed order the spec states (the Case: byte cap, canonical form, decoding, format version; the recorded Run: byte cap, decoding, event cap, the `case` field, re-encoding; then the pair: `open`, `crossed` only with a Verdict present, `inconsistent`, `malformed` Known Gap kinds, `stale`; so a legacy record without `case` is `incompatible` and a Run with no Verdict `open`): `noncanonical` (a Case not in canonical form, or a recorded Run whose bytes are not `EncodeRecordedRun`'s re-encoding of what they decode to), `malformed` (an input that does not decode; also a Known Gap whose kind is `UNSPECIFIED` or not a declared enum value), `incompatible` (a Case whose format version is not 1.0, or a recorded Run without the `case` field), `oversized` (a Case over 4 MiB, a recorded Run over 16 MiB or 65,536 events, named constants), `crossed` (the recorded Run's `case`, the SHA-256 of the canonical Case it was prepared from, is not the admitted Case's identity; the Run's `case_id` or `program_id` is not the Case's; the Verdict's rule IDs are not exactly the Contract's `rules` and `correlated.rules` together, each once), `open` (an empty Run ID, no events, a disposition or cleanup status that is absent or `UNSPECIFIED`, no Verdict), `inconsistent` (a supporting sequence naming no event or an event twice; a rule of the closed Verdict still `PENDING` or `UNSPECIFIED`; an `UNSPECIFIED` Verdict status; a Verdict status that disagrees with its rules or the disposition either way: violated exactly when some rule is violated, `STOPPED_BY_MONITOR` exactly when violated, satisfied exactly when every rule is satisfied on a `COMPLETED` Run, inconclusive otherwise), and `stale` (the recorded catalog fingerprint is not `catalog`). The recorded-Run codec, reading the canonical Case, the Case and Program crossing, the supporting-sequence check and the two-way disposition/Verdict agreement (`Agreement`) move to a leaf package, `tools/umpire/internal/recordedrun`, whose codec also rejects a duplicate or case-folded outer key, which `tools/umpire/replay` (keeping its names as aliases) and `tools/umpire/evaluation` both import, each mapping to its own reasons; replay's `ViolatedForm` (`replay/form.go`, called from `replay/rerun.go`) stays in replay, rebuilt on `Agreement`, keeping its cleanup and non-violated gates and every reason class `subject_test.go` pins. The recorded-Run format gains `case`, the canonical Case's SHA-256, computed by one helper, `recordedrun.CaseIdentity(bytes)` (`casefile.Canonical`, then SHA-256), that every writer and both admissions call, exported as `replay.CaseIdentity` because the live suite may import `replay` but not `tools/umpire/internal`; `replay.WriteRecordedRun` takes the Case bytes and computes it: `EncodeRecordedRun` takes it; `umpire-run` computes it from its fixture while parsing its configuration and, with `--record`, refuses a fixture in no canonical form before anything runs (exit 3); `umpire-fuzz --record-root` (through `campaign.DriveRecording`'s record) passes the identity of the Case it compacts; the live suite's `runRecording` takes the Case bytes its one caller already reads. Replay admission rejects a mismatch as `crossed`, and the pinned negative-control record is re-encoded with it (deterministic, sequences `{9, 19}` unchanged); `key_test.go` says a change to the control's definitions needs a live re-record. A violated, stopped Run whose cleanup failed or timed out is admitted (the `cleanup-failure-after-proved-violation` conformance shape). The crossing tests include a correlated-only Case and a regenerated Case with the same IDs against an older record. The evaluation tests import the history types the fixtures' `Any` values need. The `Subject` carries the Case identity (SHA-256 of the canonical bytes), the Run identity (SHA-256 of the canonical recorded-Run bytes), the Case, Program and Contract IDs, the recorded `DriverIdentity`, the Run's ID, disposition, cleanup and Verdict, and the Case's Known Gaps as its provenance declares them. It never prepares, runs, replays or reads an event's payload. Add `tools/umpire/evaluation/profile.go`: the rendered Profiles embedded with `//go:embed profiles/*.json`, `LoadProfile(name)` selecting only by an exact name from that set, decoding strictly and validating as Lean declares -- an unknown condition, decision or Known Gap kind, an empty table, an empty or duplicate reason name, a repeated condition, `known-gap-blocking` without a blocking kind or blocking kinds without it all reject, so `Assess` only ever receives a valid Profile -- and the Profile identity as `sha256:<hex>` of its embedded bytes, which a Go test matches against the identity pinned in Lean. An unexported `parseProfile(bytes)` does the decoding and validation `LoadProfile` uses, so the test-only Profile fixture (`testdata/test-profiles/`, outside the embedded pattern) and every load rejection are exercised here.
