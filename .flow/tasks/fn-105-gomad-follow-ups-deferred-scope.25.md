# fn-105-gomad-follow-ups-deferred-scope.25 D25: fix enhanced DescribeTaskQueue caching of report flags

## Description
Required production fix approved on 2026-09-30. Enhanced DescribeTaskQueue caches physical task-queue information by build ID and task-queue type without distinguishing the requested poller/stat fields. A cached poller response can leak pollers into a reachability-only response, and an incomplete cached response may omit subsequently requested fields. Make cache reuse and response construction respect request report flags using the established matching-cache patterns. Preserve the existing functional assertion and obtain a dedicated production code review; this is ordinary server work, not a Gomad-only fix.

- A relaxed report-flag assertion, cache-expiry wait, Gomad-only seam, classification, or unresolved production behavior cannot close this required fix.

## Done summary
Enhanced DescribeTaskQueue now keys its per-root-partition cache by the report flags that shape the cached value (`dtq_enhanced:<buildId>.<type>.pollers=<bool>.stats=<bool>`), so a response is only served partition info fetched for its own poller/stat flags. On a partial cache hit the fan-out now replaces the cached info it had collected instead of merging into it, which had double-counted stats and written the doubled value back to the cache.

`TestDescribeTaskQueueEnhanced_ReportFlags` had a second, test-side defect that the first failure masked: its readiness wait accepted the worker's poller under either task-queue type while the last request asserts one poller under each. Per the conductor's decision the wait now requires the poller under both types; no assertion, message, timeout or interval changed. Under Gomad the incomplete first response was otherwise replayed from the cache, because the suite's zero TTL is clamped to 1ns and virtual time does not advance between the calls.

Verified on darwin/arm64 (linux/amd64 not run): unit regressions red before and green after (all 64 ordered flag pairs within the TTL, expiry, build-ID/type isolation, no mutation of cached values or earlier responses); native functional test 5/5; under Gomad the test alone passes on seeds 11 and 17 and the whole `TestVersioningFunctionalSuite` qualifies on both seeds with two repetitions each. The suite's `target_failure` expectation is removed from `tests.generator.json` and the regenerated `tests.json`; the D25 bullet in `.plans/GOMAD_MILESTONES.md` "Open findings" records the outcome. Nothing is committed: the user owns the commit.
