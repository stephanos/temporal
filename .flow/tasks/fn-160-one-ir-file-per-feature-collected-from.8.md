# fn-160-one-ir-file-per-feature-collected-from.8 Drop scala. from Case identities; derive the set from the feature package

## Description
Drop the `scala.` vestige from Case identities and the strings beside it, deriving the Case id's set from the feature package instead (R15). The set once told Lean-authored Cases from Scala-authored ones; with Lean gone it says nothing, and the owner asked for it to go (2026-10-11). The seal notes in `.plans/UMPIRE_MODULES.md` froze these strings as compatibility data only because fn-155's byte comparison was running; this task lifts that freeze with a mapped identity.

**Size:** M
**Touches:** [tools/umpire/lower/**/*.go, tools/umpire/explore/*.go, tools/umpire/cmd/umpire-gen-cases/*.go, tools/umpire/cmd/umpire-run/*_test.go, tools/canary/casebinding/**, tools/canary/preflight/**, tests/testcore/testpilot/**, common/testing/testpilot/evaluation/*_test.go, model/check/Equivalence.scala, model/check/test/*.scala, model/temporal/features/**/generated/**, model/testdata/**, .plans/UMPIRE_MODULES.md]

### Approach
- One computation of the set: the lowering takes it from the IR's package root (`temporal.features.activity.standalone` today, the flat form package after R14, `protocol` for the level after R12), so `IdentityFor("temporal.case", set, query)` yields `temporal.features.<feature>.case.<query>`. Remove the `"scala."+model` string; `generateCase` no longer derives anything from the IR file name.
- Exploration: `scala.explore.<name>` becomes `explore.<name>`; the candidate digest is unchanged by R11's rule, only the prefix moves.
- Strings beside it: `umpire-scala.<feature>-<query>-activity` drops `scala`; `scala-model` provenance becomes `model`. `Equivalence.scala` reads the provenance string, so it changes with it.
- Consumers: regenerate the functional fixture tree and the canary binding's Case bytes; rewrite the Driver Profile literals that name the changed activity types or task queues, and record the diff on the task (QLF-01: a deliberate change, never a derived one). Fix the unit tests that assert literal ids (`casebinding_test`, `umpire-run/run_test`, `artifact_test`, `admission_test`, the Equivalence tests).
- Baseline: `--check-equivalence` compares against the before under a mapped identity (fn-155's projection), so the whole-tree diff is identities only; record the mapping with the task.
- Update the seal note in `.plans/UMPIRE_MODULES.md`: the strings are no longer compatibility data.
- After fn-160.2 (the package is the name's source) and fn-160.7 (the flat form folders fix the spine); sweep-time, since it touches the lowering, fixtures and baseline.
