### Finite and declared domains

1. Add `Finite: Sized` with the agreed iterator-returning domain contract, a bool implementation and derive for fieldless enums. Reuse declaration-order enumeration. Do not blanket-implement Finite for raw integer types: the admitted small integer domain comes from an explicitly bounded newtype or existing field `#[inputs]` range/list. Retain existing generic parameters and authored bounds; add only the field bounds actually needed by the generated implementation.
2. Use one authored bounded range on the single integer backing field of a range-newtype, reusing `#[inputs(lo..=hi)]` and its existing bounded-range parser. Generate Finite enumeration plus a checked scalar constructor `try_new(raw) -> Option<Self>` and `contains(raw) -> bool` from that same declaration. Validate the primitive backing width and literal bounds. No second table, blanket integer Finite, general ADT framework or implicit World validation is introduced. Raw tuple construction remains possible; O and activity admission must use the checked seam, and authored native invariants detect invalid starts/updates. Finite enumeration alone is not validation of every Rust value.
3. Retain explicit `#[inputs(range)]` and `#[inputs([values])]` behavior and old generated bytes. For new fields, use Finite when no explicit domain is supplied. `#[domain(path)]` is field-level on tuple or named fields and names a typed `fn(&World) -> impl Iterator<Item = FieldType>`. Refuse variant-level placement, duplicate/conflicting field domain declarations, a missing Finite implementation, wrong iterator item type and a missing/mismatched World context. Preserve field/variant declaration-order products, including the existing last-field-fastest ordering and explicit-list duplicate behavior. Do not regenerate existing diagnostics: in particular the existing raw-u8 `action_inputs_missing` refusal remains exact.

### Checked catalog admission

6. Keep `Machine::actions(&self) -> Vec<Action>` source-compatible. Add a defaulted fallible DSL seam, shaped as `Machine::checked_catalog(&self, limit: usize) -> Result<ActionCatalog<Self::Action>, CatalogError>`, with DSL-owned catalog/error values so DSL does not import checker. The default adapts existing Vec-returning manual worlds and checks their returned length; it cannot promise pre-allocation admission for opaque manual implementations. Generated input-bearing machines override it with count-before-materialization. Its successful catalog retains concrete actions plus optional per-variant cardinalities, including zero. The normal limit is 4096; a small additive checker/suite option supplies another limit without changing existing explore/Space call signatures. The same selected limit must reach catalog revalidation and covered/search operations. Existing worlds/expansions need no new required method.
7. Reuse ActionDomain::count, InputDomain and Fn-217's established explicit-domain controls, checked product/concatenation arithmetic and indexed value construction. Compute the entire representable catalog count before allocating its Cartesian product or evaluating any Model action. For an arbitrary finite iterator field, retain only bounded field values while counting its complete stream with checked arithmetic; do not allocate the full product or pretend the first limit+1 values are its exact size. Preserve the existing zero-factor behavior, including an empty factor paired with an otherwise overflowing range. A representable over-limit catalog returns a Refusal naming exact count and limit; arithmetic overflow is a distinct explicit refusal, not a saturated/truncated/fabricated count. No handler executes and no exploration count is published on failed admission. Accepted catalogs still attempt every concrete action, including disabled actions: filtering by enabledness must not reduce evaluated/refused counts.
8. Checker exploration/refuted/progress-catalog revalidation, suite Rooted forwarding/coverage/search, backend catalog lookups and wasm expected-action/Answer/replay paths must use checked admission rather than bypass it through raw actions(). Forward admission metadata through wrappers. Keep unchecked Vec access as a compatibility surface, not a rejection transport; do not use an empty Vec or a panic to signal a limit refusal. Map the new checker refusal through the wasm exhaustive mapper using existing refusal categories, without changing the protocol/ABI. Preserve transaction/state behavior on refusal.
9. Record a declared zero-action variant in the native report using the catalog's optional variant metadata and existing warning/report machinery. Do not invent a concrete action for that variant, increment attempted-action counts, or lose it because there are no reached starts. Legacy catalog metadata defaults to absent and preserves every old report/golden byte. Preserve typed equality for native only/without/fair: fairness applies to concrete action values, not a variant-wide union.
