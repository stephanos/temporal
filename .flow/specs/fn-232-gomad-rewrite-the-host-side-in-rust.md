# Gomad: rewrite the host side in Rust

## Goal & Context

Gomad's execution semantics already live in the Rust helper: Wasmtime, the WASI subset, the clock, World, volume, network and namespace models, the cluster broker and inspection. The Go side owns orchestration: the CLI verbs, the campaign Runner, the artifact store, records and identities, qualification, installation and the toolchain overlay. The two halves talk over a per-execution pipe with codecs generated from shared schemas on both sides.

This spec rewrites the Go host side in Rust so that one binary owns orchestration and execution. The reasons are structural, not speed: one codebase instead of two codecs per schema, the engine available in-process to inspect, replay and minimize, a single static host binary, and a host that treats Go as one guest among possible others. Go remains where it is the right tool: the runtime overlay that patches Go's own runtime, the reference models that serve as the differential oracle, and the conformance corpora that hold Rust equal to them.

Evidence compatibility with artifacts the Go binary published is not required. The Rust binary starts a new storage lineage and record schema, refuses earlier-lineage artifacts the way the store already refuses them, and is free to choose its own canonical encodings. What must survive is behavior: the same target under the same seed and profile reaches the same outcome, the same divergence ordinal, and the same failure grouping under either binary. Operators are the engineers who run campaigns locally and in CI; rigor is business-critical for evidence integrity within the new lineage.

## Architecture & Data Models

Use std and the helper's existing exact-pinned dependencies and helpers only, including rustix filesystem/locking APIs where available. Preserve the CLI grammar with a std parser and reuse existing codec/error/hex helpers and sorted BTreeMaps. No additional third-party library is authorized without a specific owner request; filesystem locks and publication must retain the existing operating-system semantics, not weakened lock-file or rename substitutes.

The Rust workspace gains a `gomad` binary crate beside the existing helper crate, which becomes a library the binary links. Executions run in-process in fresh Wasmtime stores; parallel slots are threads with the existing fuel, memory and wall-clock bounds. Minimization and qualification keep their freshness guarantee through a fresh engine and store per candidate. Process isolation per execution is out of scope.

The evidence layer is redesigned for Rust rather than ported: a versioned record envelope with a new schema name, serde-native canonical encoding with sorted keys and native integers, the same identity semantics (record hash over the canonical bytes, failure signature excluding the seed, execution identity binding target, toolchain, platform and implementation), a new storage lineage, and the same publication discipline of staging, sync and no-replace rename, retained-bytes rules and shared target pool. The Runner ports campaign control: seeds, parallel slots, failure policy, resume ledgers, choice and simulation exploration rounds, minimization and qualification. Installation and discovery port with a new installation manifest version.

Publication uses an actual atomic no-replace directory rename on the qualified platforms: Linux renameat2 with RENAME_NOREPLACE and Darwin renamex_np with RENAME_EXCL, matching the existing platform semantics. Private staging directories are managed with std and existing pinned filesystem helpers; file-persistence APIs and hard links are not directory-publication substitutes. Sync payloads, manifest/envelope and staging directories before rename, then the store directory and created parents before returning a publishable reference. On collision authenticate the existing artifact and reuse only an equivalent identity; otherwise use the existing deterministic collision policy, never overwrite. Unsupported exclusive directory-rename semantics fail closed; no new dependency is authorized by this plan.

All artifact consumers share one authenticated opener. Pin a real 0700 artifact root by handle, check its identity across opening, reject symlink roots and substitutions during open, and resolve only contained relative paths through that handle. Subsequent reads stay attached to the pinned root rather than reopening its pathname. Check lineage before manifest decoding; bound the manifest at 16 MiB and require regular 0600 files and private 0700 subdirectories. An immutable validated manifest authorizes each payload. Reject missing/unlisted entries, traversal, symlinks, wrong modes, nonregular files, unexpected hard links and pre-open/opened identity changes. Preserve the target pool's intentional module hard links; other payloads must be single-link. Each payload open enforces the caller's size bound, exact manifest size, EOF and SHA-256 on the same opened handle before use, refusing mutation or mismatch. inspect and replay must not bypass this opener.

The Go toolchain overlay stays in Go and is invoked by the Rust binary through the pinned Go toolchain as a build step, exactly as the Go Runner invokes the compiler today. The Go reference models, the protocol generator and the conformance corpora stay in Go; the generator keeps emitting the Rust codecs the binary uses, and the Go codecs the oracle uses.


**Testing strategy.** The Rust host is tested from the outside in, through fixtures and golden files, with unit tests reserved for invariants no fixture can observe.

- *Golden CLI corpus.* A checked-in corpus fixes guests, toolchain/module/configuration identities, seeds, arguments and bounds. The driver retains raw CLI outputs, manifests and ledgers, authenticates them, then compares a versioned, per-verb golden view. Canonical execution-record bytes and hashes are checked directly, without normalization, under the fixed fixture identities; payload and trace digests are independently recomputed. Raw campaign/round ledgers must pass their original hash-link, record-reference, ordinal/order and bounds checks even when diagnostic metadata makes their bytes differ.
- *Golden comparison projection.* Each verb declares exact field paths and types, never recursive wildcard masking. Only generated campaign/run IDs (consistent first-occurrence tokens), host metadata timestamps/elapsed reporting, declared scratch/output-root prefixes and replay-command path operands may be normalized. Preserve relative artifact/module suffixes and every command flag/argument. Derived ledger chain envelopes are verified on raw bytes, with their topology compared by ordinal references in the golden view, not rewritten to manufacture valid evidence. Evidence record hashes, payload/trace digests, execution/implementation identities, outcomes/status/termination, seeds, selection order/counts, failure grouping, divergence/reductions, limits, virtual time and qualification verdicts are never normalized. Unknown fields require a reviewed mapping or fail comparison. Fixture-only ID and metadata-clock providers may stabilize these diagnostic fields; they must not change production behavior or guest clocks, scheduling, watchdogs or budget decisions. Regeneration requires repeated agreement of this declared view, unchanged canonical record bytes/hashes and a byte-identical second regeneration of the golden corpus. Go/Rust comparisons remain semantic, not cross-lineage hash equality.
- *Behavioral parity harness.* The same corpus feeds the Go-versus-Rust harness until Go retires; afterwards the goldens are the regression suite and the harness is deleted.
- *Conformance corpora.* The existing Rust-versus-Go model corpora stay as they are.
- *Fault fixtures through the CLI.* Crash around stage/rename/sync, concurrent publishers, budget exhaustion, lock contention, interrupted rounds and authenticated-open attacks are exercised end to end through a `determinism-fixture`-style cargo feature. Validate raw store/ledger integrity before comparing the declared golden view. Fault and deterministic-fixture controls are absent from the release build and its accepted flags/environment; qualify and ship only the release binary without that feature.
- *Unit tests only for unobservable invariants.* Allocation-free probes, lock ordering, overlap counters and codec round-trips that a CLI run cannot distinguish. Each such test states in a comment which invariant it protects and why no fixture can.
- *Rule for changes.* A bug fix adds or changes a corpus case first; a unit test is added only when the CLI cannot observe the defect. Golden diffs are reviewed as expectation diffs, never regenerated blind.

Foundation fixture drivers may exercise execution, records and publication before public verbs exist; the actual inspect lane first passes in task .5. The corpus/comparator foundation in task .4 must not depend on that later lane. Preserve the frozen pre-fn-228 Go baseline under this spec's ownership, including executable/helper, source revision, compiler/runtime, fixture preparations, configurations and complete identities, until all fresh behavioral comparisons finish.

Verb order: `inspect`, then `replay`, then seed `explore` with `resume` and `merge`, then choice and simulation exploration, then `minimize`, then `qualify` and installation-free `report --result FILE`, then `install`, `doctor`, `discover`, `plan` and `recover`. The Rust binary is built verb by verb against a behavioral differential harness, and replaces the Go binary wholesale once every verb passes and one qualification cycle has run on the Rust binary alone. There is no period in which both binaries share an artifact root. The owner's interleaved order applies: fn-229 follows Rust inspect (.5), fn-230 follows Rust exploration (.8), fn-231 follows Rust minimize (.9), and fn-222.1 follows Rust qualify (.10). These features do not wait for retirement of the entire Go host.

### Whole-process deadline and qualification accounting

The in-process architecture cannot cancel a blocked native compiler/teardown thread through Wasmtime epoch interruption. R1 therefore requires a process-wide fail-stop deadline backstop, armed before compilation and retained through teardown. Cooperative cancellation first stops work and permits bounded cleanup; if the deadline cannot be honored, the backstop terminates the CLI with the existing infrastructure exit classification without waiting for scoped-thread joins. This ends all slots in that CLI invocation; it introduces no per-execution subprocess. Already-published records remain authenticated; incomplete staging/ledger tails are recovered through the ordinary interrupted-campaign path and never fabricated into successful outcomes. Exercise the hard backstop in an external test harness against the real CLI with fixture-only stalled compile/teardown hooks, proving bounded process exit and no surviving workers. A guest-only epoch-watchdog test does not close R1.

R9/R12 resource accounting must count linked execution exactly once. Retain raw whole-process CPU/RSS observations, thread/store concurrency and phase boundaries; never add a fictitious helper-process CPU measurement to process self CPU. Each cost component and ceiling in the old Spec/Freeze/Run/Result contract needs an explicit mapping to a measurable linked-process quantity, including compilation, concurrent stores, replay, publication and post-execution cleanup. Do not silently apply the former operator-only 2 GiB ceiling to combined helper memory or omit helper costs. Preserve the existing resource limits: if equivalent attribution cannot be measured/enforced, mark the cell unsupported/pending with the named accounting blocker and leave R9/R12 open; do not invent zero measurements, widen budgets or claim qualification. Test CPU charged once, concurrent-store aggregation, missing measurements, boundary violations and report recomputation from retained raw observations.

Qualification golden projection is distinct from canonical execution evidence. First authenticate the raw Result/PublicationReceipt hashes, their process-ID relationships, resource observations and recomputed costs/verdicts. Compare an explicit stable qualification view: cell/spec/freeze identities, selections, limits, outcomes, verdicts and referenced execution evidence. PID, measured CPU/RSS and diagnostic timing values remain retained and validated but are not byte-equality targets across real runs. The Result/receipt addresses derived from these variable observations are authenticated on raw bytes and compared as typed references, not literal cross-run suffixes. This exception applies only to qualification measurement envelopes, never execution-record hashes, module/trace digests or execution identities. Fixture lanes control resource observations to make threshold/verdict regressions deterministic; real measurement lanes must independently satisfy the unchanged limits.

## API Contracts

The CLI verbs, flags, status codes and environment variables are unchanged. `--json` result shapes may change where the new encoding makes a field redundant; every change is listed in the CLI documentation diff that ships with the verb. The behavioral differential harness runs the Go binary and the Rust binary on fresh executions of a fixed corpus of targets, seeds, profiles, scenarios and exploration plans, and compares: outcome class and termination, failure signature grouping (same executions group together under both), divergence ordinal and reason on replay of each binary's own artifacts, accepted minimization reductions by removed decision identity, and qualification verdict per cell. It reports the first difference with its path.

The Rust host's linked helper library is the default execution implementation. The existing `--helper PATH` grammar remains accepted, but it is optional rather than required for the in-process host. An explicit path must authenticate the same linked Rust implementation identity as the running binary or install refuses with the existing tool/identity refusal status; it cannot select an alternate external execution helper. Record the actual linked implementation identity and any supplied tool digest. This architecture-authorized default/requiredness change is documented with install's CLI diff; unchanged flag grammar does not require preserving the former Go launcher's external-helper requirement.

Replay's existing `--determinism-fixture` and `--stress-jitter` selectors retain their positive paths in Rust binaries linking the corresponding actual compiled helper role, with explicit opt-in and identity authorization. The former Go launcher plus matching role helper maps to one matching Rust binary, never external-helper selection. Ordinary release/qualification binaries do not acquire or activate diagnostic roles or their test-only controls; document this binary-role availability mapping explicitly rather than calling a plain-release refusal equivalent to the old launcher with a diagnostic helper. Keep host-only fixture hooks separate from helper-role feature forwarding, so enabling the host fixture corpus does not silently change every execution's helper role. Preserve actual wrong-role/profile/mutual-exclusion/refusal behavior in fixtures, and use truthful linked-feature/role identities, not a role label pretending another implementation was compiled. Repeated/concurrent role executions require fresh request-local conditions and bounded diagnostic sinks, never temporary environment mutation or process-global recorder state. This mapping preserves R14's compiled-feature exclusion; it does not authorize benign diagnostic roles in the ordinary release or waive qualification restrictions.

## Edge Cases & Constraints

Artifacts, campaigns, checkpoints and installation manifests from the Go lineage are refused by the Rust binary with the existing unsupported-format error, never migrated or silently reinterpreted. Fail-closed behavior is unchanged: unsupported operations, malformed data, identity mismatches and capacity exhaustion remain explicit outcomes. Exact replay of a Rust-published artifact under the Rust binary must be exact; byte equality of records within the Rust lineage is required so that byte-equal behavior yields byte-equal records, as today.

## Acceptance Criteria

R1 includes the compile/instantiation/teardown fail-stop and interrupted-campaign behavior above. R9/R13 include the existing public `report --result FILE` verb, installation-free authenticated result reads, independent cost/verdict recomputation and its live grammar/refusal parity. R14 applies the qualification-specific raw-authentication and stable projection above; execution evidence remains byte-exact.

- **R1:** A `gomad` Rust binary crate links the helper crate as a library and executes guests in-process in fresh Wasmtime stores with the existing fuel, memory and wall-clock bounds, and parallel slots as threads. Errors: a trap, fuel exhaustion, memory limit or watchdog timeout → the same termination classes and status codes as today; a host panic in one slot aborts the campaign with an explicit error rather than continuing.
- **R2:** The Rust evidence layer defines a new record schema with canonical serde encoding, and within that lineage byte-equal behavior yields byte-equal records: two fresh executions of the same target, seed and profile produce identical record bytes and hash. Errors: any nondeterministic field in the record fails a repeated-execution test; diagnostic paths and host timestamps are excluded as today.
- **R3:** The Rust artifact store publishes under a new storage lineage through durable staging and atomic exclusive directory rename, enforces the byte budget and shares targets through the pool. Its shared opener enforces the pinned-root containment, private-permission, immutable-manifest, bounded size/digest and link-policy contracts above. Errors: a Go-lineage artifact → unsupported-format refusal before manifest decoding; budget exceeded → the existing status; crash mid-publish → at most an unreferenced directory, never a referenced half artifact; unsafe or unauthenticated paths/payloads → refusal before consumption. A reference is returned only after required syncs, including collision reuse.
- **R4:** `inspect` in Rust reads Rust-lineage artifacts and reports the same facts the Go inspect reports for an equivalent execution, as checked by the harness on field semantics rather than bytes. Errors: a Go-lineage artifact → unsupported-format error; a corrupt manifest or a root/path/permission/link/size/digest violation → the existing open refusal through the shared authenticated opener.
- **R5:** `replay` in Rust replays Rust-lineage artifacts exactly, and the harness shows the same match or first-divergence ordinal and reason as the Go binary shows on its own artifacts for the same corpus execution. Replay consumes only the shared opener's authenticated pinned handles. Errors: identity mismatch, unsafe or corrupt payloads, missing payloads and divergence each produce today's status and message; preflight/open failures start no guest. Depends on fn-228 so the tape is validated by the helper library, not reimplemented.
- **R6:** Seed `explore`, `resume`, `execute-shard` and `merge` in Rust produce the same selection order, the same outcome classes and the same failure grouping as the Go binary on the campaign corpus. Errors: interrupted rounds resume from the last complete hash-linked round; changed bounds and identities are refused as today; a Go-lineage campaign root → refused.
- **R7:** Choice exploration and simulation exploration in Rust produce the same frontier order and the same explored-envelope report as the Go binary on the corpus. Errors: exhausted bounds report the envelope, never completion; a malformed plan is refused on open.
- **R8:** `minimize` in Rust accepts the same reductions by removed decision identity and records equivalent evidence for the corpus failures. Errors: changed bounds, corrupt state, concurrent writer and changed identities → status 3 refusals as today; a candidate that changes the failure signature → rejected.
- **R9:** `qualify`, `qualify-set`, `merge-set` and `compare-support` in Rust preserve their current WASM availability/refusal behavior and reach the same verdict per cell as the Go binary on the fixture cell and the SQLite workload, with a report bound to the candidate identities in the new schema. Errors: a failed repetition or replay fails the cell with an explicit report.
- **R10:** `install`, `doctor`, `discover`, `plan` and `recover` in Rust behave as documented, including the existing WASM refusal for native-only `analyze`, with `install` invoking the Go toolchain overlay through the pinned toolchain and pinning unchanged compiler/runtime/input digests and actual Rust binary/library implementation identities in a new manifest version. Errors: a missing or mismatched pinned tool is refused; a Go-version manifest is refused; `install` never downloads.
- **R11:** The Go toolchain overlay, reference models, protocol generator and conformance corpora remain in Go, and `make validate` keeps proving Rust codecs equal to the generated schemas and Rust models equal to the Go oracles. Errors: a corpus difference fails validation.
- **R12:** After R4 to R10 pass, one full qualification cycle runs on the final frozen Rust binary alone under the unchanged one-hour limit, including required runtime, workload and retained-replay gates, and its reports and actual identity bindings are retained. This receives the pending fn-228 R7, fn-219 R5, fn-227 R4 and fn-188 identity-triggered qualification obligations; failed/interrupted/unrun Go attempts remain historical. Then the Go host-side packages and the Go binary are removed from the default build, with archcheck enforcing that no default-set source imports them. Errors: a qualification cell failing on the Rust binary blocks retirement.
- **R13:** The mandatory local behavioral differential harness runs both binaries on fresh executions of the corpus for every public verb, comparing each binary's own identity-matching artifacts, and reports the first semantic difference with its path. CI job source is wired until R12 completes; actual CI execution is not authorized or required by this source-only delivery. Errors: a missing corpus entry or semantic difference fails the local gate, never skips or becomes advisory.

- **R15:** The behavioral reach of the retired `make -C tools/gomad test-wasm` is mapped: every original test root and named subtest maps onto a Rust suite, parity lane, transferred live root or qualification cell in `tools/gomad/testdata/parity/test-wasm-reach-map.json`, with its original assertions and bounds, or carries a one-line Go-implementation-only retirement reason. Errors: once task .14 closes, the reach reader refuses any `gap:` or `partial:` entry; until then it reports them (2026-10-24 opportunistic-merge decision). The 752 original callables are not ported one by one.

- **R14:** Every verb uses the declared per-verb diagnostic-only projection and deterministic fixture controls above, with raw canonical-record/hash and ledger-integrity verification independent of golden comparison. Regeneration under an environment flag requires repeated agreement and a byte-identical second golden regeneration. Fault/fixture features are excluded from release and qualification binaries. Unit tests exist only for invariants the corpus cannot observe and each names that invariant. Errors: a golden or raw-integrity difference fails with its path; undeclared normalization or a differing second regeneration fails; a unit test without a stated invariant fails lint.

## Boundaries

- No byte-for-byte compatibility with Go-lineage records, artifacts, campaigns, checkpoints or manifests, and no migration tool for them.
- No per-execution subprocess isolation; fresh stores in-process are the freshness mechanism.
- Preserve CLI verb/flag grammar, status codes and environment variables. The linked-helper admission/default exception above is explicit; `--json` shapes and that install requiredness change are documented per verb.
- No port of the toolchain overlay, reference models, protocol generator or corpora.
- No second guest language; the decision kinds remain Go runtime concepts.
- No performance target; speedups are not a goal of this spec.
- No broad unit-test suite; coverage comes from the golden corpus and fault fixtures (R14).
- Removing the retired native backend tree is tracked elsewhere.
- No PR, push or CI execution. Validate CI source wiring and run the required commands locally.

## Decision Context

The rewrite is scheduled on structural grounds the owner weighed against the port cost: one codec per schema, the engine in-process for inspect and replay and minimize, a single host binary, and a host shape that does not privilege Go. Performance and code size were rejected as justifications. The owner explicitly dropped byte-for-byte compatibility with existing evidence: the store already refuses earlier lineages rather than migrating them, so starting a new lineage is the existing policy applied once more, and it frees the Rust side to use serde-native canonical encoding instead of reproducing Go's JSON escaping and string-encoded integers. Behavioral equivalence on fresh executions is the gate instead, because what the tool promises is that the same target under the same seed reaches the same outcome and groups the same failures. In-process execution was chosen over re-exec isolation because Wasmtime bounds the guest and a fresh store provides the host-state freshness the fresh-process rule protected. Keeping the Go models as the oracle was non-negotiable: a Rust-only model would be checking itself. The owner chose fixture and golden-file testing over a large unit-test suite: end-to-end runs over a corpus catch regressions at the boundary users see and cost less to maintain, and the repository already runs its model and transcript corpora this way.
