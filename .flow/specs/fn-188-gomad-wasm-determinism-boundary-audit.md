## Goal & Context

Testing alone cannot prove that an arbitrary Go program running under Gomad has no remaining nondeterminism. The achievable and stronger goal is a closed contract: every influence on a WASM execution is either controlled by Gomad, recorded as a declared input, or explicitly rejected before execution, and the list of those influences is machine-checked against the code so it cannot silently grow. This spec establishes that contract for the WASM backend, guest and host together, and makes it enforceable: an inventory with a disposition for every influence, fail-closed boundaries on both sides of the guest, fresh same-seed runs under deliberate host perturbation, first-divergence diagnostics, and regression gates that every discovered escape and every toolchain or dependency update must pass. [paraphrase]

Surveyed on 2026-10-16, the pieces that exist are uneven. The Rust helper's `operations!` table is a closed import inventory (33 WASI preview1 imports, the `gomad_wasm_v1`/`v2` cooperative imports and the fn-180 `gomad_debug_v1` import); unknown imports, wrong signatures, non-function imports and disabled atomics are refused before `started`, and the Go side re-checks the frozen import list. Operations outside the stock WASI profile are refused by both the Go namespace and its Rust twin. Random and clock draws are transcribed; the diagnostic trace `gomad-diagnostic-trace/v1` carries the seven seeded draw counters at every choice point, `DiffDiagnostics` already reports the first differing record between repetitions, and the cooperative runtime qualification compares byte-identical evidence over 32 seeds by 25 fresh instances. What is missing on the WASM side: the reviewed seeded-draw and host-clock inventories cover only darwin/arm64 and linux/amd64 and have no wasip1 rows; the WASM runtime defines the host-timed-draw check `gomadDiagnosticCheckSeededDraw` as a no-op; there is no WASM soak, no deliberate host-load, layout or thread-timing perturbation (the native conformance suite has all three), no divergence report that spans cluster incarnations and the shared World order, and the README's escape catalogue (GC stamps, tracer, FIPS, `Gettimeofday`, `cputicks`) says nothing about whether each applies under wasip1. The helper's own nondeterminism sources (`Instant`, `SystemTime`, hash-map iteration, one OS thread per cluster instance) are individually believed harmless but nowhere listed.

Deployment bounds: one maintainer, Linux/arm64 development host, Flow-driven workers; evidence identity and qualification rigor as for the rest of the WASM backend.

## Architecture & Data Models

- **Determinism inventory.** One checked-in inventory for the WASM backend, schema `gomad.wasm-determinism-inventory/v1`, kept next to the WASM backend sources and read by Go and Rust tests. Each entry has: `id` (stable, append-only), `layer` (`guest-runtime`, `guest-stdlib`, `helper`, `host-go`, `engine-config`, `host-process`), `class` (`clock`, `entropy`, `scheduling`, `gc-finalizer`, `address`, `fs-io`, `network-io`, `thread-order`, `settings`), `site` (the import, function, overlay patch, type or setting it names), `disposition` (`controlled`, `recorded`, `rejected`, `escape`), `owner` (the model or package that controls it), `rule` (one sentence: how it is controlled, where it is recorded, or what refuses it), `evidence` (the test names that enforce the rule) and, for `escape` only, `justification` and the README anchor that documents it. The inventory also records the toolchain, Wasmtime and Rust versions it was reviewed against.
- **Completeness checks.** Tests derive the set of sites from the code and fail when a site has no row or a row names a site that no longer exists: every `Operation` variant of the helper's import table; every WASI op the Go and Rust namespaces accept; every seeded stream the diagnostic differ compares; every clock and draw patch the WASM overlay applies to the runtime and every runtime host-time read in `runtime_wasm.go.txt`; every `Instant`, `SystemTime`, `/dev/urandom`, `thread::spawn` and hash-map-iteration site in the helper's production sources; every `time.Now` and goroutine fan-out site in the Go host packages outside the archcheck-exempt files; every Wasmtime `Config` setting the engine sets. The existing native `reviewedDrawReferences`/`reviewedHostClockReferences` grammar is reused for the wasip1 runtime rows so one reviewer convention covers both backends; the native tables themselves are not edited.
- **Fail-closed boundaries.** Both sides refuse unlisted inputs with a classified refusal at the earliest applicable boundary: admission inputs before guest execution, runtime callback/reply inputs before dispatching the affected operation or consuming the reply: unknown or mis-typed imports and unsupported instructions (exists), WASI ops outside the stock profile (exists), unknown request fields or kinds on the Go-to-helper execute request, unknown reply kinds or fields on the helper-to-Go callback path including the fn-176 split-mode remote path, and engine settings outside the pinned configuration. The host-side broker is audited as a boundary too: every host operation the Go side performs for a guest is either a transcribed model operation or refused. The helper gains a source-scan test for the time, entropy and thread sites listed above outside an explicit allowlist (diagnostics, metrics, cache temp-file naming); the Go side extends archcheck with the same rule for the host packages.
- **Same-seed stress.** A `stress` producer runs K fresh executions of a declared workload and seed, holding declared inputs fixed and perturbing only undeclared host conditions, one axis per cell: host CPU load (busy threads, as the native conformance and soak already do), concurrent instances (`GOMAD_WASM_PROTOTYPE_PARALLEL`-style fan-out), process layout (helper restarted per execution with varied cache path length and environment size), and handoff timing (a `stress-jitter` helper feature, compiled out of the release helper, that delays cluster baton handoffs and remote replies by bounded random amounts). Each cell compares, across repetitions and against an unperturbed reference: choice tape digest and the diagnostic trace, WASI transcript digest, clock-run folding, entropy counters, model transition digests (World, network, volume, namespace), per-incarnation outputs and the shared World order. Workloads: the cooperative runtime qualification suite seeds, the fn-178 two-cluster scenario (seeds 7, 19, 42) and the single-guest workflow and activity selections (seeds 0, 1000003, 2000006). It lands as a subcommand of the fn-187.2 measurement command when that exists, otherwise as its own env-gated producer in the same shape, and is never a test target.
- **First-divergence report.** When any comparison differs, the report names the earliest differing event in helper execution order: kind (`choice`, `draw-counter`, `clock`, `entropy`, `wasi-op`, `model-transition`, `output`, `world-order`), instance and incarnation for clusters, local ordinal and shared coordinate, virtual time, and both values. It reuses `DiffDiagnostics` for the seeded counters and the fn-180 inspection coordinates (tape ordinal, trace ordinal, shared execution-order coordinate) so a divergence can be handed to `gomad replay` stop-and-inspect at that boundary. The report carries a reproducer: workload, seed, perturbation cell, both evidence digests, identities and exact rerun commands. Reproducer minimization is the prefix cut at the first divergent boundary; no new search machinery.
- **Regression gates.** Every escape found during the audit becomes a test (a helper transcript corpus case from fn-187.1 where the behavior is end-to-end, an engine refusal test, or a Go host test) and the inventory row names it; the completeness test fails when a named test disappears. The inventory's reviewed versions are pinned the way `PINNED_GO_CLOCK_SHA256` pins the clock twin: a Go toolchain, Wasmtime or Rust toolchain change fails the inventory test until the row set is re-reviewed and the pin updated. The inventory tests run in the WASM package test target and in `make -C tools/gomad validate`.

## API Contracts

- Inventory file: JSON, `schema`, `reviewed` (`go_toolchain`, `wasmtime`, `rust`), `entries[]` with exactly the fields named above. Unknown fields are a load error. `id` values are never reused; a retired site keeps its row with disposition `rejected` and the refusal test that proves it.
- Refusals: pre-execution refusals keep the existing `unsupported` outcome class and message shapes (`unknown import m::n`, `operation outside stock WASI profile: <op>`); the new refusals for unknown request fields, unknown reply kinds and off-pin engine settings use the same class with messages naming the field, kind or setting. Admission refusals precede guest execution. Runtime callback/reply validation may occur after earlier guest execution; it must refuse before the affected operation consumes invalid input, terminate promptly and report the actual execution state without mislabeling it as pre-execution.
- Stress report: one retained artifact under `.flow/artifacts/` per run with the matrix (workload by seed by axis), per-cell pass/divergence/skipped, every first-divergence report, identities (host, source, helper, module, engine, model), raw evidence digests and rerun commands. Forced replay runs are not admissible cells: a cell is a set of fresh seeded executions.
- Diagnostic trace, choice tape, transcript, model and evidence formats are unchanged; the report consumes them. The release helper's behavior and identities are unchanged except where an audit finding requires a fix, and each such fix rotates identities and reruns the WASM gates on the frozen candidate.
- Documentation contract: the WASM README gains a determinism contract section listing dispositions by class, the escapes with their justification, and the stress evidence it rests on; the top-level README's determinism section cross-references it and states for each catalogued native escape whether it applies under wasip1.

## Edge Cases & Constraints

- Seed findings the audit must dispose of, each with a row and a decision: the WASM no-op `gomadDiagnosticCheckSeededDraw` (implement the host-timed-draw check or record why wasip1 cannot host-time a draw); the still host-timed `enlistWorker` draw in the GC pacer under wasip1; GC `LastGC`/`PauseEnd` stamps under wasip1; `cputicks`, tracer and FIPS paths under wasip1; the helper's `SystemTime`/`/dev/urandom` temp-file names and `Instant` metrics; one OS thread per cluster instance under the baton; Go map ranging that feeds volume evidence before sorting; `sort.Slice` keys; serde_json map ordering; Wasmtime SIMD with NaN canonicalization.
- A disposition of `escape` is admitted only when the influence is outside the deterministic-time guarantee today, is documented in the README with its justification, and has a test that detects when it starts reaching bounded evidence. An escape that reaches bounded evidence on any stress cell is a failure, not a documented escape.
- Perturbation must not change declared inputs: environment and path variations stay outside the recorded environment and identities; a cell that would alter an identity is invalid and reported as such. The `stress-jitter` feature is refused by the Go side for any qualification role, like the diagnostic-profile and guest-profile helpers.
- Stress runs are measurement-class producers, never part of `make test`. Owner decision 2026-10-23: the full matrix runs right after the fn-232.13 cycle on the loaded host as a correctness check; every same-seed divergence is a finding regardless of load, while wall time and other timing results are recorded and judged only in the quiet-host window. Repetition counts are stated in the report; a cell with fewer repetitions than requested is `skipped`, never `pass`.
- Cluster comparisons cover every executed incarnation and the shared World order, not only the selected guest; never-started guests contribute nothing. Equal-time orderings follow recorded cluster order.
- Coordination: fn-180 owns the debug import, prefix cuts and the runtime-state witness; this spec lists the debug import as `controlled` with fn-180's tests as evidence and reuses the witness fields in comparisons rather than adding counters. fn-187.1 owns the helper transcript corpus and fn-187.2 the measurement command; the stress producer and new corpus cases follow their shapes and land after them or batch with them. fn-185 edits dispatch points for profiling; the helper source scan allowlists its diagnostic module. fn-184 isolates native; this spec does not touch native sources.
- No model semantic, protocol, evidence format or performance change is in scope; a finding that requires one is filed as its own spec and the row records the referral.

## Acceptance Criteria

- **R1:** A WASM determinism inventory exists with the schema above, and completeness tests derive every site class named in Architecture from the code and fail on a site without a row, a row without an existing site, a row without a named evidence test, or an `escape` row without justification and README anchor. Errors: an unknown inventory field or a reused `id` fails loading; a missing evidence test fails the completeness test by name.
- **R2:** Both sides refuse unlisted inputs at their applicable boundary (admission before guest execution; runtime callbacks/replies before affected-operation dispatch/consumption): unknown or mis-typed imports, WASI ops outside the stock profile, unknown execute-request fields or kinds, unknown callback reply kinds or fields including the split-mode remote path, and engine settings outside the pinned configuration, each with a classified `unsupported` refusal and a test in Rust and in Go. The helper source scan and the archcheck extension fail on a time, entropy or thread site outside the allowlist. Errors: an admission refusal after execution, or use of an invalid runtime reply before refusal, is a defect; an allowlist entry without an inventory row fails the scan.
- **R3:** The stress producer runs fresh same-seed executions over the workload, seed and perturbation matrix on one host and retains one report with per-cell results, identities and rerun commands; the retained report for the candidate shows every cell `pass` with the stated repetition count. Errors: a divergent cell fails the run and carries an R4 report; an inapplicable axis is `skipped` with the reason; a forced-replay cell or a cell that changed an identity is rejected by the producer.
- **R4:** On any divergence the report names the earliest differing event with kind, instance and incarnation, local ordinal, shared coordinate, virtual time and both values, plus a reproducer with rerun commands and the prefix cut usable as a `gomad replay` stop point. A seeded fixture that injects one perturbed draw, one shifted clock read and one reordered cluster handoff produces the expected first-divergence event for each. Errors: runs without a diagnostic trace report `undiagnosable` and the flag to enable it; comparing runs with different seeds or identities is refused.
- **R5:** Every escape found during the audit has a regression test named by its row; the inventory is pinned to the reviewed Go toolchain, Wasmtime and Rust versions and the inventory test fails on a pin mismatch until re-review; the inventory and boundary tests run in the WASM package test target and in `make -C tools/gomad validate`. Errors: deleting a named test fails the completeness test; a pin update without a re-review date in the inventory fails the test.
- **R6:** The WASM README states the determinism contract by disposition and class with the escapes and their justification, the top-level README records per catalogued native escape whether it applies under wasip1, and the claim is worded as a tested contract, never as elimination of all nondeterminism. The seed findings in Edge Cases each have a recorded decision. Errors: a seed finding without a decision, or a README claim without a backing row, is a review finding.

## Boundaries

- Native execution was retired and removed by fn-223; fn-128/fn-149/fn-184 are historical references. Read native history only where needed to reconcile WASM inventory provenance; no native execution or source restoration.
- No model semantic, protocol, evidence format, scheduler, engine or performance change; fixes beyond refusals and tests are filed as follow-up specs.
- No new minimizer mode; the reproducer is the prefix cut.
- No CI run, PR or push; the stress producer is never a scheduled job in this spec.
