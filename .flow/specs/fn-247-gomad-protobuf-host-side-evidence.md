# Gomad: protobuf host-side evidence formats and flate2 compression

## Goal & Context

The Rust host writes and reads several hand-designed binary evidence formats: `GMWSNAP1` (expanded World snapshot) inside the `GMWORLD2` gzip envelope, `GMNETEV1` (per-instance network evidence), `GMVOLIMG` (volume recovery image) and the storage evidence streams. Each format has a hand-written or `protocolgen`-rendered encoder and a bounded hand-written decoder. The heap diagnostic profile is a hand-encoded pprof protobuf (`proto_uint`/`proto_bytes`/`varint` in `wasmhost/src/linked_inspection.rs`) wrapped in hand-written stored gzip blocks. World compression is a ~1.3k-line port of Go 1.27.1 `compress/flate` (`wasmhost/src/world/deflate/`, `gzip.rs`).

These designs date from when the Go host decoded what the Rust helper wrote, with byte-for-byte conformance (fn-178.4) and identity hashes over the exact bytes. The Go host is retired; Go remains only as the reference model for conformance tests. Owner, 2026-10-24: "happy to break and simplify with prost/protobuf". Byte compatibility is not a requirement; identities and goldens that change are regenerated once (fn-246 exception, 2026-10-24).

## Architecture & Data Models

- **Schemas.** One `.proto` file per host-side format under `tools/gomad/internal/model/proto/` (World snapshot, network evidence, volume image, storage evidence). The heap profile uses the upstream pprof `profile.proto` (vendored, BSD/Apache terms retained).
- **Rust.** `prost` (pinned `=`) message types, generated by `make generate` and checked in, the same convention as `protocolgen` outputs today. Code generation uses `protox` (pure-Rust protobuf compiler), so no `protoc` binary is required. No `build.rs` code generation, so the identity closure stays a plain source scan.
- **No Go side.** fn-249 retires the test-only Go reference models before this spec, so only Rust code is generated. Conformance runs against the Rust corpus tests fn-249 captured.
- **Compression.** `flate2` (pinned `=`, `rust_backend`/`miniz_oxide`, no C) replaces the Go deflate port for the World envelope and the heap profile. The envelope keeps its expanded-size, compressed-size and SHA-256 header fields, or folds them into a protobuf envelope message.
- **Large streams.** World snapshots can reach the 384 MiB expanded bound. Encode them as length-delimited records (a header message followed by request, event and transition messages), so writing still streams and stops at the bound. Do not encode one giant message.
- **Bounds.** Every decoder checks the total byte length before decoding, then each length-delimited record against the remaining bytes and the per-field limits the current decoders enforce: counts, string bytes, payload bytes and depth. `prost`'s recursion limit stays on.

Formats that cross into the guest stay custom and out of scope: `choicewire` (rendered into the Go runtime overlay), `timewire` runtime, `net_stream_status` (toolchain overlay) and any frame the overlay decodes. The overlay cannot import a protobuf runtime, and those are fixed-size layouts.

## API Contracts

- CLI flags, verbs and JSON outputs are unchanged. Retained evidence bytes, their identities and the goldens that pin them change once.
- `make -C tools/gomad generate validate test-harness test-rust-engine validate-wasm-determinism lint-rust` and `cargo test --workspace` pass after every task.
- Old-format artifacts are not migrated. Readers refuse them with a clear format-version error.

## Edge Cases & Constraints

- The decoders reject truncated, oversized, trailing-byte, duplicate-field and out-of-order record streams. Each refusal has a catching test that mutates real encoded evidence.
- Deterministic encoding: Rust output for the same model state is byte-stable across runs, because `prost` writes fields in field-number order and record order follows the existing canonical order. A test encodes twice and compares.
- `protocolgen`'s World family (`snapshotwire.json`, `snapshotwire.go.tmpl`, `snapshotwire.rs.tmpl`, `wire_generated.rs`, `compressed_wire_generated.go`) is deleted once World moves.
- The determinism inventory, `internal/archcheck/inventory.go` exclusions and `rust/driver/static-ignored.json` (if it still exists) drop the deleted deflate and codec rows.

## Acceptance Criteria

- **R1:** An inventory classifies every custom binary format as host-only or guest-boundary, naming its writers, readers, identity uses and goldens. Errors: a format moved to protobuf that the guest overlay decodes, or a host-only format left unclassified, is a finding.
- **R2:** `flate2` replaces `wasmhost/src/world/deflate/` and the hand-written gzip framing, including the heap profile's stored-block writer. The deflate directory, its Go oracle and its inventory rows are deleted. Bounded decoding still refuses truncation, corruption, trailing data and expansion past the declared limit. Errors: a surviving hand-written deflate/gzip codec, or a decode without an expansion bound, is a finding.
- **R3:** World snapshot evidence is protobuf (`prost`), streamed as length-delimited records within the existing 384 MiB expanded and 64 MiB compressed bounds. The `protocolgen` World family is deleted. Errors: an unbounded decode, or a surviving hand-written World codec, is a finding.
- **R4:** Network evidence (`GMNETEV1`) and volume/storage evidence (`GMVOLIMG`, storage evidence streams) are protobuf with the same bound discipline. Their hand-written encoders, decoders and varint helpers are deleted. Errors: a surviving hand-written varint/frame codec for a migrated format is a finding.
- **R5:** The heap diagnostic profile is built from `prost` messages of the vendored pprof `profile.proto`, and `go tool pprof` still reads it. Errors: hand-written protobuf field encoding left in `linked_inspection.rs` is a finding.
- **R6:** Changed identities and goldens are regenerated once, with before/after identity lists recorded in `.flow/artifacts/fn-247/identities.md`, before fn-246 binds its candidate. Errors: a regenerated golden without a recorded reason, or a regeneration after fn-246 binding, is a finding.

## Boundaries

- No change to guest-boundary wires (`choicewire`, `timewire`, `net_stream_status`, overlay frames).
- No migration of old artifacts.
- No change to the helper's JSON control protocol frames, only to the binary payloads they carry.
- No CI run, PR or push is authorized by this spec.

## Decision Context

Owner, 2026-10-24: off-the-shelf crates review. The custom formats existed for Go host byte compatibility, which ended when the Go host was retired, and byte compatibility was waived on 2026-10-09. `protox` plus checked-in generated code keeps builds free of `protoc` and keeps the build identity a source scan. Rejected: also migrating guest-boundary wires, because the runtime overlay cannot carry a protobuf runtime. Rejected: `serde`/`bincode`, because its format has no cross-language Go reader for the reference model.

Sequencing (owner, 2026-10-24): after fn-249 (no Go reference model left to generate for) and fn-242, whose tasks .21 and .27 port the retained codec and World/network wire readers, and before fn-240, so the crate extraction moves the smaller code. fn-246 follows fn-240 and so binds its candidate after this spec.
