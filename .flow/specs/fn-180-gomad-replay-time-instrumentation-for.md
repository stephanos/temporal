# Replay-time instrumentation for WASM failures

## Goal & Context

A Gomad failure replays exactly, but today a developer can only see what the run itself printed. Go emits no DWARF for wasm (golang/go#33503 is unplanned), so debuggers cannot show Go variables, and adding a log line changes the binary and breaks the replay. Developers need to inspect a failing run's state at the moment that matters without losing exact replay.

The contract that makes this possible: instrumentation is always compiled in and dormant by default. When enabled at replay, it writes only to a side channel and changes nothing the guest can observe before the inspection point. That means no extra heap allocation, scheduling, clock or entropy reads, WASI I/O or choice consumption. Every instrumented replay verifies authenticated retained prefix evidence and a compulsory runtime-state witness; optional diagnostic collection alone cannot establish this contract.

## Architecture & Data Models

- **Stop-and-inspect.** A replay request names a choice index, virtual time or recorded failure, resolved to an inspectable decision boundary in one guest incarnation. The helper validates the pending recorded decision without applying it and requests a runtime-owned debug handoff. A debug goroutine, created and parked at the same initialization point in every recording and replay incarnation, runs the selected dumps and ends the replay. The handoff handles both g0 run-queue hooks and user-goroutine select hooks safely. After the prefix is sealed, dumps may allocate; all application goroutines and other cluster guests remain parked and no simulation execution resumes. Runtime GC cooperation remains available to the debug goroutine.
- **Built-in dumps:** all goroutine stacks with file and line, and a heap profile, for the selected guest incarnation.
- **Registered dumps:** programs register named dump functions at initialization (for example Temporal shard contexts, mutable-state cache, task queues). The replay request selects them by name within the selected incarnation.
- **Dormant probes.** Programs declare named probes at initialization; registration order gives each a stable ID. A probe's enabled check is a single load and branch on a host-set bitmask. An enabled probe encodes primitive values and string bytes, without allocating, into a buffer reserved at initialization in every run, and flushes it through a dedicated debug host import. The host decodes and formats the records.
- **Debug side channel:** a host import module separate from WASI and the cooperative runtime imports. Its calls never yield, never read the clock, never enter the WASI transcript or choice trace, and are not part of evidence identity.
- **Go probe library:** the server module's public, standard-library-only `common/gomaddebug` package provides probe declaration, emit, dump and invariant registration. The active variant uses `gomad && wasip1 && wasm`; complementary no-op variants cover ordinary server builds and native Gomad. Guest callers never import `tools/gomad/internal`, and the nested host module never imports this server package. Runtime/library linkage is a narrow, explicitly inventoried guest initialization seam.
- **Invariant search.** Each evaluation starts a fresh exact replay of the same artifact and evaluates the registered check only after stopping at a candidate boundary. The default is an ascending scan of the selected incarnation's choice boundaries. Binary search is an explicit optimization for a check declared monotonic over that range: once false, it remains false. Sampling cannot establish that contract. Search never carries guest or invariant state between attempts.
- **CLI:** `gomad replay` gains stop-point, target incarnation, dump, probe-pattern and bounded invariant-search options. Debug output is written next to the replay result, never into the artifact.

## API Contracts

- Replay request: optional stop point (`choice=N`, `time=T` or `failure`), target (`instance`, `incarnation`), dump selection (built-in names and registered names), probe patterns. The instance is the existing recorded node ID and the incarnation is its existing positive incarnation number; no new identity namespace is introduced. Single-guest artifacts infer their sole target; cluster artifacts require both stable recorded identifiers. Never infer a cluster target from host process order, the currently live incarnation or the first failure.
- `choice=N` is the zero-based ordinal in that incarnation's retained choice tape. Stop immediately before applying decision N, after validating its recorded site and enabled alternatives. Ordinals restart for each incarnation and are not global cluster choice indexes.
- A choice-tape decision ordinal is not a trace-record ordinal: select-result observations and other records can advance the latter without creating a decision. Retain both exact local coordinates and their mapping to a shared helper execution-order coordinate. Implement a safe inspectable handoff for every tape decision kind, including run-queue and select decisions; do not silently reinterpret `choice=N` as the next convenient boundary. Time/failure selectors resolve only against this explicit boundary inventory.
- `time=T` uses recorded shared virtual time and resolves to the first inspectable scheduler boundary of the selected incarnation at or after T. Equal-time boundaries follow recorded cluster order. Report the resolved time and boundary; never imply the guest ran at an otherwise unobservable exact timestamp.
- `failure` names the selected incarnation's recorded failure and resolves to its last inspectable scheduler boundary at or before the terminal failure. Report that boundary and its relation to the failure. If no such boundary is retained and reachable, refuse; a destroyed or trapped guest cannot be reconstructed as an inspectable post-failure heap.
- Debug output: probe records (probe name, ordered typed fields, local choice position and virtual time) and dump sections (name, bytes), bounded in size, with explicit truncation markers. Every cluster record carries instance and incarnation identifiers. Stop and search reports bind the artifact, requested target, requested stop and resolved boundary.
- Successful inspection has a dedicated `inspected_prefix` terminal/report status, carrying verified prefix cuts, witness match and requested/resolved stop. It never claims full failure reproduction or full-tape consumption. Leave normal exact replay and `runtime_finish`'s missing/extra-decision checks intact. Existing `ModePrefix` means forced-prefix exploration followed by seeded continuation and must not implement inspection.
- Invariant search request: registered check, selected target, inclusive local choice range, mode (`scan` by default or explicit `bisect`) and positive replay-attempt and wall-time bounds. Bisect requires a check registration declaring monotonic failure for that domain; the report states that its result relies on the declaration. Each evaluation uses the same recorded cluster prefix through its selected boundary, including other incarnations' effects.
- Search results distinguish first failure within the requested range, already failing at the first boundary, no failure within a fully examined range, incomplete search, invariant evaluation failure and replay divergence. Bisect's no-failure conclusion is explicitly conditional on monotonicity. A bounded partial scan can report only the range it actually checked; no mode claims the first failure outside its requested range.

## Edge Cases & Constraints

- An instrumented replay must match retained evidence up to the resolved boundary. For clusters this includes every executed incarnation's choice/WASI/network evidence and the shared World ordering, rather than only the selected guest's tape. Any mismatch is instrumentation divergence, distinct from an ordinary replay divergence.
- Preflight resolves selectors from retained evidence and refuses unknown/missing instance or incarnation, ambiguous cluster requests, invalid choice/range/time values and stops outside the retained inspectable range. Missing boundary metadata or incomplete replay evidence is an explicit unsupported/incomplete-evidence refusal before debug execution, never a guessed stop or a rebuilt guest. Failure to reach a validated boundary during replay is divergence, not successful inspection.
- Probe and dump names are scoped to the selected incarnation. Unknown names are refused before execution, not ignored; artifacts without sufficient retained registration metadata are explicitly unsupported for that request.
- A bisect request without a monotonic registration is refused before execution. Observing a false result at an earlier boundary and a true result at a later one invalidates the bisect result as a monotonicity violation. Unobserved reversals cannot be ruled out by binary search; use scan for an unconditional first-failure result within the range.
- An invariant panic, evaluation timeout or replay mismatch is inconclusive for that evaluation, never a passing or failing predicate. Exhausting an attempt/time bound returns incomplete with evaluated positions and the remaining interval, never "never fails" or an unproven earliest failure.
- Enabled probes consume fuel. If a replay approaches the recorded fuel limit, it reports that rather than mis-classifying the outcome.
- A registered dump that panics or exceeds its byte bound is reported per dump; other dumps still run.
- Output bounds: total debug bytes and per-dump bytes are capped, with truncation markers.
- Debug output is diagnostic only: never evidence, never input to identity, never published as an artifact.

## Implementation Design

### Retained prefix and registration evidence (.1–.3)

Extend the existing artifact, cooperative runtime and cluster evidence owners with one bounded, versioned inspection metadata payload. Bind that payload and its byte limits to the recorded artifact/implementation identity; debug request options and emitted debug bytes remain outside identity. Existing final WASI/network/storage digests cannot prove an arbitrary prefix. Retain the canonical bounded streams or equivalent authenticated incremental material sufficient to recompute each cut, not unauthenticated hashes claimed by the replay.

For every inspectable decision retain its target handle, tape-decision ordinal, trace-record ordinal, shared execution-order coordinate and virtual time. At the matching global cut retain each executed incarnation's choice/observation, WASI, network, storage and stdout/stderr prefix lengths and authenticated state/digests, plus shared World/lifecycle order and relevant volume/recovery state. Completed earlier incarnations use their authenticated terminal cuts; partially executed neighbors use their cuts at this stop; never-started guests contribute no fabricated execution. Retain sufficient folded-clock-run state to compare a cut inside a WASI clock run without splitting the canonical stream differently. Network validation preserves the existing structural versus composed generic-I/O payload guarantees; add no unrelated payload-hash layer.

Record a compulsory, allocation-free runtime-state witness in every instrumentable recording/replay incarnation independently of optional `--diagnostics`. Cover allocation count/bytes, GC state, goroutine and queue state, seeded draw counters and choice/observation counters at decision boundaries and the exact sealed prefix. Enabled probes must match the witness as well as external evidence; even a deliberately allocating probe whose allocation never triggers GC or changes output must be rejected under R4. Reuse the existing runtime digest fields and counters where possible; do not turn on identity-changing optional diagnostics only during replay. Debug initialization allocations and the parked debug goroutine are identical before recording/replay application initialization. Add bounded registration descriptors for dump/probe/check names, stable IDs, availability coordinates and monotonic declarations, even when disabled. Close registration at the package-initialization/main boundary; duplicate, oversized or later registration fails deterministically. Retain the completed registry and its closure marker in the recording so replay preflight can reject unknown names without launching replay; a recording failing before closure explicitly lacks sufficient registration evidence. For a stop during initialization, requested callbacks/checks must already be registered at that coordinate; built-in runtime dumps do not require guest-library initialization. Do not renumber or skip initialization tape decisions. Old, absent, corrupt, incomplete or capacity-truncated metadata cannot authorize inspection.

Existing owners: `internal/model/cluster/wasm.go` (retained incarnation/World evidence and cloning/validation), `internal/backends/wasm/cluster/{retained,provider,replay}.go`, `wasi/{runtime,process}.go`, `wasmhost/src/{model,protocol,engine,runtime_typed,abi}.rs`, existing artifact capture/replay owners and `internal/runner/replay_operation.go`. Integrate against fn-178's final incarnation-aware client and lifecycle protocol, preserving delayed/never-started `Open`/`Start`, streamed terminals, restart holds and `Finish` semantics. Provisional sibling source is design context, not qualified fn-180 acceptance.

### Runtime handoff and dumps (.2)

`toolchain/runtime_wasm.go.txt`'s `gomadChoiceDecision` and `gomadWasmStartUserCode`, and `toolchain/overlay.go`'s `runqget`/`selectgo` hooks own the handoff. A choice hook may execute on g0: never invoke Go dump callbacks there and never encode debug mode as an invalid runnable rank. Use separate typed host control plus a preallocated pending-decision record. On g0, the scheduler dispatches the precreated debug goroutine without committing the selected application decision; on a user hook it parks that user goroutine at the validated predecision boundary and transfers to the same scheduler path. Preserve the pending original decision/site/alternatives and seal its prefix before any inspection work. Test every admitted decision kind, including select observations that do not consume tape decisions.

After prefix validation, prevent every application goroutine (including timer, finalizer and cleanup user callbacks) and every other cluster guest from running; disable application World/network/time/lifecycle advancement. Permit only debug execution and required runtime GC workers/assists. Inspection allocations and stack collection cannot enter canonical prefix evidence or resume a pending application decision. Finish through the dedicated inspection terminal, with deterministic error propagation and bounded host cancellation that destroys fresh stores rather than reusing trapped/cancelled incarnations.

The runtime must not import `runtime/pprof` (import cycle). Built-ins use runtime-owned stack/frame and memory-profile primitives after the stop, emit structured PCs/frames/samples through the debug channel, and let the host encode a standard heap pprof profile. Verify the heap artifact opens with `go tool pprof`; retain existing sampling policy, and report sampling rather than claiming an exhaustive heap dump. Registered callbacks enter through the guest initialization link seam and run on the debug goroutine. A panic is isolated per callback; a callback timeout aborts that inspection, as a nonyielding callback cannot be safely recovered in the same store. Dumps must be compatible with frozen application goroutines: no callback may wait for an application-held lock or message.

### Side channel and allocation-free probes (.1/.3)

Add a dedicated debug import ABI/linker path that bypasses ordinary `runtime_typed` dispatch: that path calls `close_clock_run` and would perturb canonical WASI clock folding. The import writes only bounded diagnostic transport, never yields, advances virtual time, consumes choices/draws, changes transcript/clock/canonical counters, or makes guest-visible host calls. Read current time/coordinates from already-held model state rather than issuing clock imports. Validate guest ranges and IDs with the existing ABI conventions and bound malformed records/output; transport failure remains a debug error, not successful inspection.

Allocate the registry, bitmask, emit buffer and debug goroutine identically in every incarnation before application execution. Apply replay enablement through the separate control seam without guest allocation or runtime scheduling. The disabled call site checks `probe.Enabled()` before computing fields; the enabled typed emit surface accepts only primitive values and existing strings and copies directly into reserved storage. No `fmt`, interfaces, variadic boxed arguments, string concatenation or pre-call formatting is admitted. Bounded oversized records and buffer exhaustion increment reserved drop counters and emit counted markers without retry/yield or guest-visible effects. Host formatting happens after import. Measure disabled load/branch shape and enabled path allocation count, and verify no extra goroutines, clock reads, seeded draws or choice consumption through the compulsory witness and prefix evidence.

### Search and Temporal integration (.4/.5)

Search reuses the exact stop resolver and dedicated terminal, the closed invariant registry and a fresh cluster/helper/store for every attempt. Apply the positive wall bound to startup, replay, predicate execution and cleanup; isolate panic/timeout from predicate truth. Ascending scan is unconditional within its fully examined inclusive local range. Bisect requires the retained monotonic declaration, labels every answer conditional and invalidates observed reversals; it cannot establish unobserved monotonicity.

Temporal shard and mutable-state summaries use gomad-only immutable diagnostic views captured at existing safe mutation points, or direct nonblocking access proved safe while application goroutines are parked. Do not acquire ordinary shard/cache/workflow locks from stopped-world callbacks. Keep the selected view bounded and include its freshness/boundary in output; qualify a stop while those locks are held so the dump demonstrates useful summaries without deadlock. A retained Temporal failure recorded with the final instrumentation-enabled binary (dormant probes) supplies the R6 demonstration; rebuilding an older artifact cannot enable inspection.

### Delivery and verification

Tasks .1–.3 form one runtime/library/prefix subsystem batch, .4 adds search and .5 integrates Temporal and the final qualification. Develop coupled interfaces together; root owns integration, review and Flow completion. Change only existing owners; no parallel replay engine or new top-level nested-module directory. Rotate all affected ABI/runtime/model/helper/source identities and their inventories, strict decoders, cloning and bounds together. Preserve ordinary replay behavior and explicit unsupported old-artifact refusals.

Focused fixtures cover exact tape/trace mapping, g0 and select handoff, disabled metadata availability, witness-only allocation perturbation, cuts within clock runs, altered nonselected incarnation/World/output/storage prefixes, restarted and never-started guests, dump panic/truncation/timeout and frozen application locks. Run host-source/package and architecture checks with `-tags test_dep`, Rust helper/model suites and `make -C tools/gomad validate`; run full `test-wasm` and current-candidate cooperative runtime qualification once on the integrated runtime candidate, plus the retained Temporal failure inspection/replay demonstration. Retain one batch evidence handover with task/R-ID mapping, exact identities, commands/exits and independent review. Native execution stays deferred under fn-128/fn-149; plan review authorizes no implementation, push, PR or CI action.

## Acceptance Criteria

- **R1:** `gomad replay` resolves a choice index, virtual time or recorded failure to an inspectable boundary and writes the selected guest's goroutine stacks (file and line) and heap profile. Single-guest targets are inferred; cluster targets require recorded instance and incarnation identifiers, with local choice indexing and deterministic equal-time resolution. Reports name requested and resolved stops. Errors: unknown/ambiguous target, invalid or unreachable stop, unknown dump, unavailable registration/boundary metadata or incomplete replay evidence are refused before debug execution; replay failing to reach a validated stop is divergence; oversized output is truncated with a marker. Cover reused choice ordinals across nodes and restarted incarnations, equal timestamps, a terminated incarnation and a failure without an inspectable boundary.
- **R2:** A program can register named dump functions, and a replay can select them for its target incarnation; their output appears in the debug output. A panicking or oversized dump is reported for that dump while the others still run. No error surface beyond R1.
- **R3:** A program can declare named probes; a replay can enable them by pattern and receives their records with choice position, virtual time and, for clusters, instance/incarnation identifiers. Disabled probes cost one load and branch, and enabled probes perform no Go heap allocation. Errors: unknown probe pattern is refused before execution; probe buffer exhaustion drops records with a counted marker, never a guest-visible effect.
- **R4:** Every instrumented replay verifies retained evidence up to the resolved stop, including the shared World order and all executed incarnation prefixes for clusters. Other guests remain parked while the selected guest dumps and the replay ends afterward. A deliberately perturbing test probe (one that allocates) is reported as instrumentation divergence. Errors: missing evidence is refused under R1; divergence in any executed guest or the shared order prevents a successful inspection claim.
- **R5:** Given a registered invariant, bounded ascending scan finds the first failing choice within the selected incarnation and inclusive range, even when the predicate fails, recovers and fails again. Explicit bisect is available only with a declared monotonicity contract and labels its result as conditional on that contract. Each evaluation starts a fresh exact replay. Errors: absent monotonic declaration, unknown check, invalid range or nonpositive bounds are refused; observed monotonicity violations invalidate bisect; panic, evaluation timeout and divergence are inconclusive; exhausted search bounds report incomplete. Tests cover monotonic transitions, an early failure followed by recovery with both passing and failing endpoints, already-failing and never-failing ranges, a restarted incarnation and budget exhaustion.
- **R6:** At least one Temporal registered dump (shard and mutable-state summaries) and one probe exist and are demonstrated on a retained Temporal failure artifact. Usage documents incarnation targeting, resolved failure/time stops and scan versus conditional bisect. No error surface beyond R1–R5.

## Boundaries

- Debug logs formatted ahead of time (always formatting debug log lines during exploration so they can be captured on replay) are out of scope; they are a possible later campaign mode.
- No DWARF, no debugger attachment and no Go-aware heap walker over raw memory snapshots.
- No instrumentation of the native backend in this spec.
- Recorded runs never enable probes or dumps. They do initialize the same dormant infrastructure and retain authenticated registration/boundary/prefix metadata and the compulsory runtime-state witness; older artifacts lacking it are refused explicitly.
- Dumps inspect one guest incarnation, not an atomic cross-guest heap snapshot. A search does not order local choice indexes across incarnations or claim the first failure across the entire cluster.

## Decision Context

Owner request (2026-10-13), following the finding that the WASM backend gives function and line visibility but no variable inspection, and that upstream Go has no plan for wasm DWARF. Stop-and-inspect comes first because one replay to a point plus arbitrary dumps answers most debugging questions. Probes follow for traces leading up to the failure. Ordered after all other WASM specs in the original queue.

Owner-authorized amendment from the WASM roadmap review: make invariant search correct for nonmonotonic predicates and make cluster stop points unambiguous. Bounded scan is the general first-failure operation; bisect retains its speed only under an explicit monotonicity contract. Cluster debugging depends on fn-178's incarnation lifecycle and deterministic ordering.

Planning refinement (2026-10-15): preserve the full `choice=N` tape contract through safe runtime handoffs, separate inspected-prefix termination from seeded continuation, authenticate all cluster prefix cuts and require runtime-state verification independently of diagnostics. Public guest helpers live in `common/gomaddebug` to respect the nested module's import and directory boundaries. These additions implement existing R1–R6 under their current owners.
