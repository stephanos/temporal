# Replay-time instrumentation for WASM failures

## Goal & Context

A Gomad failure replays exactly, but today a developer can only see what the run itself printed. Go emits no DWARF for wasm (golang/go#33503 is unplanned), so debuggers cannot show Go variables, and adding a log line changes the binary and breaks the replay. Developers need to inspect a failing run's state at the moment that matters without losing exact replay.

The contract that makes this possible: instrumentation is always compiled in and dormant by default. When enabled at replay, it writes only to a side channel and changes nothing the guest can observe before the inspection point. That means no extra heap allocation, scheduling, clock or entropy reads, WASI I/O or choice consumption. Gomad's existing divergence detection verifies the contract on every instrumented replay.

## Architecture & Data Models

- **Stop-and-inspect.** A replay request names a choice index, virtual time or recorded failure, resolved to an inspectable scheduler boundary in one guest incarnation. The helper replays exactly to that boundary, then answers the scheduler hook with an "enter debug mode" decision. A debug goroutine, created at initialization in every run so recorded and replayed runs stay identical, is woken. It runs the selected dumps and ends the replay. After the stop point, dumps may allocate and run arbitrary Go code; other cluster guests remain parked and no simulation execution resumes.
- **Built-in dumps:** all goroutine stacks with file and line, and a heap profile, for the selected guest incarnation.
- **Registered dumps:** programs register named dump functions at initialization (for example Temporal shard contexts, mutable-state cache, task queues). The replay request selects them by name within the selected incarnation.
- **Dormant probes.** Programs declare named probes at initialization; registration order gives each a stable ID. A probe's enabled check is a single load and branch on a host-set bitmask. An enabled probe encodes primitive values and string bytes, without allocating, into a buffer reserved at initialization in every run, and flushes it through a dedicated debug host import. The host decodes and formats the records.
- **Debug side channel:** a host import module separate from WASI and the cooperative runtime imports. Its calls never yield, never read the clock, never enter the WASI transcript or choice trace, and are not part of evidence identity.
- **Go probe library:** an importable package providing probe declaration, emit and dump registration. It is a no-op outside Gomad and on the native backend until that backend opts in.
- **Invariant search.** Each evaluation starts a fresh exact replay of the same artifact and evaluates the registered check only after stopping at a candidate boundary. The default is an ascending scan of the selected incarnation's choice boundaries. Binary search is an explicit optimization for a check declared monotonic over that range: once false, it remains false. Sampling cannot establish that contract. Search never carries guest or invariant state between attempts.
- **CLI:** `gomad replay` gains stop-point, target incarnation, dump, probe-pattern and bounded invariant-search options. Debug output is written next to the replay result, never into the artifact.

## API Contracts

- Replay request: optional stop point (`choice=N`, `time=T` or `failure`), target (`instance`, `incarnation`), dump selection (built-in names and registered names), probe patterns. The instance is the existing recorded node ID and the incarnation is its existing positive incarnation number; no new identity namespace is introduced. Single-guest artifacts infer their sole target; cluster artifacts require both stable recorded identifiers. Never infer a cluster target from host process order, the currently live incarnation or the first failure.
- `choice=N` is the zero-based ordinal in that incarnation's retained choice tape. Stop immediately before applying decision N, after validating its recorded site and enabled alternatives. Ordinals restart for each incarnation and are not global cluster choice indexes.
- `time=T` uses recorded shared virtual time and resolves to the first inspectable scheduler boundary of the selected incarnation at or after T. Equal-time boundaries follow recorded cluster order. Report the resolved time and boundary; never imply the guest ran at an otherwise unobservable exact timestamp.
- `failure` names the selected incarnation's recorded failure and resolves to its last inspectable scheduler boundary at or before the terminal failure. Report that boundary and its relation to the failure. If no such boundary is retained and reachable, refuse; a destroyed or trapped guest cannot be reconstructed as an inspectable post-failure heap.
- Debug output: probe records (probe name, ordered typed fields, local choice position and virtual time) and dump sections (name, bytes), bounded in size, with explicit truncation markers. Every cluster record carries instance and incarnation identifiers. Stop and search reports bind the artifact, requested target, requested stop and resolved boundary.
- Invariant search request: registered check, selected target, inclusive local choice range, mode (`scan` by default or explicit `bisect`) and positive replay-attempt and wall-time bounds. Bisect requires a check registration declaring monotonic failure for that domain; the report states that its result relies on the declaration. Each evaluation uses the same recorded cluster prefix through its selected boundary, including other incarnations' effects.
- Search results distinguish first failure within the requested range, already failing at the first boundary, no failure within a fully examined range, incomplete search, invariant evaluation failure and replay divergence. Bisect's no-failure conclusion is explicitly conditional on monotonicity. A bounded partial scan can report only the range it actually checked; no mode claims the first failure outside its requested range.

## Edge Cases & Constraints

- An instrumented replay must match retained evidence up to the resolved boundary. For clusters this includes every executed incarnation's choice/WASI/network evidence and the shared World ordering, rather than only the selected guest's tape. Any mismatch is instrumentation divergence, distinct from an ordinary replay divergence.
- Preflight resolves selectors from retained evidence and refuses unknown/missing instance or incarnation, ambiguous cluster requests, invalid choice/range/time values and stops outside the retained inspectable range. Missing boundary metadata or incomplete replay evidence is an explicit unsupported/incomplete-evidence refusal before debug execution, never a guessed stop or a rebuilt guest. Failure to reach a validated boundary during replay is divergence, not successful inspection.
- Probe and dump names are scoped to the selected incarnation. Unknown names are refused before execution, not ignored; artifacts without sufficient retained registration metadata are explicitly unsupported for that request.
- A bisect request without a monotonic registration is refused before execution. Observing a false result at an earlier boundary and a true result at a later one invalidates the bisect result as a monotonicity violation. Unobserved reversals cannot be ruled out by binary search; use scan for an unconditional first-failure result within the range.
- An invariant panic, evaluation timeout or replay mismatch is inconclusive for that evaluation, never a passing or failing predicate. Exhausting an attempt/time bound returns incomplete with evaluated positions and the remaining interval, never "never fails" or an unproven earliest failure.
- Enabled probes consume fuel. If a replay approaches the recorded fuel limit, it reports that rather than mis-classifying the outcome.
- A registered dump that panics or exceeds its byte bound is reported per dump; other dumps still run.
- Output bounds: total debug bytes and per-dump bytes are capped, with truncation markers.
- Debug output is diagnostic only: never evidence, never input to identity, never published as an artifact.

## Acceptance Criteria

- **R1:** `gomad replay` resolves a choice index, virtual time or recorded failure to an inspectable boundary and writes the selected guest's goroutine stacks (file and line) and heap profile. Single-guest targets are inferred; cluster targets require recorded instance and incarnation identifiers, with local choice indexing and deterministic equal-time resolution. Reports name requested and resolved stops. Errors: unknown/ambiguous target, invalid or unreachable stop, unknown dump, unavailable registration/boundary metadata or incomplete replay evidence are refused before debug execution; replay failing to reach a validated stop is divergence; oversized output is truncated with a marker. Cover reused choice ordinals across nodes and restarted incarnations, equal timestamps, a terminated incarnation and a failure without an inspectable boundary.
- **R2:** A program can register named dump functions, and a replay can select them for its target incarnation; their output appears in the debug output. A panicking or oversized dump is reported for that dump while the others still run. No error surface beyond R1.
- **R3:** A program can declare named probes; a replay can enable them by pattern and receives their records with choice position, virtual time and, for clusters, instance/incarnation identifiers. Disabled probes cost one load and branch, and enabled probes perform no Go heap allocation. Errors: unknown probe pattern is refused before execution; probe buffer exhaustion drops records with a counted marker, never a guest-visible effect.
- **R4:** Every instrumented replay verifies retained evidence up to the resolved stop, including the shared World order and all executed incarnation prefixes for clusters. Other guests remain parked while the selected guest dumps and the replay ends afterward. A deliberately perturbing test probe (one that allocates) is reported as instrumentation divergence. Errors: missing evidence is refused under R1; divergence in any executed guest or the shared order prevents a successful inspection claim.
- **R5:** Given a registered invariant, bounded ascending scan finds the first failing choice within the selected incarnation and inclusive range, even when the predicate fails, recovers and fails again. Explicit bisect is available only with a declared monotonicity contract and labels its result as conditional on that contract. Each evaluation starts a fresh exact replay. Errors: absent monotonic declaration, unknown check, invalid range or nonpositive bounds are refused; observed monotonicity violations invalidate bisect; panic, evaluation timeout and divergence are inconclusive; exhausted search bounds report incomplete. Tests cover monotonic transitions, an early failure followed by recovery with both passing and failing endpoints, already-failing and never-failing ranges, a restarted incarnation and budget exhaustion.
- **R6:** At least one Temporal registered dump (shard and mutable-state summaries) and one probe exist and are demonstrated on a retained Temporal failure artifact. Usage documents incarnation targeting, resolved failure/time stops and scan versus conditional bisect. No error surface beyond R1–R5.

## Boundaries

- Debug logs formatted ahead of time (always formatting debug log lines during exploration so they can be captured on replay) are out of scope; they are a possible later campaign mode.
- No DWARF, no debugger attachment and no Go-aware heap walker over raw memory snapshots.
- No instrumentation of the native backend in this spec.
- No change to what recording does: recorded runs never enable probes or dumps. Required registration/boundary metadata must be retained without enabling either feature; older artifacts lacking it are refused explicitly.
- Dumps inspect one guest incarnation, not an atomic cross-guest heap snapshot. A search does not order local choice indexes across incarnations or claim the first failure across the entire cluster.

## Decision Context

Owner request (2026-10-13), following the finding that the WASM backend gives function and line visibility but no variable inspection, and that upstream Go has no plan for wasm DWARF. Stop-and-inspect comes first because one replay to a point plus arbitrary dumps answers most debugging questions. Probes follow for traces leading up to the failure. Ordered after all other WASM specs in the original queue.

Owner-authorized amendment from the WASM roadmap review: make invariant search correct for nonmonotonic predicates and make cluster stop points unambiguous. Bounded scan is the general first-failure operation; bisect retains its speed only under an explicit monotonicity contract. Cluster debugging depends on fn-178's incarnation lifecycle and deterministic ordering.
