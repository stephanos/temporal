# Shorten ordinary model authoring

## Overview

Add small, typed constructors for the most repeated inert record shapes in Core, Query, Space, and Implementation Link, then migrate ordinary Umpire and Temporal declarations. The constructors make intent visible at the call site—a named Model Value, bounded Query limits, baseline/fault Space leaves, or a forward mapping pair—without adding macros, implicit coercions, defaults that affect meaning, or a language above the existing checked DSLs.

Every raw record remains available as the expert path. Existing checkers, semantic identities, planner results, canonical artifacts, and generated bytes remain authoritative and unchanged.

## Goal & Context
<!-- scope: business -->

Model developers should write and review the domain decision rather than repeated field labels and fixed units. Shorter declarations should remain transparent Lean values that are easy to navigate, test, and expand when a non-default field is needed. End users and operators receive no behavioral or runtime change.

## Architecture & Data Models
<!-- scope: technical -->

Each constructor lives beside the record it creates:

- Core owns `ModelValue.named`.
- Query owns `QueryLimits.bounded`.
- Space owns focused baseline, binding, fault-selection, fault-axis, occurrence-fault, and seek-goal constructors.
- Implementation Link owns `.forward` constructors for value and semantic mapping pairs.

These are additive, inert functions returning the existing public records. They do not check, register, infer, canonicalize, or mutate declarations. Existing language checkers remain the sole admission and diagnostic authorities.

## API Contracts
<!-- scope: technical -->

- `ModelValue.named` pairs one Definition identity with one value string and produces the exact existing `ModelValue` record.
- `QueryLimits.bounded` accepts transition, selected-action, and candidate-evaluation bounds and fixes only their existing units. Zero and other invalid policy values remain representable and are rejected by the existing Query checker where applicable.
- Space leaf constructors fill only the established ordinary defaults: version one, no undocumented effects, and explicit caller-provided IDs/source/role/value/fault/occurrence/action/capability/subject/minimum. Non-default records remain expressible directly.
- `ImplementationValueMapping.forward` and `ImplementationSemanticMapping.forward` pair an explicit source with an explicit destination without looking up, checking, or inferring either side.
- Constructor output is definitionally or structurally equal to the record literal it replaces. No constructor changes declaration ordering, checker selection, error precedence, canonicalization, or identity.

## Approach

1. Add and test the Core named-value constructor, inventory author-written `ModelValue` literals repository-wide, then migrate every ordinary production and shared-positive-fixture pair while retaining raw mutation/negative/runtime-derived records deliberately.
2. Add the bounded Query constructor, inventory all fixed-unit triples repository-wide, and migrate every ordinary production and shared-positive-fixture declaration.
3. Add Space leaf constructors and rewrite the production Variation Space plus shared fixtures.
4. Add forward mapping constructors, inventory mapping pairs repository-wide, and rewrite ordinary production and positive Link fixtures while retaining deliberate mutations raw.
5. Document exported conveniences and run identity, planner, artifact, aggregate, regression, and lint gates.

## Edge Cases & Constraints
<!-- scope: technical -->

- Blank, non-namespaced, duplicate, unknown, wrong-kind, unavailable, incompatible, zero, or out-of-range inputs are not silently repaired. Existing checkers retain their current typed errors.
- Constructors do not infer source locations, Definition identities, roles, capabilities, occurrences, values, dispositions, bounds, baselines, or coverage minima.
- Baseline choices remain effect-free; fault selections remain request-only; coverage goals remain seek-only; mapping pairs remain inert tables.
- Existing record literals remain public and valid for non-default authoring. No deprecation, compatibility layer, macro, notation, coercion, builder object, type-class search, or callback is introduced.
- Migrations preserve every existing comment and declaration name, changing only the repeated record construction beside it.
- Definition order, source provenance, checked values, Query/Space/Link diagnostics, planner results, Behavior Fingerprints, canonical JSON, artifacts, checksums, and generated views remain unchanged.
- At ten times the declaration count, constructors add no work beyond creating the same records; checker and canonicalization complexity is unchanged.

## Acceptance Criteria
<!-- scope: both -->

- **R1:** `ModelValue.named` constructs the exact existing Definition-ID/value pair, and a repository-wide inventory proves ordinary Umpire/Temporal production declarations plus shared positive fixtures use it wherever no non-default record behavior exists. Errors: blank/non-namespaced/unknown/wrong-kind values remain representable raw input and retain their existing owning-checker diagnostic; no validation or inference is added to the constructor, and every retained literal has a mutation, negative-test, runtime-derived, or non-`ModelValue` reason.
- **R2:** `QueryLimits.bounded` constructs the exact existing transition, selected-action, and candidate-evaluation Limits with their fixed units, and a repository-wide inventory proves every ordinary production and shared-positive-fixture fixed-unit declaration uses it. Errors: zero, inconsistent, or insufficient bounds retain existing Query/Planning outcomes; custom-unit, mutation, and deliberately expanded records continue to use the raw structure.
- **R3:** Space exposes focused constructors for ordinary baseline, bound-value, fault-selection, fault-axis, occurrence-fault, and seek-goal leaves, and the production Variation Space plus shared fixtures use them. Errors: baseline effects, empty choices, unknown roles/values/faults/occurrences/capabilities, incompatible faults, invalid minima, duplicates, and bounds retain current Space diagnostics.
- **R4:** Implementation Link exposes explicit forward constructors for value and semantic mapping pairs, and a repository-wide inventory proves ordinary production mappings plus positive fixtures use them. Errors: missing, duplicate, ambiguous, wrong-kind, fingerprint-drifted, or uncovered mappings retain current Link diagnostics; constructors never perform lookup or checking, and deliberate mutation witnesses remain raw.
- **R5:** Every constructor has a concise public docstring, a direct equivalence test, facade/import visibility where intended, and no implicit DSL machinery. Errors: a macro, notation, coercion, default semantic inference, callback, registration side effect, hidden checker, or parallel record type fails completion.
- **R6:** Migrated declarations preserve names, comments, order, source provenance, checked identities, planner/Space/Link results, canonical JSON, artifacts, checksums, fingerprints, and generated views. The literal `make lint-code` gate MUST run. Its pre-edit branch-wide baseline of 1,379 golangci findings plus the existing `tools/umpire/runtime/errors.go:60:9` `errortype` finding is inherited only when the final run introduces no new or changed finding and reports no task Go path; the no-fix golangci phase scoped from `7d777dbdc8930d36a453bd3ed515e7d0a0ede77d` MUST report zero findings. Errors: eligible ordinary boilerplate remaining without a documented non-default reason, lost comment, identity/byte drift, warning, a new or changed lint finding, a task-path lint finding, or a nonzero scoped golangci finding blocks completion.

## Early proof point

Task `.1` proves the smallest constructor is a transparent exact projection over an existing semantic record and does not absorb validation. If direct equality or checker behavior changes, reconsider the additive-constructor approach before migrating any declaration.

## Boundaries
<!-- scope: business -->

- No new semantic language, facade module, builder framework, macro, notation, coercion, type class, callback, or recursive authoring form.
- No removal or deprecation of raw records and no constructor for every possible record shape.
- No new defaults for planner policy, Space bounds, field dispositions, mappings, or semantic identities.
- No change to checked-authoring, FiniteMachine, Observation, accepted traces, Known Gaps, artifact schemas, runtime behavior, or generated formats.
- No broad mechanical rewrite of intentionally custom or negative-test record literals.

## Decision Context
<!-- scope: both — conditionally substructured -->

The constructors are owned by the records they return, keeping navigation and diagnostics inside existing module boundaries. Grouping them in one migration spec is useful because they share the same additive-only contract and verification method, not because they form a cross-module abstraction.

Reject a fluent builder or macro DSL as shallower and harder to debug than plain Lean functions. Reject validation inside constructors because it would duplicate or bypass the existing checked-language boundaries. Raw records remain necessary for negative tests and deliberate non-default declarations.

Sequence after ordinary-authoring deepening so Core, Query, and Implementation Link receive these conveniences on their final public surfaces. Space remains independently owned; this spec adds only leaf constructors and does not reopen Space compilation or exploration semantics.
