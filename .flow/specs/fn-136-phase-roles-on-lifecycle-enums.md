## Goal & Context
<!-- scope: business -->
<!-- Goal & Context: 50% [paraphrase], 30% [user], 20% [inferred] -->

Every lifecycle machine in the Temporal Models writes its own set of phase predicates, and the names drift between models: what is `terminal` in one is `terminalPhase` in another, and `live` in one is `running` in the next. The activity system, the activity product, the activity record, the Nexus workflow system, the Nexus standalone system and the Nexus product each write a `states` block of hand-picked phase sets (terminal, live, waiting, held, created). Their `end` predicate and the capabilities they declare read those sets.

The owner wants "several pre-defined reusable states like \"is terminal\"" instead, but composable: no predefined set of types up front, and "each of these to be a trait" that "the actual enum" connects with. The classification lives on the phase enum, not the machine ("divide and conquer"). The enum says what each phase is. A machine only says where its phase sits, and a machine without a lifecycle (a worker, a queue) uses none of it.

This spec introduces **phase roles**: marker traits that cases of a phase enum mix in. A role is metadata, "not another state dimension". It adds no field and no state, and the lifter lowers a role test to the existing predicate IR. This is the first of three specs. Capabilities reading roles, and Retries and Deadline capabilities, follow in sibling specs.

## Architecture & Data Models
<!-- scope: technical -->

**Roles are traits.** [paraphrase] The framework provides a small open vocabulary of role traits, related by inheritance so that broader roles follow from narrower ones:

- `Live`: the entity exists and is not over. `Waiting` (exists, no attempt held), `Held` (a worker or handler holds the attempt) and `Suspended` (paused) extend it, and `Retrying` (backing off between attempts) extends `Waiting`.
- `Closed`: the entity is over. `Succeeded`, `Failed`, `Canceled`, `Terminated` and `TimedOut` extend it.

[paraphrase] A model can declare its own role by extending one of these, without changing the framework. A role is a framework role trait or a trait that extends one; a stand-alone trait is not a role, and a test against it is refused as a non-role type test. A phase with no role (`unstarted`, `unscheduled`) is one where the entity does not exist yet. "Created" is `Live` or `Closed`.

**The enum declares the roles.** [paraphrase] A case takes roles in its own extends clause: `case backingOff extends Phase, Retrying`. Scala 3 requires each such case to name its enum and refuses grouped cases with an extends clause, so the repeated `extends Phase,` is accepted. Role mixins leave `derives Finite` and the enum's values unchanged (verified on Scala 3.9.0 against the framework).

**A machine reads roles through its phase.** [paraphrase] A lifecycle machine's `end` reads a role of its phase, e.g. the phase is `Closed`. A composition reads a nested phase (`state.activity.phase`). A machine whose valid stopping point differs from lifecycle completion writes its own `end`, as `ActivityRecord` does today. No required mixin and no type parameter is added to `Machine`; where a machine names its phase once, it does so through the optional `Phased` mixin of sibling spec fn-137 ("Capabilities read phase roles").

**The lifter lowers role tests.** [paraphrase] A type test of a phase against a role (`p.isInstanceOf[Closed]`, or a `case _: Closed` pattern) lowers to membership in the set of the enum's cases that have that role, in the existing predicate IR. The IR gains no role construct: a reader of the IR sees the same case-set membership a hand-written `p.in(...)` gives. An `isInstanceOf` lowers like `in(...)`; a type pattern (a wildcard or binding under a type test, `case _: Closed` or `case p: Closed`) lowers to the alternatives of the matching case literals. A type test the compiler inserts around a constructor pattern (`case Fact.statusTimedOut(_)`, `case Some(x)`) is not a type pattern and keeps lifting as today. The cases are listed in the enum's declaration order. One role-closure computation (per enum: the cases of each role, inheritance included, and the conflicting cases) serves both the lowering and the R4 check. Today the lifter drops a type pattern and lifts it as a wildcard, which this spec replaces with the role lowering or a refusal.

**Named predicates stay first; their bodies change.** Rule headings such as `in(states.terminal)` lift to a call of the named predicate's IR Function, and `end`, Properties and compositions name those predicates too. So the `states` predicates keep their names and their callers, and only their bodies become role tests. Only a body that is a single `in(...)` listing exactly a role's cases in declaration order lifts identically, so only such bodies are replaced. `end`, an OR of predicates (e.g. `created`) and a single-case comparison (e.g. `s.phase == paused`) keep their bodies; they read roles through the predicates they call. Removing them at this step would change IR Function names and Definition IDs, which R7 forbids, so tasks .1 to .3 keep them, and those steps prove the role lowering byte-equal.

**Then the role-set predicates retire.** [amendment, 2026-10-06] Once the bodies are role tests, a predicate such as `terminal`, `terminalPhase`, `live`, `held` or `waiting` only renames a role, and its name drifts between machines, which was this spec's starting point. So callers read the role directly, and the predicate is deleted. Two short spellings make this read as well as the name did:
- **`in[R]`** in a rule heading, for the phases with role `R`: `in[Closed] ~> effects.notFound`. It lowers like `in(p1, …)` over the role's cases, through the rules' projection.
- **`p.is[R]`** on a phase value, anywhere else (`end`, effects, claims, other predicates): `s.phase.is[Closed]`, `p.is[Live] || p.is[Closed]`. It lowers like `isInstanceOf[R]`.

Both take the role's type test as a `using` argument, so there is no unchecked warning. A planning probe on Scala 3.9.0 checked that `in[R]` resolves next to the existing `in(p1, …)` and `in(set)` overloads, and that `is[R]` works as an extension. This step accepts a bounded IR change (R9): it removes the retired Functions and inlines their case sets at every former call site. Query answers and Check verdicts don't change.

**What stays in `states`.** [amendment] Only what roles can't say: single-phase and other subsets that aren't a role (`paused`, `pausable`, `running` as `started` alone), predicates over other fields, predicates over steps used by claims, constants and helpers. A derived name that combines roles (`created`, `Live` or `Closed`) keeps its name with an `is` body. A role-set predicate that a capability field still reads (`terminal` behind Closable's `terminal`) stays until fn-137 removes that field and then deletes it. The same applies to any caller that the lifter accepts only as a named definition, and to a predicate a claim names (`productTerminal`): an inline claim lambda would make the lifter synthesize a new IR Function, which R9's bound doesn't allow. A machine whose `states` empties loses the section.

**Refinements preserve closedness.** [paraphrase] Where a system machine and the product machine it refines both have role-carrying phases, a system state is `Closed` exactly when its product image is `Closed`. The IR carries no roles, so the check runs in Scala, not in the Go refinement check: a framework check enumerates the system machine's `Finite` states, runs `toProduct` on each and compares the `Closed` role of both phases through each machine's phase projection. The model tests invoke it explicitly for each role-carrying refinement; a role-carrying refinement added later must be added to those tests.

## API Contracts
<!-- scope: technical -->

- [paraphrase] **Role traits**: `Live`, `Waiting`, `Retrying`, `Held`, `Suspended`, `Closed`, `Succeeded`, `Failed`, `Canceled`, `Terminated`, `TimedOut`, with the inheritance above. They are plain traits with no members.
- [paraphrase] **Role declaration**: `case <phase> extends <Enum>, <Role>[, <Role>…]` on a `derives Finite` enum.
- [paraphrase] **Role test**: a type test of a phase value against a role, written as `isInstanceOf` or as a type pattern in a match. *Amended:* or as `p.is[R]`, or as `in[R]` in a rule heading. The lifter lowers these four forms and no other role form.
- [amendment] **`in[R](using TypeTest[P, R])`**: a rule case holding in the phases with role `R`, read through the rules' projection.
- [amendment] **`extension [P](p: P) def is[R](using TypeTest[P, R]): Boolean`**: the role test as a method. It is distinct from fn-135's `is { }` predicate block, which takes a block and no receiver.

## Edge Cases & Constraints
<!-- scope: technical -->

- [inferred] Contradictory roles are refused: a phase that is both `Live` and `Closed`, one that has two of `Waiting`, `Held` and `Suspended`, or one that has two closure roles. Roles a model declares itself take part only through the framework roles they extend.
- [paraphrase] A pending request is not a role. Activity models a cancel request as a phase (`cancelRequested`), while Nexus standalone models it as a Boolean field, so a phase role cannot describe both. `pauseRequested` and `cancelRequested` are `Held`.
- [inferred] A role test on a type that is not a finite enum, or on a role no case of the enum has, is refused instead of lowering to an empty or unbounded set.
- [amendment] `in[R]` in rules that declare no projection is refused, as `in(p1, …)` is. `is[R]` on a value that is not a phase of a role-carrying enum gets R3's refusals.
- [amendment] A retired predicate that a caller outside its machine reads (`TrustingCaller` reads `NexusSystem.states.terminalPhase`, and the activity and Nexus compositions read their member's) is replaced at that caller too. WithTaskQueue reads only keeps (`terminal` for Closable, `running`). No forwarding alias is kept.

## Acceptance Criteria
<!-- scope: both -->

- **R1:** [paraphrase] The framework provides the role traits `Live`, `Waiting`, `Retrying`, `Held`, `Suspended`, `Closed`, `Succeeded`, `Failed`, `Canceled`, `Terminated` and `TimedOut`, with `Waiting`, `Held` and `Suspended` extending `Live`, `Retrying` extending `Waiting`, and the five closure roles extending `Closed`. A model can declare its own role by extending a framework role, without changing the framework; a test against it lowers to the cases carrying that trait. No error surface beyond R3 and R4.
- **R2:** [paraphrase] A case of a `derives Finite` phase enum declares roles in its extends clause, and its `Finite` instance and values are the same as without roles. A case with no role is allowed. No error surface beyond the compiler's own enum rules.
- **R3:** [paraphrase] The lifter lowers a type test of a phase against a role, whether `isInstanceOf` or a type pattern (a wildcard or binding under a type test), to membership in the set of that enum's cases having the role, in declaration order, including roles inherited through a narrower one (a `Retrying` case is `Waiting` and `Live`). The IR has no role-specific construct. Errors: a role test on a value whose type is not a finite enum is refused by the lifter, naming the position; a role test that no case of the enum satisfies is refused, naming the role and the enum; a type test or type pattern against a type that is not a role (including a stand-alone trait) is refused instead of lifting as a wildcard; a compiler-inserted type test around a constructor pattern is not a type pattern and lifts as today.
- **R4:** The lifter refuses a phase enum in which a case is both `Live` and `Closed`, has more than one of `Waiting`, `Held` and `Suspended`, or has more than one closure role, naming the case and the conflicting roles. The check runs on every role-carrying enum when it is declared, not on first use, and on roles after inheritance closure (`Retrying` with `Waiting` is not a conflict). A model's own role takes part only through the framework roles it extends. Errors: this criterion is the error surface.
- **R5:** [paraphrase] The activity system and product, the activity record's admission phase, the Nexus workflow and standalone systems and the Nexus product declare roles on their phase enums, and every `states` predicate whose body is a single `in(...)` listing exactly a role's cases in declaration order (terminal, live, running, waiting and held sets) becomes a role test; the predicates keep their names and callers. `end`, OR-composed predicates such as `created` and single-case comparisons such as the product's `paused` keep their bodies and read roles through the predicates they call; `ActivityRecord.end` stays `stopped`. The activity record's `pausedWhileHeld` takes no role in this spec, so its sets that include it stay hand-written; its role is decided in fn-137. Inline phase comparisons outside the `states` sets (e.g. the Nexus start-to-close rule's `phase == started`) are left as they are. The worker and task queue machines declare no roles. No error surface beyond R3 and R4. (*Amended:* R9 then retires these predicates, so "keep their names and callers" holds only through task .3.)
- **R6:** [paraphrase] For each Refinement whose system and product phases both carry roles, a system state is `Closed` exactly when its product image is `Closed`, checked in Scala over every `Finite` system state; a violation fails the model tests naming the system state and its image. Every role-carrying refinement (the activity system's, the activity record's `ActivityRecord.refinement` and `HeldDispatch.refinement`, the Nexus workflow's and the Nexus standalone's) is checked by name. Errors: a refinement whose machines carry no roles (the task queue's) is not checked, and this is not an error.
- **R7:** Each regeneration of R1 to R6 (tasks .1 to .3) leaves every Query answer, Check receipt, Definition ID, exploration identity and Case byte unchanged, because role tests lower to the same case sets, in the same order, as the hand-written predicates they replace; the IR diff is limited to source positions. Errors: any other difference, including a reordered case list, stops the change until the role lowering or the role assignment reproduces the old set. *Amended 2026-10-06 (batching, see MILESTONES.md):* the tasks run in the DSL batch without their own regenerations; R7 and R9 are checked at the batch's single regeneration against the batch baseline.
- **R8:** [amendment] The framework provides `in[R]` for rule headings and `p.is[R]` for phase values. The lifter lowers each to the same case-set membership as the equivalent `in(p1, …)` and `isInstanceOf[R]`, in declaration order, and the build has no unchecked warning. Errors: `in[R]` in rules with no projection is refused at compile time and by the lifter, naming the fix. `in[R]` and `is[R]` against a non-role or on a non-enum value get R3's refusals.
- **R9:** [amendment] Every `states` predicate whose body is a single role test is deleted, and its callers (rule headings, `end`, effects, claims, compositions and other machines) read the role directly with `in[R]` or `is[R]`. The predicates that stay are listed in the task's summary, each with its reason: a capability field reads it until fn-137, the lifter needs a named definition, or it is not a role set. A section left empty is removed. Errors: none beyond R3 and R8. IR contract: every Query answer and Check verdict is unchanged. The IR diff is limited to removing the retired Functions, putting their case-set membership at each former call site, and the Definition IDs, exploration identities and Case references that follow from those. The task records a diff summary that classifies every changed line. Any other difference stops the change.

## Decision Context
<!-- scope: both -->

[paraphrase] Three shapes were weighed. A Boolean constructor parameter (`case scheduled extends Phase(false)`) adds one positional flag per classification and doesn't scale past "is terminal". A predefined `Stage` enum with a total `stage(p)` map on the machine gives exactly one stage per phase, but fixes the vocabulary up front and puts the classification on the machine instead of the enum. Marker traits on enum cases keep the vocabulary open, put the classification where the phase is defined, and derive broader roles from narrower ones through inheritance. The cost is losing the stage enum's guarantee that a phase sits in exactly one stage, which R4 restores. [paraphrase] The repeated `extends Phase,` is required by Scala 3: omitting the enum (`enum case does not extend its enum`), grouping cases (`case a, b extends …`) and an intermediate parent class (`extending enums is prohibited`) are all refused by the compiler.

[paraphrase] This spec is one of three split from one conversation: it comes first, after fn-132 and fn-135 close (both edit the same phase predicates); fn-137 ("Capabilities read phase roles") depends on it, and fn-138 ("Retries and Deadline capabilities") depends on that.

[amendment] Keeping the role-set predicates forever was rejected: the names would keep drifting (`terminal` vs `terminalPhase`, `live` vs `running`), which is what this spec set out to fix, and `states` would keep restating what the enum says. `p.isInstanceOf[Closed]` at every call was rejected as too noisy, which is why the earlier draft kept the names. `in[R]` and `is[R]` remove that reason. Retiring in a separate step after the byte-equal tasks keeps the role lowering proven before any IR changes. `p.isA[R]` was considered so as not to reuse `is` from fn-135's `is { }`. It was rejected because `is` reads as the sentence ("the phase is Closed"), and the two never meet: one takes a receiver, the other a block.

Maintainability (plan review, amendment): duplication - none identified; structure - Expressions.scala `lift` absorbs the `isInstanceOf`/`is[R]` branches and irgen Syntax.scala `sugar` the `in[R]` form; both delegate to the role-closure module

Maintainability (plan review): duplication - none identified; structure - `lift` in `Expressions.scala` (the central match) absorbs the new `isInstanceOf` branch and `pattern` the role branch; keep both thin by delegating to the role-closure module.
