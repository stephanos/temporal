## Goal & Context

The Umpire IR was the specification Go interpreted. With the Scala checker as the oracle and every Model-reading tool moving to Scala, the IR has one remaining job: a tree representation of Model bodies that text emitters (Quint, TLA) walk. That job does not need checked-in JSON, a public schema contract, a strict loader, an equivalence dumper or a Go sample check. This spec renames today's exporter to the lift module, stops writing IR files, deletes the checked-in IR and every gate step that settles against it, moves the IR proto into the framework, decides the numeric contract, and recuts fn-192 so builtin semantics live in the checker and the Scala emitters. Fingerprints computed from IR bytes are recut once, with the managed Cases regenerated by fn-203.

## Architecture & Data Models

- `framework.lift` is the plugin-captured tree and the lifter, package-private to the framework. Its output is an in-memory `Lifted` value; no file is written by default. A debug flag writes ProtoJSON to a caller-named path for inspection only.
- The IR proto moves under the framework's proto directory and is generated into the ScalaPB jar from there. Nothing in Go imports it after fn-208.
- Deleted: the checked-in IR directory, the per-feature `generated/ir.json` files, the lift-and-settle loop of the model gate, the interpreter-table equivalence and its external dumper, the Go sample check embedded in the Scala gate, and the identity normalisers that existed to hash IR content.
- Fingerprints and Case identities derive from the lifted tree's canonical form; the canonical encoder moves into the lift module and is byte-stable from this spec on. Their first values differ from today's; fn-203 regenerates the Cases once.
- Numeric contract: the checker's host semantics (signed 32-bit `Int`, wrapping) are the Model's semantics. The IR's checked signed 64-bit contract is retired; emitters translate `Int` as the backend's integer and state the bound in the module header. The owner may instead choose a checked bound; the decision is recorded before fn-205 starts.
- fn-192 recut: the builtins table remains the one list of operators; the checker executes them as Scala and each Scala emitter owns its translation; the conformance test holds the table, the checker and each emitter to the list. The Go interpreter row is removed.

## API Contracts

- `Lift.of(instance): Lifted` returns the tree for a checked instance; `Lifted.canonical: Array[Byte]` is the byte-stable encoding fingerprints hash.
- `Lift.debugWrite(lifted, path)` writes ProtoJSON; it is never called by a gate.
- No Make target reads or writes `model/ir`; `umpire-check-model`'s lift, settle and sample-check steps are removed, and the remaining steps are renamed under the framework check.

## Edge Cases & Constraints

- The export fixtures (454 Scala files) currently fail on retired vocabulary; this spec lands after the Phase 4 lifting tasks that re-anchor them against the final DSL.
- The lifted tree must still refuse what emitters cannot write (holes, channels, unwritable choice names); refusals move with the tree.
- The ScalaPB jar for the IR is generated from the new path; the API jar is unaffected until fn-202.
- Deleting the checked-in IR removes the Go packages' test inputs; those packages are deleted by fn-208 and their tests are not maintained in between.

## Acceptance Criteria

- **R1:** `framework.lift` replaces the exporter: same tree, no file written by default, a debug write on request. Errors: a Model the lifter cannot capture refuses with the existing capture diagnostics.
- **R2:** The checked-in IR, the generated IR files, the lift-and-settle gate steps, the equivalence dumper and the embedded Go sample check are deleted; the framework check passes without them. No error surface.
- **R3:** The IR proto lives under the framework and the IR ScalaPB jar is generated from there. Errors: a stale jar fails naming the generation target.
- **R4:** Fingerprints and Case identities derive from `Lifted.canonical`, byte-stable under a pinned test; their first values are recorded for fn-203's regeneration. No error surface.
- **R5:** The numeric contract is decided and recorded (host `Int` or a checked bound); SEMANTICS and the builtins table state it; the IR's int64 wording is removed. No error surface.
- **R6:** fn-192 is recut: the builtins table, the checker and each Scala emitter are held to the list by one conformance test; the Go interpreter row is deleted. Errors: an operator in the table with no emitter translation fails the test naming the emitter.

## Boundaries

- No emitter is written here (fn-205, fn-207).
- No Go package is deleted here (fn-208); they merely lose their inputs.
- No Temporal Model is lifted; Temporal sources stay disabled.
