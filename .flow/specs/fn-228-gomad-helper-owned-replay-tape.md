# Gomad: helper-owned replay tape validation

## Goal & Context

Exact replay validates the choice tape in two places. The Runner decodes the retained choice trace, projects it into a replay plan, checks the plan digest, serializes the plan into JSON tape chunks, and after exit decodes the helper's choice bytes a second time to compare digests and counts. The Rust helper independently decodes the chunks and performs the per-decision comparison. The Go reference session keeps a third per-decision comparison that runs only under split-owned differential mode and the conformance corpora.

This spec makes the helper the single owner of replay-time tape validation. The Runner hands it the retained trace bytes with the expected identities; the helper projects, validates, replays and reports. The Runner keeps one codec for inspection, identity and publication, and the Go reference session stays as the differential oracle. Rigor is business-critical for evidence integrity: a replay that reports a match must be exact, and nothing here may weaken that.

## Architecture & Data Models

The current Go/helper pipe carries LF-terminated JSON only. This change adds an explicitly versioned replay-trace binary block on that pipe; it does not assume an existing binary-frame transport. The Runner sends the retained trace and expectations, and the helper derives the decisions. The helper library exposes the same bounded preflight to the in-process Rust host from fn-232 without making that caller serialize through the pipe.

The helper gains a replay-plan projection equivalent to the Runner's: filter decision records, carry each select result's readiness onto the poll decisions of the same select, encode and hash the plan. The helper model configuration carries mode, limit, execution identity, expected trace digest, expected tape digest and expected decision count. The helper terminal gains the complete trace digest, record count and branching count. Prefix replay also carries separate typed controller input; a controller-forced rank is never forged into retained trace evidence.

A new conformance corpus holds the Go and Rust projections equal on retained trace fixtures, regenerated like the other corpora: two passes, byte-identical.

## API Contracts

The LF-terminated JSON replay declaration carries `{schema, mode, limit, execution_identity, trace_sha256, tape_sha256, decisions, trace_bytes, trace_frames}`. The new schema identifies this framing; old senders and receivers fail closed on version mismatch. Before allocation, require `trace_bytes <= limit` and `trace_frames = ceil(trace_bytes / 65536)`, with checked arithmetic. Each binary frame has a four-byte unsigned big-endian payload length followed by exactly that many raw trace bytes. Frame payloads are 65,536 bytes except the final remainder; zero-length frames are invalid. Their aggregate must equal `trace_bytes`. A zero-byte replay has zero binary frames. Record mode permits no trace block. Exact replay accepts trace evidence only and refuses prefix controls.

The binary block immediately follows its declaration at the replay-input point, before any subsequent JSON control input or guest instantiation. One buffered reader owns both JSON and binary reads. After the declared frames, an LF-terminated JSON `replay_trace_end` marker repeats the schema, frame count and byte count. Preflight consumes and validates that marker before starting a guest; truncated lengths/payloads, extra frames, missing/wrong markers and arithmetic overflow are refusals. This explicit end marker prevents undeclared bytes from being accepted as a completed trace block.

Cluster initial execution and manual start/restart use the same admission contract bound to the intended node and incarnation. Their runtime declarations carry the replay declaration and optional prefix control instead of `tape_chunks`. A tagged LF-JSON block declaration and end marker carry node/incarnation plus schema/counts; the intervening length-prefixed binary payload is read verbatim under the same attributed block. The shared input reader and writer serialize the entire declaration/block/end-marker transaction so blocks cannot interleave. Update both automatic and manual cluster input adapters; never split binary payload on LF or feed it through the old tagged-JSON line decoder. Wrong/stale node or incarnation attribution, missing declarations, malformed/truncated frames and extra bytes refuse admission before that guest is instantiated, preserving the existing cluster transport refusal classification.

Helper preflight failure reports `{error: "replay_preflight", check}` naming framing, schema, execution identity, trace digest/decode, tape digest or decision count. The Runner preserves the corresponding existing refusal status. Admission precedence is transport/schema, execution identity, trace digest, trace decode, projection/resulting tape digest, then expected decision count. Every check completes before instantiation or guest start. Helper exit terminal adds `{trace_sha256, records, branching_records}` beside the existing fields. The divergence terminal shape is unchanged.

Prefix mode additionally accepts bounded typed `prefix_control` containing a decision cutoff and, when required, one final-decision rank override with its ordinal, rank and reconstruct-versus-new-alternative intent. The helper first validates/projects the source trace, then applies the existing `Prefix`, `BuildRankPrefix` or `BuildForcedRankPrefix` semantics and canonical tape encoding. The cutoff cannot exceed the projected decision count; an override must address the final retained branching decision, exclude select-result records, satisfy alternative/rank bounds and enforce the existing observed-versus-nonselected rank rule. Validate the resulting tape digest, source binding, execution identity and expected decision count against the request before execution. Controller controls are bounded independently of trace bytes; malformed/extra controls are refused. Preserve all currently permitted `ChoiceCapability.ReplayPlan` controller producers across exploration, minimization and backend adapters; transport them through this distinct prefix-control path without converting rank overrides into observed trace records or narrowing their valid constructions. Exact replay never accepts an override and the Runner does not project a tape on its replay execution path.

## Edge Cases & Constraints

The choice trace wire format, canonical replay-plan projection and encoding, decision semantics and existing Go record schema remain fixed. Helper source/binary and embedded WASI/model implementation identities rotate when their inputs change; record every old/new value and cause with full hash coverage. Do not preserve stale digests or promise that an artifact bound to an earlier implementation replays under the changed implementation. Identity and request-version mismatches fail closed.

Preserve a frozen pre-change Go executable, matching helper, source and preparation receipts under fn-232 ownership for fresh behavioral equivalence. Compare each implementation's fresh executions and replay its own identity-matching artifacts. fn-232's new Rust storage lineage refuses Go-lineage artifacts and manifests; this spec adds no migration. Final runtime/workload/replay qualification of the changed Rust candidate belongs to fn-232 R12 and task .13. Before fn-228 closes, its ledger and receiving task must record that outstanding obligation explicitly; focused corpus/source passes do not substitute for it.

## Acceptance Criteria

- **R1:** When the Runner replays an artifact with a choice profile, it passes the retained trace bytes, trace digest, execution identity, expected tape digest and expected decision count to the helper and does not project a replay plan on the execution path. Prefix requests additionally pass only the bounded typed cutoff/override controls; exact requests forbid them. Errors: unreadable trace payload → replay preflight error, status unchanged from today; trace digest mismatch against the manifest → same.
- **R2:** Before the guest starts, the helper verifies the trace digest, projects the replay plan, and verifies the projected tape digest and decision count against the supplied expectations. Errors: any check fails → helper refuses to start, replies with the preflight error naming the failed check, and the Runner surfaces it as a replay preflight error with the same status code as today.
- **R3:** During exact and prefix replay the helper validates kind, site, enabled alternatives, alternative-set digest and selected rank at every decision, and reports tape exhaustion and unconsumed tape, exactly as today. Prefix cutoff and final rank-override behavior match the Go oracle's Prefix/BuildRankPrefix/BuildForcedRankPrefix semantics; rank overrides remain controller input rather than trace evidence. Errors: first mismatch → divergence terminal with ordinal, reason, expected and observed decision; no new error surface.
- **R4:** On exit the helper terminal carries the complete trace digest, record count and branching count, and the Runner compares those three against the manifest without decoding the trace bytes a second time. Errors: any mismatch → the existing `choice_profile.trace.*` divergence strings, unchanged.
- **R5:** When a storage crash interrupts replay, the helper reports the validated cursor, tape decision count and complete next-unconsumed decision/divergence payload when the cursor is below that count. The Runner preserves the existing unconsumed-tape reason and Expected decision without reconstructing the input tape from the observed prefix. At end-of-tape the terminal carries no next decision; the existing interrupted evidence projection may still consume observed bytes. Errors: cursor beyond the admitted count, inconsistent tape identity/count, missing next decision below the count or unexpected/misnumbered next decision at the end → invalid helper terminal.
- **R6:** The Runner still decodes the choice trace for inspection, identity derivation, publication and minimization evidence. No error surface beyond the existing decoders.
- **R7:** Existing replay corpus scenarios produce the same match, divergence ordinal and divergence reason on fresh baseline and candidate executions, each replaying its own matching artifacts. Preserve the frozen Go baseline and exact source/helper/model identity ledger for fn-232's harness. Record the pending full Rust-candidate qualification transfer to fn-232 R12/task .13 before closure. Errors: incompatible historical implementation identities are refused, never relabeled or treated as successful replay; a missing comparison or unexplained identity rotation blocks acceptance.
- **R8:** A conformance corpus of retained trace fixtures holds the helper projection and the Runner projection byte-equal with equal tape digests, and a second regeneration pass is byte-identical. The corpus includes shortened/zero/full prefixes, valid and invalid final rank overrides and reconstructed forced prefixes, including selected-identity/readiness and digest equality. Errors: a projection difference fails the corpus test; a non-identical second pass fails regeneration.
- **R9:** The Go reference session and the split-owned differential mode remain and keep routing runtime ops to it. No error surface beyond today.
- **R10:** The versioned trace block follows the exact declaration, length-prefix, 64-KiB chunk, aggregate-limit and end-marker contract above. Validate lengths/counts with checked arithmetic before allocation or instantiation. Errors: oversized/truncated/zero-length/extra frames, byte/count mismatch, missing/wrong marker and overflow produce an explicit preflight refusal; no malformed block starts the guest. Apply this to standalone, automatic cluster and manual start/restart, including LF-bearing payloads and wrong/stale node/incarnation attribution.
- **R11:** The helper replay request carries a schema version. Errors: a version the helper does not implement → explicit refusal naming both versions, never a silent misread.

## Boundaries

- No change to the choice trace wire format, canonical replay-plan encoding or decision semantics. Keep the existing Go record schema during this bridge; fn-232 separately owns the new Rust lineage. Implementation identities track their actual changed inputs.
- No removal of the Go reference session or the split-owned mode.
- No change to inspection, publication or minimization codecs.
- Passing the helper a path into the artifact store instead of frames is out of scope; the helper stays sealed from the store.

## Decision Context

Conductor amendment (2026-10-20), applying the owner's Rust-host/new-lineage direction: the original unchanged-all-identities and historical cross-implementation replay premise was false. Preserve fixed trace/tape semantics, record source-driven helper/model rotations and fail closed on mismatches. Preserve the Go baseline for fresh equivalence, and transfer the final changed-candidate qualification obligation explicitly to fn-232 R12/task .13. Implement all four fn-228 tasks as one coherent worker batch before the Rust host verb work.


The per-decision comparison already lives in the helper on the default path; this spec removes the surrounding duplication rather than the comparison. Frames were chosen over a store path because the choice limit already bounds the copy and the helper never touches the artifact store today. Rejected deleting the Go reference session as overkill: it is the differential oracle for the transcript corpus, and removing it would leave the helper checking itself.
