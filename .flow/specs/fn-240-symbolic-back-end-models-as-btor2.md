## Goal & Context

The 2026-10-23 spike (`model/design/native-symbolic-backend.md`, probe kept at `model/design/native-symbolic/`) emitted Kettle from the embedded admitted tree (`umpire_ir::Lifted`, what the shared front end of fn-238 produces) as a BTOR2 word-level transition system, checked it with rIC3, and replayed every witness through `checked_step`. All five Kettle properties agreed with the native checker in 0.10 s each: unbounded IC3 proofs for the three safe claims and the arithmetic monitor, and a 62-step `never_beeps` counterexample replayed and natively confirmed. Two controls that mutate only the admitted tree were flagged. On a scaled Kettle (boiling at 1 000 000, two million states) the native checker took 19 s and IC3 0.10 s per proof, so proof time did not move with the state space. The owner's standing concern is scaling (the Model expands dramatically soon) and eventual Quint parity.

This spec turns the probe into a real back end beside `umpire/backends/tlc` and `umpire/backends/apalache`: same shared front end, same fixture runner, same rule that native agreement is claimed only when the native checker confirms the answer; symbolic-only answers remain explicitly unconfirmed. It gives what fn-211 was filed for (bounded and unbounded symbolic verdicts over large state spaces, symbolic Worlds) without TLA+ emission, Snowcat annotations, ITF decoding or a JVM. fn-211 stays deferred until set-valued state (symbolic sets, functions, unbounded sequences) is admitted; this spec does not close it.

## Architecture & Data Models

- **Crate** `umpire-symbolic` at `model/umpire/backends/symbolic/`, member of the independent `model/umpire` workspace, same manifest conventions as `umpire-tlc`. It depends on `umpire-ir` (and `umpire-dsl` for `Lifts`/`Machine`), never on the lifter: the emitter reads the embedded admitted tree of the compiled World, not source.
- **Emitter** (ported from the probe's `btor2.rs`): one BTOR2 file per Model and property. State fields become states with widths from the field's Rust type; enums are small unsigned words with a domain constraint; World fields are free states with `next = self` (symbolic constants) or `init` to the selected World's values (concrete mode). Branches keep first-match semantics; an action is enabled when its taken branch changes state or preserves a self-loop; a free `act` input with an extra "no step" value stutters. Postconditions use one-step history (`prev_*`, `prev_act`, `has_step`) and their `after =` filters. Checked arithmetic (fn-210 R11: overflow, division and remainder by zero, signed MIN/-1) latches a `fault` state, with overflow detected by widening because rIC3's logic library has no `saddo`-family ops; the fault is its own property, distinct from any authored claim. Exactly one `bad` per property; property metadata distinguishes invariant, postcondition, arithmetic and negative control. The emitter hash-conses every node, operators as well as sorts and constants (an `IndexSet` or `FxHashMap` keyed by the node, insertion order giving the BTOR2 id), so a repeated subexpression is emitted once. No BTOR2 crate is used: flussab-btor2, btor2rs and btor2tools fail fn-210 R18.
- **Engines**: rIC3 pinned as a built binary (it is a Rust crate with C++ SAT solvers; the build needs cmake and a clang or a shim), admitted into `<framework-root>/build/ric3` (`model/umpire/build/ric3` in this checkout) by a Rust command in fn-247's `xtask` (pinned version and source checksum, private staging, atomic publish under a lock, symlink refusal), not a Python script. rIC3, and any other solver this back end runs, executes through `umpire_backend_process::run_process` with its `Limits`, never GNU `timeout`. IC3 (`ric3 check <file> --cex --ui=false ic3`) for proofs; BMC to the native BFS depth plus one for violations when IC3 times out or is asked to; `kind` optional. Verdicts: `Safe` (unbounded proof), `Unsafe { witness }`, `Bounded { depth }` (no violation to the bound, never a proof), `Timeout`, `NotRun { reason }`.
- **Witness decoding and replay**: BTOR2 witnesses key assignments by state and input declaration index, so the emitter records a layout (field name, index, width, signedness, `Type`). Frames decode into typed `Value`s through the existing `Values`/`Value` contract; the start is found in `world.starts()`, each step through `checked_step`, the successor matched by typed values, and the violated claim re-judged natively (invariant predicate, `StepClaim::holds`, arithmetic refusal). Adapt completed typed BTOR2 edges to fn-250.3's existing `umpire_tla::replay::step` core (`EdgeValues`, `ReplayedEdge`, `ReplayError`), which selects exact concrete actions and compares native successor, outcome and ordered facts. Keep BTOR2 framing, completion, stutter/history and selected-property confirmation in this adapter. Extend the existing core only where necessary; do not create a second replay implementation or make a backend depend on `umpire-testing`. Share neutral result types in existing backend support only if both adapters need them. A non-replayable witness is witness-rejected and fails the fixture.
- **Fixture consumer**: `expected/symbolic.txt` per fixture (property, kind, engine, verdict, bound where bounded, `Agreement::{Agrees, Disagrees { reason }, Unconfirmed { reason }}`); violations also write `expected/symbolic/paths/<property>.txt`. Selected by the presence of the golden, run only under `UMPIRE_BACKENDS=require`, same ownership registration as the TLC consumer. Timings never appear in goldens.
- **Symbolic Worlds** (fn-211 R6, moved here): a fixture opting in leaves World fields free within their declared finite domains, so one run per property covers every World; a violation decodes the World values, constructs the World through a checked native adapter and replays under it. `Values` is export-only; task .5 must provide an internal generated codec or fixture callback taking typed fields to `Result<W, Refusal>`, validate exact field/type/domain membership and require export-after-construction to equal the decoded assignment, including private fields. The same adapter constructs Worlds for native domain enumeration under a preflight product limit. Computed starts (`#[starts]` bodies) need either the front end to admit the start bodies or a native start table over the World domain; the task plan chooses and records why.
- **Optional SMT-LIB path**: the same node graph unrolled as QF_BV SMT-LIB piped to a solver (the probe's `smt.rs`) stays a development tool for timing comparisons and is not a consumer.

## API Contracts

- `Symbolic::emit(world: &W, property, mode) -> Result<System, Refusal>` where `System` carries the BTOR2 text and the `Layout`; native adapters require `W: Machine + Lifts + Values`, typed state exports, concrete action identity and typed outcome/fact exports as the shared replay core requires. Symbolic mode additionally requires a checked native World-construction adapter described below.
- `Ric3::check(system, engine, bound, timeout) -> Result<Verdict, Refusal>` with the verdict enum above; `Refusal` is a tool admission, execution or decoding failure, never a property verdict, as in `umpire-tlc`.
- `replay(world, layout, frames, property, limits) -> Result<Replayed, Refusal>` with a `Confirmation::Violation` or `Confirmation::Arithmetic` for the selected violation. Partial-trace completion is bounded and refuses on exhaustion.
- Engine verdict and native agreement are separate. `Agreement` is `Agrees`, `Disagrees { reason }` or `Unconfirmed { reason }`. `Safe` requires exhaustive native checking over the full selected World domain to receive `Agrees`; `Bounded { depth }` can agree only with native checking covering that depth or a complete native graph, and stays bounded. An Unsafe result receives Agrees only through a confirming native replay under its decoded World. Cut exploration and an over-limit World product cannot establish agreement for absence; timeout, tool refusal and completion-budget exhaustion cannot establish agreement; required fixtures fail without the required confirmation.
- `symbolic.txt` lists properties in declaration order; framework `cargo xtask update` owns rewrites and root `make model-update` delegates; the default `make model-check` neither downloads nor builds rIC3.

## Edge Cases & Constraints

- Unbounded `Safe` is a proof of the encoding, not of the Model: agreement with the native checker on every selected fixture is what makes it evidence. `Bounded` says nothing beyond the bound and the golden states the bound.
- Integer widths and signedness come from explicit Rust backing metadata carried on `Type::Int`; task .1 adds this prerequisite before emission or tool checks. Nominal `Bounded` backing metadata remains separate from its declared finite-domain constraint; narrowing never shrinks the arithmetic width.
- Unsupported admitted forms (sequences beyond a bounded length, text, non-unit outcomes before R7) refuse emission naming the construct; a refusal is `NotRun`, never a pass.
- Determinism: the same fixture produces the same `symbolic.txt`; engine timeouts are not blessed by golden update under required mode.
- rIC3 witnesses may omit assignments in later frames; frame 0 must be complete. Deterministic completion searches whole native paths consistent with every assigned state, input, history, outcome and fact value, backtracking across matching choices and checking the selected terminal violation. Choose the first complete confirming path in native order, never the first local match. If exhaustive completion finds complete native paths but none confirms the selected violation, report Disagrees; if no complete native path exists, witness-reject. Enforce explicit search/time limits; exhaustion is a located witness-rejected refusal, never disagreement, agreement or a successful replay. Tests cover a locally matching first successor that dead-ends, a later confirming successor and budget exhaustion.
- No Temporal detail in `model/umpire` (owner rule); the back end is system-agnostic.

## Acceptance Criteria

- **R1:** `umpire-symbolic` emits every Kettle-shaped fixture (bools, ranged ints, fieldless enums, unit outcomes, no action inputs, concrete starts) as BTOR2 from the embedded admitted tree with one `bad` per property, first-match branches, enabledness and stutter, one-step history for postconditions with `after =` filters, and checked arithmetic latched as its own property, using explicit Rust width/signedness metadata introduced in task .1 and updated across current readers. Errors: an unsupported admitted form refuses emission naming the construct and the Model.
- **R2:** A pinned rIC3 is built and admitted into `<framework-root>/build/ric3` with checksum, lock and symlink refusal; the admission is an `xtask` command (Rust, fn-247), not a script; the runner runs IC3 for proofs and BMC to the native depth plus one for violations through `umpire_backend_process::run_process` with `Limits` (bounded time, output drained, children reaped; never GNU `timeout`), and no files outside the build root. Errors: a missing or mis-versioned tool fails before any fixture; a tool failure is `NotRun` with its message.
- **R3:** Witnesses are decoded through typed `Value`s by declaration index and replayed through `checked_step`; the violated claim is re-judged natively, and an arithmetic witness is validated by the native arithmetic refusal. Exact-edge execution uses fn-250.3's existing shared replay core, with whole-trace completion under explicit limits for partial witnesses; result types are shared only where needed. Errors: no complete native path is witness-rejected; exhaustive completion with native paths but no confirming violation is Disagrees; search exhaustion refuses without either conclusion. All fail the required fixture.
- **R4:** Kettle has `expected/symbolic.txt` showing agreement on every invariant, postcondition and the arithmetic monitor (unbounded `Safe`) and a replayed, natively confirmed `never_beeps` violation; two mutation controls (a changed postcondition literal, an overflow mutant) are tests that must disagree or witness-reject. Errors: a disagreement is listed in the golden and fails.
- **R5:** The consumer runs only for fixtures with `expected/symbolic.txt` and only under `UMPIRE_BACKENDS=require`; ownership of `symbolic.txt` and `symbolic/paths/*.txt` is registered even when skipped; framework xtask gate/update/validate own standalone provisioning and output updates, while root Make delegates; the default skipped-tool behavior is unchanged. No error surface.
- **R6:** Symbolic Worlds: a fixture opting in checks each property once across every World in its declared finite domain; a violation decodes the World, constructs it through a checked typed native adapter and replays under it; the golden records the domain, native agreement status and, for violations, the decoded World. Safe or bounded absence agrees only after complete native checking of every World at that scope; a cut or over-limit check is Unconfirmed. Unsafe agrees through a confirming replay under its decoded World. `parameterized_world` is the first such fixture. Errors: a World field without a finite domain refuses symbolic mode naming the field; a decoded World the Model cannot construct is witness-rejected.
- **R7:** The rest of the admitted finite subset: action inputs, non-unit outcomes, bounded sequences and fn-245's finite sets/maps and collection method table, preserving ordered short-circuit arithmetic semantics. `action_inputs`, `shared_returns`, `finite_sets`, `finite_maps` and `bounded_queue` gain symbolic goldens; task .1 supplies Rust width/signedness metadata before emission. Errors: constructs still outside the subset refuse as in R1.
- **R8:** DESIGN.md and MILESTONES describe the back end, its verdict kinds and the rule that proofs are evidence only with native agreement; `model/design/native-symbolic-backend.md` gains a status line pointing at the crate; fn-211 is recorded as deferred until set-valued state. No error surface.
