# Gomad: promote the model projections and cut the WASM dependency on native sources

## Conversation Evidence

> user: "we want to retire the native backend (not delete yet); so we'll want to relocate the overlay model so that wasm has no more dependencies on native."
> user: "our goal is definitely to run arbitrary functional tests with gomad (wasm)."
> user: "yes file flow spec for promotion."

## Goal & Context

The native backend is retiring. WASM is the product, and its goal is deterministic execution of arbitrary Temporal functional tests. Today the shared model and the WASM backend still depend on the native tree in four ways that are not Go imports and therefore survived the fn-184 module isolation:

1. The volume model (`internal/model/volume/{fs,handles,local_handles,volume}_generated.go`, `internal/hashwire/{hash,wire}_generated.go`, `types_generated.go`, `provenance_generated.go`) and the network model (output of `internal/model/network/generate`) are AST projections of the native overlay packages `gomadfs`, `gomadio` and `gomadchoicewire` under `internal/backends/native/toolchain/runtime/overlay/src/internal/`. Drift guards (`TestGeneratedProjectionMatchesNativeSources`, `TestGeneratedNetworkIsCurrent`, `TestProjectionPreservesNativeOwnerBodies`) fail when the overlay and the projection diverge.
2. The protocol generator (`internal/backends/native/generation/protocol`, invoked as `gomadtool protocol-generate` under `gomad_native`) reads the I/O wire schema and templates from `internal/backends/native/transcript/schema/` and writes codecs into the shared model (`internal/model/iowire`, `internal/model/choice/internal/wire`, `internal/model/network/stream_status_generated.go`, `internal/model/world/compressed_wire_generated.go`, `internal/model/runtimesource/gomad_choicewire_generated.go.txt`), into the WASM toolchain (`internal/backends/wasm/toolchain/net_stream_status_generated.go.txt`) and into the Rust helper (`internal/backends/wasm/wasmhost/src/world/wire_generated.rs`). Every one of those outputs carries a header naming the native generator.
3. `make generate` and `make validate` run the native `gomadtool` with `-tags gomad_native` for protocol generation, so the default WASM gate still compiles the native module.
4. `internal/archcheck` and `.github/workflows/gomad.yml` encode the coupling: the CI path filter maps edits of the overlay, the schema directory and the generator package to `wasm=true`.

The projected model code is gomad's own filesystem and network simulation, not Go standard library code. The projection exists only because the native design linked that code into a patched Go runtime; the generator strips the runtime-specific parts (`go:linkname` hooks, `internal/poll`, direct OS calls), and the result compiles with stock Go and no tags (verified 2026-10-19). Once native stops being executed, the overlay is a reference implementation nobody runs. The Rust helper is already held equal to the Go model, not to the overlay, by the differential conformance corpora. Promoting the projection to ordinary source therefore loses nothing WASM relies on, and it removes the last reason a Go release bump touches the model.

After this spec, nothing in the parent module outside `internal/backends/native` and outside `gomad_native`-tagged files references the native tree by path, import, generator, Makefile target or CI filter. The native module stays in the tree, buildable and validating under its selection, and its own generated outputs keep being produced.

## Architecture & Data Models

**Projection promotion.** The volume and network projection outputs become ordinary source files: rename away the `_generated` suffix, drop the `Code generated`, `Source:` and `Source SHA256:` headers, delete `provenance_generated.go` and its `ProjectionSourcesSHA256`/`ProjectionSourceInventory` constants (no consumer outside the generator), delete `internal/model/volume/internal/projection` and `internal/model/network/generate` with their drift tests, and remove the deleted test names from the `test-wasm` `-run` selector in `tools/gomad/Makefile`. `types_generated.go` mirrors `internal/model/iowire/wire_generated.go` types; it stays generated by the relocated protocol generator (see below) or becomes a plain file if the mirror is a one-to-one copy. Task .1 decides and records which. The volume model's implementation identity (`identity.go`, `TestImplementationInventoryNamesEveryEmbeddedSource`) is computed from the package's own embedded sources and keeps working; whether its value rotates because file names change is recorded in the ledger (R5).

**Protocol generator relocation.** Move `internal/backends/native/transcript/schema/{iowire.json,iowire.go.tmpl,iowire_test.go.tmpl}` to `internal/model/schema/` next to `modelwire.json` and `timewire.json`. Move `internal/backends/native/generation/protocol` to `internal/model/generation/protocol` in the parent module with a thin `internal/model/cmd/protocolgen` main (`generate` and `-check`), no build tag. The generator's output table splits into two sets:

- Shared set, written by `protocolgen`: `internal/model/iowire/wire_generated.go` and its test, `internal/model/choice/internal/wire/wire_generated.go` and its test, `internal/model/network/stream_status_generated.go`, `internal/backends/wasm/toolchain/net_stream_status_generated.go.txt`, `internal/model/runtimesource/gomad_choicewire_generated.go.txt`, `internal/model/world/compressed_wire_generated.go`, `internal/backends/wasm/wasmhost/src/world/wire_generated.rs`, `internal/model/cluster/internal/wire/*` and the volume `types_generated.go` mirror if it stays generated.
- Native set, written by native `gomadtool protocol-generate` under `gomad_native`, which imports the shared generator package and passes its own targets: `overlay/src/internal/{gomadwire,gomadchoicewire,gomadmodelwire,gomadsim}` outputs, `overlay/src/runtime/gomad_{iowire,timewire}_generated*.go`, `internal/backends/native/execution/simulation_{model,time}_wire_generated*.go`, `build/internal/livecap/protocol_generated.go` and `overlay/src/cmd/internal/gomadcap/protocol_generated.go`. The native-only templates `iowire_runtime.go.tmpl`, `timewire_*.tmpl`, `modeltransport.go.tmpl`, `livecap.go.tmpl` and the `livecap.json` schema stay in the native tree; the native set reads the shared schemas by path from the parent module root, which the nested module already resolves through its `replace`.

Generated headers change from `internal/backends/native/cmd/gomadtool` to `internal/model/cmd/protocolgen`. Relocation preserves output bodies byte-for-byte. The subsequent choice identity inventory excludes the retired nested module, rotating only the `ImplementationSourceSHA256` literals in the shared choice and hashwire codecs. Retain separate relocation-only and final diffs; all other body bytes must remain identical. These identity changes and the Rust generated-header change require the R5 ledger and current-candidate qualification.

**Gates.** `tools/gomad/Makefile`: `generate` and `validate-toolchain` run `go run ./internal/model/cmd/protocolgen` (and `-check`) without tags; the remaining native generators and validators (`version-generate`, `boundary-generate`, `compatibility-pack`, `patch-validate`, `script-validate`, `qualification-manifest-generate`, `TestHostPacksBindCurrentProfile`) move to `generate-native` and `validate-native`, which set `-tags gomad_native` themselves. `validate` depends only on default-set targets; `validate-native` is listed separately and the native Make targets that already select the tag depend on it where they depended on `validate`. `OVERLAY_FILES`, `VERSION_INPUTS`, `BOUNDARY_INPUTS` and `COMPATIBILITY_INPUTS` move with the native targets.

**archcheck.** Ownership tables and inventories keep their native entries, but only under `NativeSelected`; the default run reads no native path and must not need the native module present. Remove the `internal/model/volume/internal/projection` and `internal/model/network/generate` entries. Add a default-set check that no production or test file outside `internal/backends/native` and outside `gomad_native`-tagged files contains the string `internal/backends/native` (comments included; the fixtures `internal/backends/testfixture/native.go` and `internal/evidence/record/testfixture/native.go` are tagged and allowed).

**CI.** In `.github/workflows/gomad.yml`, the path filter stops mapping overlay, schema and generator paths under native to `wasm=true`; `internal/model/schema/*` and `internal/model/generation/*` are already covered by the `tools/gomad/*` branch that sets both. The `host-tools-linux` job runs `make validate` without `GOFLAGS=-tags=gomad_native` and runs `make validate-native` only when `native == 'true'`. `gomad-smoke.yml` is unaffected unless it calls `validate`.

**Unchanged.** `internal/model/cluster/runtime_{network,process,volume}.go` keep their `go:linkname` declarations against `internal/gomadio` and `internal/gomadsim` symbol names; they are text, compile under stock Go with the `ErrRuntimeUnavailable` fallbacks, and are not a dependency on the native tree. Their removal belongs to a later native deletion spec.

## API Contracts

- `go run ./internal/model/cmd/protocolgen [-check] [-root DIR]` from `tools/gomad`: writes or checks the shared set; exit 0 on success, exit 1 with one `stale: <path>` line per stale file under `-check`, exit 2 on schema or template errors. No other flags.
- Native `gomadtool protocol-generate [-check]` keeps its name and exit semantics and writes or checks the native set only.
- `make -C tools/gomad generate`, `validate` and `test-wasm` run no command with `-tags gomad_native` and succeed on a checkout where `internal/backends/native` is absent except for the shared schema files that moved out of it.
- `make -C tools/gomad generate-native` and `validate-native` run the native generators and validators under the selection with the same commands and exit statuses as before.
- Generated file headers in the shared set read `// Code generated by internal/model/cmd/protocolgen. DO NOT EDIT.` (Go) and `// Code generated by internal/model/cmd/protocolgen. DO NOT EDIT.` (Rust). Native-set headers name `gomadtool` as today.
- Promoted model files carry no generated header and are formatted with `gofmt`.

## Edge Cases & Constraints

- Identity rotation is expected and must be recorded, never silent: the helper source digest (Rust header), the volume implementation identity if file names enter it, and any choice or model identity that hashes `runtimesource` or the generated Go files. Retained historical results keep their identities; the current candidate is requalified on the WASM gates named in `internal/backends/wasm/QUALIFICATION.md` after the change.
- Byte-identity of generated bodies is the proof that promotion changed nothing semantically: task .2 records a zero-length header-filtered relocation diff, then checks the final diff permits only the two declared `ImplementationSourceSHA256` literals. Their old and new values and inventory change must appear in the R5 ledger.
- The projection generator rewrote owner bodies (`TestProjectionPreservesNativeOwnerBodies` and the `processReturns` table). The promoted files are the already-rewritten outputs, so no rewrite is lost; the overlay keeps its original bodies for the native build.
- Native must keep validating: `make validate-native` and the native Make targets run under the selection after the move with their previous exit statuses. Baseline failures and current native-source comparison are recorded in `.flow/artifacts/fn219-acceptance-audit-2026-10-20.md`; the historical fn-184 closure remains in Flow and Git history. The accepted baseline is unchanged.
- No Go release change, no WASM semantics change, no evidence format change, no change to the Rust helper beyond the header comment of one generated file.
- The nested native module reads shared schema files by filesystem path relative to the parent root; that path must be derived from the module's `replace` target, not hard-coded to a working directory.
- No CI run, PR or push is authorized by this spec; workflow files are edited as source only.

## Acceptance Criteria

- **R1:** No file in the parent module outside `internal/backends/native` and outside `gomad_native`-tagged files references the native tree: no Go import, no path string `internal/backends/native`, no Makefile default target, no archcheck default-run table entry. An archcheck test enforces the string rule on the default set and fails on any new occurrence. Errors: an occurrence found by the check is a test failure, never a warning.
- **R2:** The volume and network models are ordinary source: no `_generated` projection files, no generated headers, no provenance constants, no projection generators and no drift tests. `go test -tags test_dep ./internal/model/volume/... ./internal/model/network/...` and the Rust volume, namespace and network differential conformance corpora pass with unchanged expectations. Errors: any changed model behavior or conformance expectation is a finding.
- **R3:** The protocol generator lives in the parent module, builds with stock Go and no tag, reads schemas from `internal/model/schema`, and regenerates the shared set with bodies byte-identical to the previous outputs except header lines and the two declared choice-identity literals. Retain a zero-length relocation-only body diff and a final diff containing only those identity literals, with R5 accounting and requalification. `make generate` and `make validate` run it without the native selection; `-check` fails with a named stale file when any shared output is edited. Errors: any other non-header body diff is a finding.
- **R4:** The native module builds and validates under its selection after the move: `make generate-native` and `make validate-native` exit 0, native `gomadtool protocol-generate -check` reports the native set current, and every native Make target that previously depended on `validate` still runs. No native source, fixture or ledger is deleted beyond the three schema files and the generator package that moved. Errors: a native generator or validator that no longer runs under the selection blocks completion.
- **R5:** An identity ledger in `.flow/artifacts/` lists every retained identity (helper source digest, volume implementation identity, choice identity, model identities, WASM overlay identity) as unchanged or rotated with the cause, and the rotated ones are requalified by re-running the current-candidate WASM gates named in `internal/backends/wasm/QUALIFICATION.md` with their numeric exits recorded. Errors: an unexplained rotation or a missing requalification exit is a finding.
- **R6:** `.github/workflows/gomad.yml` no longer maps native paths to the WASM job, `host-tools-linux` runs `make validate` without the selection and `validate-native` only on native changes; `tools/gomad/README.md`, `ARCHITECTURE.md` and `internal/backends/wasm/README.md` describe the models as owned source, the generator's new home, and the native tree as a frozen consumer. Errors: a documentation claim that native is deleted, qualified or still the model reference is a finding.

## Boundaries

- No deletion of native code, overlay, fixtures, ledgers or the nested module; no change to fn-128/fn-149 scope.
- No change to WASM semantics, evidence formats, the Rust helper logic, or the slim guest build.
- No removal of the `internal/model/cluster` linkname glue.
- No new WASM capability; closing the capability gap toward arbitrary functional tests is a separate spec.
- No CI run, PR or push.

## Decision Context

Conductor decision (2026-10-20), under the owner's instruction to follow recommendations autonomously: retain the parent-only choice-source inventory rather than preserve an identity that hashes retired native inputs. Permit only its two generated identity literals to rotate after the byte-identical generator relocation; require the exact diffs, identity ledger and full current-candidate WASM requalification. No codec behavior or wire-format change is authorized.

Owner decision (2026-10-19): the native backend is retiring but stays in the tree; WASM is the product and its goal is arbitrary Temporal functional tests. Promotion was chosen over relocating the overlay packages as non-compiled source text with copy-back into the native toolchain build. Relocation preserves a reference implementation that nobody will execute once native is retired, costs a materialization step in the toolchain build, and keeps the Go-release coupling alive. Promotion makes the Go model the single reference, which is already what the Rust helper is held equal to, and the Go-release coupling that remains for WASM lives entirely in `internal/backends/wasm/toolchain`. Rejected: keeping the generators reading native paths behind the selection (keeps the coupling and the native compile in `validate`).
