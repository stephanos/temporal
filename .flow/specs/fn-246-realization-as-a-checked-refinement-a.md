# Realization as a checked refinement: a shared Temporal layer, the action registry, Reach, and strategies enumerated from the Model (model, temporal)

## Conversation Evidence

> user (2026-10-24): "also consider abstractions and other patterns ; not just cuts"
> user (2026-10-24): "walk me through one at a time"
> Decisions, each chosen by the owner from a recommendation: (1) the activity protocol machine becomes a real Model checked by the native checker and TLC, with each feature Model declared as a refinement of it; (2) the path search (`Projection::Reach`) lives in `umpire-runtime`, system-agnostic; (3) worker strategies enumerated from the Model replace the hand-named scenarios after fn-243 lands, in this spec.

## Goal & Context

The activity Model is 156 lines. The code that binds it to Temporal is about 3,600 non-test lines: `feature/activity/{api,temporal,probe_gaps,phase,api_transport}.rs` (1,676) and the nominally shared `realization` crate whose `live.rs` and probe engine are written to the activity (about 2,000). The ratio is above 20. If the second feature costs the same, Umpire does not scale regardless of its checkers. The vision's acceptance test asks exactly this: the second feature "shows how much extra Model-writing and mapping work it needs."

The shape, not the line count, is the cause: one hand-written object mixes API knowledge (Temporal-wide), entity identity and admission (Temporal-wide), state projection (per feature), action evidence (per feature), worker policy (derivable), request filling (per action, written four times) and transaction mechanics (generic). This spec gives the Realization a shape with five abstractions, moves everything Temporal-wide into one shared layer, and makes the per-feature binding a checked refinement of a protocol Model rather than a live-tested object. The measured target is a per-feature mapping of at most twice the Model's lines, held first on the activity and re-measured on the workflow Model.

## Architecture & Data Models

- **Action registry.** The Model's `Action` enum carries one declaration per variant and everything else derives from it: `#[rpc(WorkflowService::RequestCancelActivityExecution, fill = cancel)]` on a client action, `#[rpc(WorkflowService::RespondActivityTaskCompleted, fill = completed, evidence = outcome.result)]` on a worker action, `#[environmental("abstract schedule-to-start deadline")]` on a deadline. RPC classification, action binding, program rows, probe baselines and the per-action evidence predicate read this table; `classify`, `bind`, `response` and the hand-written baselines go. The attribute is Temporal's (`umpire-temporal-annotate`); `umpire-dsl` sees only a generic per-variant metadata hook.
- **Fillers.** `Fill<A, Request>`: one function per action turning the action plus World, inputs and identity into a concrete request. Four consumers, one definition: Propose (client actions), program derivation (worker actions), probe baselines (valid examples to mutate), catalog probe cases. The trait is system-agnostic and lives in `umpire-runtime`.
- **Entity lens, shared.** A Temporal entity (activity execution now; workflow execution, Nexus operation, schedule later) is declared by its identity keys and its bootstrap RPC: `#[entity(bootstrap = StartActivityExecution, identity(namespace, activity_id, run_id))]`. Everything that drives a lens is written once in the shared layer: the admission transaction, receipt, freeze and Reset (today `live.rs`), proposal correlation (today `matches_proposal`), the read loop and its instruction (`#[read(DescribeActivityExecution, interval = 10ms, timeout = 30s)]`), the hold, and program envelope assembly. The feature supplies the snapshot-to-state projection (today `phase.rs`, becoming a table derive over `(status, run_state)`).
- **Reach.** `Projection::Reach(observed_state)` in `umpire-runtime`: given the projected Model state, the Runtime searches the Model's own transition graph from the current state, bounded by the admitted depth, through actions whose evidence predicates (from the registry) accept the observation; a unique path is the judgment, several are candidates in canonical order, none is Unexplained. `Current` and `Candidates` stay. Kettle adopts Reach as the system-agnostic control. `project_phase`, `consistent_evidence` and the attempt-skipping logic in `describe` are replaced by Reach plus the evidence predicates.
- **Protocol Model and checked refinement.** A shared Temporal Model of the standalone-activity API, `temporal/shared/protocol/activity`: its states are the classes of Describe snapshots the API can show (status, run state, attempt within the admitted maximum, outcome kind, last-failure kind, cancel requested), its actions are the WorkflowService RPCs with their gRPC outcomes, its World the same declared World as the feature's. It is a plain `#[machine]` Model, explored natively and admitted to TLC like any other. A feature Model declares `#[refines(protocol::activity, state = project, action = project_action)]`: the state projection is the lens's snapshot projection; the action projection maps each protocol action to a Model action or to a stutter. The framework checks the refinement offline in the sense of PROTOTYPE.md item 2: starts correspond, every protocol edge projects to an admitted Model edge with compatible outcome or to a stutter that leaves the projected state unchanged; filling a gap is reported separately from preserving a promise. This generalizes fn-227.3's checkpoint harness (`feature/activity/compatibility/checkpoint.rs`) into a `Refinement` fixture consumer in `umpire-testing` with goldens; the Runtime applies the same projection online, so a protocol change fails offline as a refinement rather than live as an Unexplained. TLC checks the protocol Model's own invariants; a TLC-side refinement mapping is recorded as a later checkpoint, not claimed here.
- **Capability traits.** `Realize` splits into `Identity`, `Snapshot`, `Evidence<K>`, `Fill<A>` and `ReplyPolicy`, each with defaults, assembled by the realization derive; `Realize` remains as the assembled whole for the Runtime. Kettle implements the same traits without Temporal. Composition later takes the product of parts' capabilities.
- **Evidence kinds.** `Observation` becomes a small algebra: `Rpc(request, response)`, `Snapshot(response)`, and the already existing compound acknowledgement generalized as `Reconciled(primary, acknowledged)`. `History(events since cursor)` is declared as a kind with no Temporal producer in this spec (the workflow Model's). Correlation per kind is shared.
- **One API catalog with claims.** The WorkflowService mirrors are generated from the descriptors into the shared layer, versioned with the API; Temporal-wide field kinds (`Namespace`, `Identity`, `ActivityId`, `RequestId`, `TaskQueueName`) carry their server limits and rejection patterns once. A feature claims what it reads (`reads(...)`) and what it fills; unclaimed fields are Ignored by default and exhaustiveness is checked only against claims. The kind-level rule that opaque (`Secret`, `Ignored`) fields have no inferred byte-length bound removes the mutation cases the 430-line gap list accepts, so the list empties rather than being trimmed.
- **Strategies enumerated from the Model.** A worker strategy is a deterministic choice of worker action at every state where one is enabled, within the admitted World; the set of strategies is enumerated by exploring the Model's worker choices to the admitted depth. Each strategy is a scenario (name derived from its choices, for example `RespondFailed{retryable}@1,RespondCompleted@2`), each (strategy, task key) a program row filled by the action's filler. The hand list `Complete, RetryThenComplete, Fail` and `response()` go; fn-243's coverage test becomes a construction; the `WorkerProgram` envelope and the `umpire-scenario` header are unchanged.
- **Layout.** `model/temporal/shared/{catalog,lens,protocol,probes,support}` for everything Temporal-wide; `model/temporal/feature/<name>/{model.rs,tests.rs,realization.rs,expected/**}` for a feature. The `realization` crate's generic remainder moves to `shared`; its activity-specific remainder moves to the feature or disappears.

## API Contracts

- `umpire-runtime`: `Projection::Reach(M::State)`; traits `Fill<A>`, `Identity`, `Snapshot`, `Evidence<K>`, `ReplyPolicy` with defaults; `Realize` assembled from them with its current methods preserved for the Runtime. `umpire.model.v1` is unchanged.
- `umpire-testing`: a `Refinement` fixture consumer selected by `expected/refinement.txt`, reporting starts, preserved edges, stutters and gaps; mutation controls shipped with it.
- `umpire-temporal-annotate`: `#[rpc(...)]`, `#[environmental(...)]`, `#[entity(...)]`, `#[read(...)]`, `#[refines(...)]`; descriptor-generated mirrors with claims; Temporal-wide field kinds.
- `umpire.temporal.v1`: unchanged. `umpire.run.v1`: unchanged beyond fn-243.
- Go: unchanged. No Temporal detail in `model/umpire` (owner rule): the registry attribute, the lens, the protocol Model and the catalog are Temporal's; Reach, fillers and the capability traits are system-agnostic.

## Edge Cases & Constraints

- Reach is bounded by the admitted depth and the registry's evidence predicates; several accepted paths are candidates in canonical order, as today; a path through an action with no evidence predicate is admitted only for stutters the refinement declares.
- The protocol Model is finite by construction: attempt is bounded by the declared World, snapshot classes are enums. Its World is the feature's World, so refinement is checked per selected World and by TLC on larger Worlds.
- The refinement check distinguishes a protocol edge with no Model counterpart (a gap, reported) from a Model edge the protocol never produces (allowed, the Model is more permissive) from a protocol edge that projects to a forbidden Model edge (a violation, fails).
- Strategy enumeration is bounded by the admitted World; a Model whose worker choices are unbounded refuses enumeration naming the state. Strategy names are canonical and stable across runs; fn-243's wire goldens for the program change once, listed.
- Every fixture and Model without a Temporal binding keeps byte-identical goldens; Kettle's goldens change only where it adopts Reach, listed.
- The live slice (complete, retry-then-complete, fail, cancel-before-start under a hold, cancel-after-completion, host refusal) passes through `umpire explore` with identical judgments before and after; the guest is rebuilt.
- Size: per-feature non-Model, non-test lines are reported for the activity before and after, with the shared layer reported separately so moving code cannot satisfy the target; the target is at most twice the Model's lines per feature. R30 budgets hold.

## Acceptance Criteria

- **R1:** `Projection::Reach` in `umpire-runtime` judges observations by bounded search through the Model's own graph with per-action evidence predicates; Kettle uses it as the system-agnostic control; unique, several and no path give judgment, canonical candidates and Unexplained respectively. Errors: an unbounded search is refused by depth, never looped.
- **R2:** `Fill<A>` and the capability traits exist with defaults; `Realize` is assembled from them with the Runtime's contract unchanged; Kettle and the activity implement them. Errors: a missing required capability is a compile error naming it.
- **R3:** `model/temporal/shared` holds the descriptor-generated WorkflowService catalog with Temporal-wide field kinds and claims, the entity lens machinery (admission, receipt, freeze, Reset, correlation, reads, hold, program envelope), the probe engine over fillers, and support; nothing in it names a feature. Errors: a feature-specific identifier in `shared` fails a scoped check.
- **R4:** The activity binding is the registry on its `Action` enum, the entity and read declarations, the snapshot projection table, field rules on claimed fields, fillers, and nothing else; `probe_gaps.rs` is empty or gone because the opaque-field rule removes the cases; the live slice passes with identical judgments and the probe inventory agrees with the previous one except for the removed cases, listed. Errors: a lost probe case not explained by the opaque rule fails the task.
- **R5:** The protocol Model `temporal/shared/protocol/activity` is a `#[machine]` Model with native goldens and TLC agreement on its invariants; the activity Model declares `#[refines(...)]`; the `Refinement` consumer reports starts, preserved edges, stutters and gaps with goldens; mutation controls (a changed protocol edge, a removed Model edge, a wrong projection) fail it; the Runtime applies the same projection online. fn-227.3's checkpoint stays as independent evidence. Errors: a gap is reported, not a pass; a violation fails.
- **R6:** Worker strategies are enumerated from the Model; program rows are derived from strategies and fillers; the hand-named scenarios and `response()` are gone; the coverage test is a construction; fn-243's live slice and controls pass with derived scenario names; wire goldens updated once, listed. Errors: unbounded worker choices refuse enumeration naming the state.
- **R7:** Per-feature mapping lines for the activity are at most twice its Model lines, reported before and after with the shared layer separate; DESIGN.md gains "Realization as a checked refinement" (abstractions, protocol Model, refinement semantics, strategy derivation, layout, counts, `make model-time`) and `model/README.md` the authoring paragraph; the workflow Model is named as the re-measurement. Errors: a count over target fails the task unless the owner grants an exception in writing.

## Boundaries

- No Model semantics change in the activity Model; no new Temporal feature; `History` evidence has no producer here.
- No TLC-side refinement mapping; TLC checks the protocol Model's own invariants and the refinement check is native with TLC agreement recorded as a later checkpoint.
- No change to `umpire.model.v1`, `umpire.temporal.v1`, the Go Runner or the executors beyond consuming the derived program.
- No DSL vocabulary for authors beyond the Temporal attributes; Models stay plain Rust.
- No Temporal detail in `model/umpire`.

## Decision Context

2026-10-24, owner, three decisions taken one at a time after the Realization inventory (Model 156 lines; binding about 3,600):

1. **Protocol Model, checked refinement** over a shared Rust binding or a binding now with the protocol Model later. The Realization gains a correctness check before it runs live; ZOOM gets its first real pair of levels; a protocol change fails offline. Cost accepted: a second Model to maintain and refinement checking as framework work (fn-227.3's harness generalized).
2. **Reach in `umpire-runtime`** over `temporal/shared` or a checker exploration query. System-agnostic, so the no-Temporal-in-umpire rule holds, Kettle uses it, and the offline refinement and the online projection share one search.
3. **Strategies after fn-243**, in this spec, over rewriting fn-243.1 or keeping hand-named scenarios. fn-243 ships as filed; the program format is unchanged; only how rows are produced changes.

Abstractions proposed the same day and folded in: the action registry, fillers, the entity lens, capability traits, evidence kinds, one API catalog with claims, the opaque-field rule.
