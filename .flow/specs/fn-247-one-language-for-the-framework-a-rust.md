## Goal & Context

Remove Python from the active Model/framework development toolchain while preserving Model semantics and operational safety under native Rust tool contracts. Shared process ownership belongs in `umpire-backend-process`, separate from TLA+ emission. A host-only `xtask` replaces build helpers, their embedded Python glue and controls. The retained-original Python hash verifier is retired, not ported; the Rust lifecycle comparison stays and no retained artifact changes. Go stays where the host requires it; Bash remains orchestration.

Developers use documented native Rust driver contracts, with callers updated together. Keep cheap useful happy-path invocations; no aliases, diagnostic spellings or old encodings are required solely for backward compatibility. The post-fn-237.3 integrated guest is semantic reference evidence, not a byte oracle. This work changes no Model, checker meaning, protocol, IR or Temporal feature behavior.

## Architecture & Data Models

`umpire-backend-process` owns the existing `Limits`, `Refusal`, `Scratch`, `ProcessFailure`, Java admission, process execution and bounded-text contracts. TLA+, TLC and Apalache use it directly where they need those contracts; Apalache acquires no TLC dependency. TLA+ retains binding, emission, Snowcat and typed-value admission. Update callers coherently where the native interface differs; preserve functional typed failure/status mapping and all process safety controls. Old signatures, compatibility reexports and diagnostic wording are not acceptance criteria solely for backward compatibility.

Use an allocation-free process supervisor inside the process crate. Prepare executable resolution, argument/environment bytes, descriptors and bounded buffers before forking. Every path in the forked supervisor and its pre-exec target child is restricted to audited libc calls and stack-only scalar/byte operations; it cannot allocate, format, lock, run Rust destructors, unwind or call general `std` process/filesystem helpers. All child exits use `_exit`. This is the production path for focused Cargo tests and library consumers; no sibling executable, runtime Cargo invocation or warm workspace build is required. A standalone Rust helper is an alternative only if a reviewed build/discovery contract first proves all those use cases.

Linux retains the private supervisor group, target session, subreaper and adopted-descendant cleanup, including escaped process groups. Darwin retains non-root admission and descendant prevention. Other platforms refuse at admission. Signals and owner-liveness EOF preserve the existing outcome mapping. Safe Rust retains capture handles, inode checks, output concatenation, dump admission and scratch cleanup. After the supervisor proof, scratch directories use `tempfile::Builder` and parent-side syscalls use `rustix` safe wrappers; the forked child's async-signal-safe path stays raw libc. Limits keep their existing units and enforcement: Java heap configuration is not an OS memory cap, and polling a regular output file is not a strict kernel output cap.

`xtask` is a native development-profile binary, excluded from guest/wasm dependency closures. Its commands use documented native Rust arguments, JSON schemas, status/error rendering and TOML behavior; retain useful ordinary invocations without emulating Python quirks. It hashes in-process with `sha2` (no `shasum` subprocess), encodes JSON with plain `serde_json` (default BTreeMap-backed `Map`; `preserve_order` off workspace-wide), and handles OS arguments with `std::env::args_os`/`OsString` (no clap), decoding command tokens only where needed. Internal commands replace cache-key calculation, launcher publication and Cargo-artifact selection formerly embedded in the guest shell. Compile xtask before setting guest wrapper/encoded flags; the compiler wrapper directly executes the built native tool, never recursively starts Cargo. Preserve raw compiler argv, previous-wrapper execution, jobserver descriptors and macOS loader environment.
