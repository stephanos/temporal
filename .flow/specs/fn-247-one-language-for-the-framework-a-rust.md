## Goal & Context

Remove Python from the active Model/framework development toolchain while preserving its existing behavior. Shared process ownership belongs in `umpire-backend-process`, separate from TLA+ emission. A host-only `xtask` replaces build helpers, their embedded Python glue and controls. The retained-original Python hash verifier is retired, not ported; the Rust lifecycle comparison stays and no retained artifact changes. Go stays where the host requires it; Bash remains orchestration.

Developers keep the existing backend APIs, guest command arguments, statuses, deterministic behavior and safety controls. The post-fn-237.3 integrated guest is the behavioral baseline; Python-produced bytes need not be reproduced. This work changes no Model, checker meaning, protocol, IR or Temporal feature behavior.

## Architecture & Data Models

`umpire-backend-process` owns the existing `Limits`, `Refusal`, `Scratch`, `ProcessFailure`, Java admission, process execution and bounded-text contracts. TLA+, TLC and Apalache use it directly where they need those contracts; Apalache acquires no TLC dependency. TLA+ retains binding, emission, Snowcat and typed-value admission. Preserve existing caller signatures and compatibility reexports used by consumers, including their diagnostic wording.

Use an allocation-free process supervisor inside the process crate. Prepare executable resolution, argument/environment bytes, descriptors and bounded buffers before forking. Every path in the forked supervisor and its pre-exec target child is restricted to audited libc calls and stack-only scalar/byte operations; it cannot allocate, format, lock, run Rust destructors, unwind or call general `std` process/filesystem helpers. All child exits use `_exit`. This is the production path for focused Cargo tests and library consumers; no sibling executable, runtime Cargo invocation or warm workspace build is required. A standalone Rust helper is an alternative only if a reviewed build/discovery contract first proves all those use cases.

Linux retains the private supervisor group, target session, subreaper and adopted-descendant cleanup, including escaped process groups. Darwin retains non-root admission and descendant prevention. Other platforms refuse at admission. Signals and owner-liveness EOF preserve the existing outcome mapping. Safe Rust retains capture handles, inode checks, output concatenation, dump admission and scratch cleanup. After the supervisor proof, scratch directories use `tempfile::Builder` and parent-side syscalls use `rustix` safe wrappers; the forked child's async-signal-safe path stays raw libc. Limits keep their existing units and enforcement: Java heap configuration is not an OS memory cap, and polling a regular output file is not a strict kernel output cap.

`xtask` is a native development-profile binary, excluded from guest/wasm dependency closures. Its existing named commands retain their positional arguments, stdout/status contracts and declared diagnostics. It hashes in-process with `sha2` (no `shasum` subprocess), encodes JSON with plain `serde_json` (key order from its default BTreeMap-backed `Map`; `preserve_order` stays off workspace-wide) and parses arguments with `std::env::args` (no clap). Internal commands also replace cache-key calculation, launcher publication and Cargo-artifact selection formerly embedded in the guest shell. The shell preserves its public interface and build/check behavior. Compile xtask before setting the guest wrapper and encoded guest flags; the compiler wrapper directly executes the built native tool, never recursively starts Cargo. Preserve the previous wrapper, jobserver descriptors and macOS loader environment.

## API Contracts

Preserve `run_process` and cancellable execution's distinction between refusal, child status and retained output. Preserve timeout/cancellation output, first-signal handling, owner EOF, target signal mapping, `125` owner-loss status and `128+signal` outcomes as applicable. Do not rename `TLC refusal` as incidental cleanup.

Guest identities, hash inputs and sidecar records are deterministic, portable across hosts and stable going forward; they need not match Python-produced bytes, escaping or spacing. Changing their encoding selects a new guest cache. Sidecars publish before compilation and disappear on failure. Closure identity retains checksums, non-dev edges across all platforms, build dependencies, edge structure, ambiguity and shared-feature unification behavior.

Guest check mode returns 0 for fresh, 2 for stale/missing and 1 for tool/build/discovery failure, reports sizes and the first differing offset, and never publishes the candidate. Freshness disables automatic installs; absent CI permits a missing-prerequisite warning/skip, while even empty CI requires failure. Probe/metadata/build/staleness errors always fail.

Freshness enters through a Bash admission launcher before any xtask cache lookup or build. It sets `MISE_AUTO_INSTALL=false` and `MISE_EXEC_AUTO_INSTALL=false` before the first probe. Missing mise or a positively established missing pinned prerequisite returns the existing local warning/0 only when CI is absent; empty or nonempty CI fails/1. Probe errors, malformed configuration/metadata, pin disagreement and bootstrap compilation failures always fail/1. The launcher uses mise's existing TOML/config and tool-query interfaces rather than adding a JSON/TOML parser or another prerequisite. Its bounded bootstrap checks cover all old missing cases before invoking Cargo: pinned Rust and Cargo, rustup-managed compiler availability, Go, protoc, rust-src and wasm target. Once admitted, build/execute xtask, which performs the full authoritative metadata/TOML validation and guest comparison again. An already cached binary never bypasses entry admission. Prove this ordering against the actual Make/shell entrypoint with an empty xtask cache and one absent prerequisite at a time; no Cargo, guest build or artifact publication may occur on a missing-prerequisite skip. Errors must never be classified as missing solely from a nonzero probe exit.

The retained-original hash integrity check is thrown away (owner, 2026-10-24): `verify.py` is removed, not ported, and `manifest.json` (paths and hashes) is deleted. The originals stay in Git as historical evidence; the completed fn-227 checksum artifact under `.flow/artifacts` is history and is not consulted. The compatibility checkpoint keeps its semantic lifecycle comparison against `original/rows.snap.txt` and its mutation control.
