## Recommendation and ownership

Task .2 supplies the authored range-newtype/Finite shape; task .7 supplies typed selected-World binding, complete starts, collision-safe identities and all CFG families. Task .4 must extend those existing mechanisms for bounded newtypes and `Option` of those newtypes, then prove the timeout Model through the ordinary source/backend route. Neither native `Finite` alone nor task .7's existing scalar binding discharges this work. No general ADT interpreter, arbitrary Rust evaluator, generic Option combinator language or native-graph-to-Next shortcut is needed.

Recommend configured `Ticks` with an admitted positive integer range `1..=3`, using an already admitted scalar backing type such as `u8`. A separate countdown value has range `0..=3`; call it `Remaining` here. Bounds and the range attribute's exact spelling must come from .2's one authored declaration, not a duplicate lifter table. Optional countdowns can distinguish an unarmed deadline from an exhausted zero budget. These are concrete proposed bounds, not an assertion that the spec already fixes them.

`Finite::domain()` enumerates admitted values; it does not prevent a Rust tuple constructor from producing an out-of-domain value. Require checked native World/start admission, plus source-binding validation, before checking. If construction can bypass the range, the activity's admission must catch it. Dynamic updates must preserve the declared countdown bound and avoid subtraction at zero; native/source failures must agree, never become silently disabled transitions. Do not add a generic runtime reflection mechanism to enforce this.

Zero semantics to write explicitly before implementing the Model: under this proposal, configured `Some(Ticks(0))` is invalid and refused with the field named. It is neither absent nor an immediately expiring timeout. `None` alone means an absent configured timeout. A valid one-tick live budget expires on the first Tick that decrements it to zero, without unsigned underflow. `Some(Remaining(0))` is representable as exhausted state and remains distinct from an unarmed `None`; the activity must state whether that zero exists in its terminal state or is cleared on closure. Zero must never remain an armed nonterminal countdown with no expiry transition. None of these representation choices settles cancellation or R4 compatibility. Task .5 may separately propose exact wire zero/absence-to-None quantization; that conversion requires an explicit request admission table and is not an Option coercion in the Model or lifter.

## Representation choices

| Representation | Merits | Cost or trap |
| --- | --- | --- |
| Scalar ordinal: None is 0; Some(n) is n+1 | Smallest CFG surface, one scalar per field, existing integer parsing; distinguishes None from Some(0) | Needs exact option-domain validation, including forbidden gaps, and authored wrapper rendering |
| Empty/singleton sequence: None is `<<>>`; Some(n) is `<<n>>` | Reuses sequence expression/value machinery; structural distinction | Plain Seq metadata accepts arbitrary lengths; direct tuple/sequence CFG literals are not supported by the inspected pinned config parser, requiring substitution or extra scalar constants |
| Tagged record/tuple with presence and payload | Explicit tag; supports later structured values | More emitter/type/decoder work, canonical absent payload rules, invalid tag/payload combinations and CFG binding indirection |

Choose the scalar ordinal encoding. For configured Ticks 1..=3, the exact allowed codes are `{0,2,3,4}`. Code 1 is the distinct encoding of invalid Some(0) and must refuse, not decode to None. For Remaining 0..=3, `{0,1,2,3,4}` is valid: code 0 is None and code 1 is Some(0). Bounds must leave room for the added 1 within TLC's signed integer range. The proposed tiny ranges trivially do, but declaration admission should check this rather than rely on arithmetic wrapping.

Mechanically, a presence test compares the encoded value with 0; a present payload is the encoded value minus 1; constructing Some adds 1 to the validated numeric payload. A defaulted read selects the present payload or authored fallback, retaining eager fallback checks. These translations carry the optional/newtype source type; an ordinary Int with the same machine value is not implicitly interchangeable. Decoding first validates the exact allowed set, then reconstructs None or Some with the authored newtype's standard Debug spelling.

Keep authored identity in type metadata: a bounded single-field integer-newtype descriptor, and an optional-bounded-newtype descriptor carrying that descriptor's name/backing type/range. Exact Rust enum variant names are implementation choices; do not erase these descriptors to ordinary Int, or admit Option of arbitrary Type. Reuse existing value/expression storage for literal payloads and encoded integers, adding only the narrow typed construction, presence and payload operations needed. No new public generic Value/ADT subsystem is justified.

The same typed binding route must validate native `None`/`Some` and payload bounds, encode them, and emit the selected World constant assignments in main, invariant, postcondition, negative and progress CFGs. A timeout absent in one selected World is assigned 0; one tick is assigned 2; three ticks is assigned 4. A direct TLA constant can carry this scalar encoding; native Debug/Display must still spell `None`, `Some(Ticks(1))`, etc. Raw encoded integers must not leak into authored reports or replay identity. A positive Ticks default must not be fabricated as zero; an optional field's default is None where an authored/default start is admitted.

Binding accepts the selected native World and authored complete starts, never constructor strings or manually maintained option tables. It validates malformed/missing/extra/duplicate fields and wrongly typed option payloads with source location. Metadata must retain exact selected bindings so configs and replay cannot silently use a different World. An edited CFG carrying code 1, a different selection, or an unknown field is not valid evidence for the selected World. Preserve .7's correlated starts and empty/deduplicated starts contract.

## Narrow source surface

Admit only source-local range newtypes in .2's canonical shape and `Option<that newtype>`. Parse full type paths/generic arguments, not a last-segment string match. Support the unshadowed prelude Option/Some/None spellings and explicit canonical `core::option::Option` / `std::option::Option` paths consistently; reject aliases, shadowed bindings, unknown constructors, wrong generic arity, unsupported backing widths, nested Option, Option of arbitrary records/collections and unbounded newtypes with located diagnostics. Enabling canonical imports must not weaken the existing alias/dependency refusal boundary.

The minimum activity expression surface is typed None/Some construction; copying an optional field; equality/inequality; `is_none`/`is_some`; `unwrap_or` with a correctly typed bounded-newtype fallback; and the admitted newtype's numeric payload projection. Native `unwrap_or` evaluates its fallback eagerly: preserve that behavior and its possible failure on the Some branch, as the vector control already does. Assignments and conditional effects reuse existing SSA lowering. Cross-newtype arithmetic/conversion is explicit through the numeric payload, not accidental nominal-type equality. Countdown decrement is guarded above zero and rewrapped into the countdown type.

Option `match`, `if let`, `let else`, binding `matches!` patterns, panicking `unwrap`/`expect`, `map`/`and_then`, mutation through references, arbitrary inherent methods, custom Deref and conversion trait impls stay refused. Existing action-handler match is unaffected. The activity must be authored with the admitted conditionals/presence/defaulted-read surface; if its final source actually needs a two-arm Option match, that is additional explicitly bounded admission work and tests, not permission to claim arbitrary pattern support. `Vector::get(...).is_some()` remains its existing special case and must not be conflated with stored Option values.

Apply option operations to state, before-state, selected World and source constants through their distinct typed identities. A World constant is never primed. Traversal/priming/check collection must visit any new expression children; a payload read from before-state must remain unprimed even when self is after-state. Do not manufacture option values from native reached states to simplify the source relation or claims.
