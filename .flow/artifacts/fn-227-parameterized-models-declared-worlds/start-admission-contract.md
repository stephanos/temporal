# fn-227.5 Start evidence and transactional admission

R6 has no faithful implementation through the unchanged three Temporal envelopes. Observation has no request slot, and the actual Start response does not carry the retry and timeout options. The smallest feasible proposal adds a request Any to Observation under explicit owner authority. The existing Dispatch transaction boundary can then install an entire prospective activity runtime, its evidence binding and admission freeze together. Neither proposal changes an independent Model transition.

## Capture the completed invocation, not intended options

The live SDK already crosses a useful boundary in `tests/testpilot_model_annotations_test.go:39`. Its interceptor fills and validates the request, invokes the RPC at line 43, and then validates the actual response. Extend that boundary for the specific Start method. Clone the fully filled typed request after request annotation and immediately before invoke; clone the raw response immediately after successful invoke, before response validation can produce a local error. Associate both captures within that invocation. Retain the raw RPC error separately from local annotation or model-admission errors. Never treat an allocated response object accompanying an RPC error as success.

Transport the captured request bytes in the proposed request Any and the captured raw response in the existing result oneof. This means the serialized filled protobuf actually handed to transport, rather than a message reconstructed from StartActivityOptions. Validate that later interceptors do not mutate the captured request before marshalling. A test should compare the capture with the exact message seen by the innermost invoker. The existing request-ID retry control at `tests/testpilot_model_annotations_test.go:220` supplies an anchor for retry stability and clone ownership.

The SDK constructs namespace, identity and request ID before the RPC, applies options, encodes arguments and propagates headers in the pinned SDK's `internal/internal_activity_client.go:583`, then invokes Start at line 629. Capture after those steps. The SDK's resulting handle supplies only ID/run ID, so the handle cannot replace the captured successful Start result.

The trusted transport owner proves same-invocation association. Protobuf bytes alone cannot prove it. The response echoes run ID and started, but not request ID. Its optional activity Link can additionally cross-check namespace, activity ID and run ID when present. Reject a contradictory Link. Never claim that matching request IDs independently authenticate a response that does not contain one. The server emits that Link at `chasm/lib/activity/handler.go:166`.

## Admission and evidence identity

The admission receipt retains the immutable actual Start request/result, method, namespace, activity ID, request ID and assigned run ID. Validate canonical message types, required identity, request-ID presence and result shape before parameter-domain checks. The request-ID fill occurs once at the transport boundary, never while observing captured evidence. Reuse fn-217's existing catalogs to validate, without repairing captured bytes.

Only an actual successful Start with started=true and a valid nonempty run ID creates a new live binding. RPC errors, absent results, wrong Any types and invalid identities leave every previous field unchanged. Return a typed state/unsupported/malformed refusal with the failed precondition; only out-of-domain World options receive the R6 admission-freeze treatment.

A successful started=false result cannot initialize a World from that request. It may name an existing run with different original options. With no retained original started=true receipt, refuse state-preservingly. With a retained original receipt, a retry of the same request ID, exact captured request and same run ID is a zero-step check. It never installs its options or resets progress. A different request using USE_EXISTING also cannot parameterize the existing run, even if its options happen to match. Actual idempotent Start retries return started=false in `tests/activity_standalone_test.go:505`; the server sets started from Created at `chasm/lib/activity/handler.go:169`.

Repeated original started=true evidence for the same receipt is also a zero-step check after progress. Same request ID with different request bytes, conflicting run IDs, a crossed namespace/activity, or another Start while a run is bound refuses without replacement. Pin one live execution per guest lifetime. This fits the current one-run ownership documented at `model/temporal/realization/README.md:5` and avoids inventing a generation protocol.

For subsequent RPC observations, carry the actual request in the same proposed slot and require its namespace/activity/run tuple to match the binding. Describe's response run_id and info.activity_id/info.run_id must agree with each other and with the receipt. Cancel request identity must agree before projecting its response/error. A request that omits run ID and implicitly selects a current run cannot establish this specific binding. A stale same-run Describe is still evaluated against current Model state and attempt; do not sort, buffer or rewrite it into a later observation.

Callbacks retain their existing partial upstream task shape. Populate namespace, activity_id, activity_run_id and attempt from SDK activity.Info, and check those against the receipt/current Model before Poll replay. These are real fields. Pinned SDK `internal/activity.go:44` exposes ActivityRunID and line 50 exposes Namespace. The live callback currently fills ActivityId and Attempt at `tests/testpilot_model_slice_test.go:175`, so it needs these additional real identity projections. The realization's ignore classifications at `model/temporal/feature/activity/temporal.rs:127` must be updated deliberately.

The receipt checks detect evidence crossing the bound run. They cannot detect a dishonest capture owner fabricating a same-invocation association before the first binding, or infer freshness from wall clocks. Keep that trust boundary explicit.

Keep full captured evidence private to the owning test/runtime. Diagnostics identify the method, failed identity component or offending option field without logging input payloads, headers, tokens, request bytes or raw failure contents. Reuse the existing catalog redaction on report copies; never redact or repair the evidence used for admission. Controls mutate captured payload/token bytes and verify neither successful nor refusal diagnostics expose them. Existing redaction ownership is pinned at `model/temporal/realization/tests/catalog.rs:330`.

## Keep admission inside the Temporal Dispatch facade

`Realize::observe` is pure and receives only an immutable state at `model/umpire/wasm/src/runtime.rs:73`. Runtime privately owns machine, state, freeze and exploration at line 89. Its prepare converts an Err refusal into an outcome with no transaction at line 381. Therefore ordinary realization error return cannot install a World or commit the R6 freeze.

Extend the existing `AnnotationRuntime` facade at `model/temporal/realization/src/annotations.rs:10` with a typed admission transaction. Its job remains Temporal-owned transport/admission around one generic Runtime. Keep generic Runtime and Realize free of Temporal request fields. Use an owned prospective replacement Runtime rather than exposing mutable World access.

Before live admission, the facade has no live run binding. Retain the explicitly declared default fixture World for Explore/Rows compatibility, as checker-only data. Judge and Answer require successful live admission and cannot infer a live World from that fixture. This concrete initialization rule preserves existing exploration consumers while exercising invalidation of a previous exploration. It supplies no missing parameter to a live execution.

Successful preparation validates the candidate World and its unique authored start, constructs a fresh Runtime with that World, and stages replacement plus its immutable Start receipt. The replacement owns the selected machine, its Scheduled/attempt-one start, empty exploration and no freeze. On commit, swap the entire owned candidate and receipt. Old Rows must then return NotExplored until a new Explore. Every later Model step, catalog and checker call uses that selected World. Keep construction and all fallible allocation before commit; commit performs owned moves with no decoding, validation, Model evaluation or encoding.

Out-of-domain option admission prepares a protocol Refusal with code Unsupported and an exact field path, together with a facade freeze transaction. Dispatch already permits a Refusal response plus Some(transaction), because its return contract is a pair rather than Result (`model/umpire/wasm/src/lib.rs:39`). The transaction records the candidate identity and first refusal, freezes this admission, and retains the previous machine/state/exploration unchanged. It does not construct an approximate World. Do not route this result through generic Runtime::prepare's Err path. A different bound execution fails identity admission before domain checking and cannot freeze the current run.

After publishing that freeze, well-formed Judge and Answer calls cannot advance until Reset. Repeated admission returns the retained first field-naming Unsupported; Answer returns State. An in-domain replacement Start cannot bypass the freeze. Ordinary malformed/unknown observations retain their normal refusal precedence and change no fields, including an existing first freeze. Stateless Annotate/Probe remains available and cannot clear it. Explore/Rows concern only a previously explicit checker World and must never claim to explain the rejected live candidate.

Preserve generic Reset's selected-World semantics. For a bound live run, Reset restores that World's unique start and clears runtime/facade freeze while retaining the immutable execution identity and original receipt. It is not authority to install another execution's World. A new execution gets a fresh guest, including each live-slice scenario. For an admission rejected before any live World exists, Reset clears the freeze but cannot turn the rejected options into an admitted World. Retain the attempted execution identity; changed options for that same request are contradictory evidence. A newly configured actual execution uses a new guest. These rules avoid an unbounded retired-run cache and make stale Start replay after Reset idempotent instead of reconfiguration.

## Publication and rollback

The facade's transaction is either delegated Model effects, an admission replacement, admission freeze, or Reset effects composed with facade freeze clearing. Reset must stage both parts, rather than clear facade metadata before delegating. Admission never changes the SDK/server run; model-publication failure cannot undo an already successful remote Start. Retain that actual capture for retry through the same guest.

`Guest::dispatch_to` encodes and accepts the entire native response before commit at `model/umpire/wasm/src/abi.rs:100`. A false publisher, panic, oversized response or response-buffer allocation failure discards the candidate and all receipt/freeze updates. The Wasm call allocates a separately owned response, encodes it and commits only at lines 74-91. Filling 16 MiB of live ABI storage makes it return zero before commit. No receipt, World, initial state, exploration invalidation, freeze or Reset effect may survive that failure. A later successful publication commits the same admission once.

The Wasm publication boundary is a live guest-owned response buffer, not the later host read. The Go host copies bytes at `model/umpire/hosts/go/host.go:330`, after guest commit. A host-side failure after that boundary cannot roll back guest state through the current ABI. Unexpected traps invalidate the host at line 273. Do not promise end-to-end acknowledgment rollback without a new protocol. Normal retries rely on receipt idempotency.
