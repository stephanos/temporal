## Supervisor architecture and lifecycle gaps

Preferred libc-only shape avoids distribution of a second executable: allocate and validate everything before `fork`; the supervisor child and its backend-launch child execute only a small audited allocation-free libc path until `execve` or `_exit`. The native library may be called from Rust's multithreaded test runner or a multithreaded consumer. Calling Rust `Command`, `Vec`, `String`, formatting, filesystem APIs, panic/error construction, logging or ordinary Rust destructors after that fork can deadlock on inherited locks. A fork followed by an ordinary Rust supervisor loop is not safe.

Pre-fork parent preparation must own stable NUL-terminated argv/env/program strings, resolved executable/search behavior, capture and owner-pipe descriptors, `/dev/null`, procfs pathname/buffers, cleanup bookkeeping and error-channel protocol. Preserve byte-valued Unix arguments and environment removals. Child-side failures report fixed errno/status bytes using `write`, then `_exit`; parent translates diagnostics. Define EINTR/EAGAIN/ESRCH handling, partial reads/writes, fixed-buffer overflow refusal and cleanup, signal mask/handler ordering, pending signal before target spawn, EOF versus target-exit ordering, inherited descriptor closure and failed exec. A supervisor must not retain unrelated parent descriptors or keep its own owner-pipe write end alive. Backend stdin remains `/dev/null`; the liveness pipe is solely supervisor input. Parent timeout starts at the same spawn boundary; this port must not accidentally add a compile step to that deadline.

Linux: establish subreaper before starting the backend; launch backend in its own session; on completion, owner EOF, cancellation/resource refusal or handled signal kill that group, then repeatedly reap adopted children and kill descendants that escaped into another session until none remain. Do not replace this with killpg alone. Assert owned PIDs are gone **before** test harness fallback cleanup; bounded waiting by a harness does not constitute successful production cleanup. Retain the acknowledged absence of a supervisor-SIGKILL recovery guarantee. Root/non-root and unsupported-platform behavior must be explicit.

Darwin: refuse real/effective root; set target RLIMIT_NPROC to zero before exec; report launch/setup failure rather than continue without prevention. Keep policy controls and non-root simulated Linux prevention controls, but do not call those native-macOS evidence. Native non-root macOS lifecycle evidence is a separate required platform receipt if available; absent evidence is reported. Keep direct supervisor TERM/INT/HUP/QUIT status behavior and target exit/signaled status/owner-EOF-before-status `125` behavior.

Standalone supervisor is a valid alternative only if it supplies an explicit build and discovery contract. A Cargo bin adjacent to an rlib is not automatically built or discoverable when another crate depends on the library. Cover direct TLC/Apalache builds/tests, workspace/all-target builds, docs, binaries outside repository cwd, debug/release/custom profile/custom CARGO_TARGET_DIR, Unicode/space paths, installed consumers, missing/wrong executable, executable integrity/version mismatch and concurrent launches. No implicit recursive Cargo invocation or unchecked PATH lookup inside `run_process`. If that packaging cannot be supplied in one task, use the audited libc-only child design or split packaging as its own prerequisite.

Compile policy: workspace `unsafe_code=forbid` cannot be lowered with a module allow. Mirror the existing `umpire-runtime` manifest's crate-specific `unsafe_code=deny` plus precise local exceptions, retaining every other workspace lint. Put unsafe code in the smallest private process module with documented safety invariants; do not weaken workspace/core/DSL lint policy. Promote exactly `libc = "=0.2.191"` if the plan promises the resolved pin; prevent guest dependency closure feature unification changes. Host-only code/dependencies must not enter wasm builds, facade/default generic capabilities, or Temporal-names source boundary controls.
