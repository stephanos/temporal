# Shared JVM admission and native process ownership

Static design only. No implementation or passing runtime proof is claimed. Inputs are hashed in lease-supervision-design-inputs.json. Read task17, source-preparation-inventory.json and actual mise-capability-probe.json. The latter establishes a concrete ownership gap: native supervision is justified beneath mise; mise remains the only scheduler.

## Existing interfaces and constraints

- Both toolchain pins are Rust1.99.1 (MSRV1.99). Installed pinned std fs.rs marks File::{lock,try_lock,unlock} stable since1.89. Unix implementation uses flock. Documentation explicitly releases the lock when the final duplicated/inherited descriptor closes and warns that reacquisition on cloned descriptors is platform dependent. Never reenter blocking lock().
- fetch_apalache.rs::lock already safely opens read/write/create/truncate(false), mode0600, O_NOFOLLOW|O_NONBLOCK, compares regular-file/dev/ino before and after File::lock. Reuse this admission pattern, including exact errors. Do not reuse its repository-local installation lock as host admission.
- Current backend-process public run_process_cancelled captures bounded output into files, owns a private syscall::Running via a liveness pipe, and applies checker policy. Running::Drop closes the pipe and waits; Linux child_main is a subreaper and kills/reaps adopted descendants including other groups. Current public API is not a streaming orchestration runner. Darwin forbids checker descendants; running Cargo/mise through that API would break gates.
- Retained support.rs adds OwnedProcess::{spawn,try_wait}, DescendantPolicy::{Checker,Orchestration}, run_owned. Its default Checker path preserves current behavior. Orchestration removes Darwin fork prevention but explicitly cannot reap escaped/adopted Darwin descendants. That is a material acceptance gap, not a portable all-descendant owner. Mixed support.rs also includes crate::work accounting; exclude it and all work_counts/provider edits.
- xtask currently has libc/tempfile, but no backend-process dependency. temporal-xtask has xtask only as a dev dependency, though its current lock already contains that edge. Adding backend-process to xtask necessarily adds its in-workspace dependency edge to both Cargo.lock files. No new registry versions/packages are needed in principle, but unchanged locks cannot be promised. Promote existing xtask edge to normal dependency for Temporal supervision reuse rather than also adding a redundant Temporal->process edge.

## Smallest admission mechanism

One exclusive kernel file lock, never a create_new semaphore or PID liveness file. Use a single same-user host coordination root independent of repository, source copy, Cargo home/target and per-command TMPDIR; otherwise independent quick/gate/standalone invocations can bypass each other. Admit a private0700 UID-owned directory, stable regular0600 lock, no symlink/hardlink/FIFO/device, owner/dev/ino checks before and after locking, no truncation, unlink or stale-lock reclamation. Open options and error taxonomy follow fetch_apalache. Actual UID is obtained by the existing process crate's safe rustix identity calls rather than trusting USER/UID environment. Fixed default coordination root must not be silently replaceable by public environment. Tests inject a root through an internal helper.

Suggested native interface under gate/lease.rs (or process support if custody belongs there): JvmLease::acquire(cancelled), JvmLease::admit_inherited(file), JvmLease::duplicate_for_child(), JvmLease::identity(). Identity is a receipt, not authority. Waiting uses try_lock with cancellation/liveness polling; errors other than contention are immediate refusals. No new scheduler or filesystem freshness shortcut.

Scope the first safe version conservatively to one outer JVM-bearing invocation (full gate/validate/standalone parent, or quick's actual test execution). Its DAG still orders framework, Temporal and standalone JVM phases within the admitted invocation. CPUs may overlap only per graph edges. Required mode global4/group2/recovery2/512MiB stays unchanged; native-only paths need no JVM lease; explicit Apalache retains cap1. Include discovery/version probes if the lease promises all JVMs, not merely models.

Parent/child handoff carries the SAME open file description, never path reopening plus an environment boolean. Stdio::from(File::try_clone()) can carry it as controlled native-command stdin while preserving stdout/stderr. The copied child retains its original source/provenance admission and independently validates inherited descriptor identity against the canonical host lock. Existing syscall target_main already maps context.null through fd3 to target stdin; a narrow optional orchestration input/custody File can replace /dev/null for this mode. Test the actual pinned Unix inherited-lock behavior; do not blindly call blocking File::lock again on a clone. A nonblocking supported-platform lock check must establish ownership or refuse, rather than trusting an env marker or mere matching metadata.

Most importantly, keep custody INSIDE the native supervisor until all owned descendants are dead/reaped. Holding File only in outer xtask drops it immediately on SIGKILL, before child JVM cleanup, permitting overlap. Duplicating into the supervisor preserves the lease while the liveness-pipe death path performs cleanup. Do not explicitly unlock a shared open description: release by descriptor close. Inherited children and outer supervisor retain custody across standalone clean env/copy boundaries. No parent waits for a child that reopens/reacquires its own parent's lock.

If implementation instead prefers leaf-only leases, it must separately prove that outer cancellation cannot kill lease-owning leaf supervisors before their JVM families. A normal RAII leaf guard plus outer kill-all is insufficient. This is why outer invocation custody is the smallest conservative first implementation.

## Necessary ownership amendment

With strictly unchanged manifests/locks there is no acceptable current public owned streaming orchestration API. Do not replace it with /bin/kill, PID enumeration, process_group(0)+Child::kill, or copy syscall unsafe code into xtask. Those cannot establish detached descendant cleanup, and xtask forbids unsafe code.

Recommend an explicit narrow amendment: process/src/support.rs and syscall.rs plus existing process tests/fixture; xtask dependency edge and both lock edge changes only; Temporal promotes existing xtask dependency to normal for wrapper reuse. Port only policy plumbing and OwnedProcess/run_owned onto current source, preserve checker default and its tests. Do not merge mixed assembly/manifest/locks wholesale. Native ownership handles liveness/cancellation/cleanup/output/status only; mise still owns dependency scheduling. Expose polling OwnedProcess so real leaf failure can trigger cancellation while mise is stuck on surviving descendant-held pipes. Merely wrapping mise and waiting for exit would retain the observed8s/12s delay.

Linux current subreaper machinery is the strongest reuse base. Darwin all-descendant guarantees remain unresolved: ordinary process groups are not enough because backend supervisors and fixtures already create other sessions/groups. Do not claim a full macOS gate contract from retained Orchestration. Need a bounded, separately reviewed native ownership extension for Darwin or an explicit platform limitation accepted by the owner; do not silently skip original gates or weaken checker prevention.

## Required focused controls (existing test binaries)

1. Two independent public gate/quick invocations with different source roots, targets, Cargo homes and TMPDIR contend on one host lease; a second producer cannot start before the first releases. Include independent standalone copied-root invocation.
2. Real parent/copy-child descriptor handoff: child executes required JVM-bearing stub without deadlock; unrelated contender stays blocked; parent env_clear does not destroy authority. Forged boolean/path/FD, wrong regular inode, closed FD and unheld lock must not admit.
3. Holder exit, spawn failure, named child failure, cancellation and original owner SIGKILL release without deleting the lock. Reacquire succeeds after cleanup. No stale PID or lock-file deletion recovery.
4. Parent SIGKILL during child model work: record descendant termination/reaping before contender entry. Include ordinary grandchildren and setsid/process-group escape on Linux; renew Darwin actual supported contract separately.
5. File/directory symlink, hardlink, FIFO/device, wrong owner/mode, path replacement while waiting and before/after acquisition all refuse promptly; protect unrelated files and produce exact refusal cause.
6. Real mise failure37 while sibling has ordinary and detached descendants: prompt owned cancellation/reaping, original named failure retained, dependent never starts; simultaneous failure records survive. Partial/duplicate/missing records fail admission. No second Rust stage scheduler.
7. Existing process checker timeout/output/nonUTF8/Java cancellation and Darwin prevention stay unchanged. New orchestration normal stdout/stderr remain separate, env removal/cwd/signal128+N preserved; declare stdin contract explicitly.
8. Frozen final candidate renews real standalone and correct-consumer quick proof, including cached positive/uncached negative TLC semantics. Synthetic contention does not replace that production proof.
