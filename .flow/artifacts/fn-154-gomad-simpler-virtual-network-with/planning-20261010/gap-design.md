# fn-154 gap reconciliation and bounded task design

Applications should receive a complete ordered stream after heal or a persistent timeout reset. The plan below combines that behavior with one local connection owner and payload-free network history. It deliberately reduces same-length payload checking in direct network-only simulation replay. Runner replay retains its separate bounded deterministic-I/O content checks.

## Ordering and lifecycle pins

Use the existing deterministic execution order and serialized model mutations. Equal-deadline native timers already use the seeded runtime stream. Do not add a global timer tie sort or a second process response barrier.

- Heal and a due expiry at the same instant compete in the existing model order. A heal committed first ends the stalled epoch and invalidates its expiry. An expiry committed first resets both endpoints permanently; later heal cannot reopen them. At exactly `start + limit`, expiry is not yet due. Retain tests for both deterministic event orders at `start + limit + 1ns`.
- Preserve the observed operation precedence. Current simulation Read checks reset/closed before pending or ready bytes, then peer EOF, then caller deadline (`simulation_handles.go:85-143`). Current Write checks terminal state, attempts available-capacity admission, then checks caller deadline (`:156-218`). Thus a committed stall reset wins over a same-instant caller deadline; already-readable data or available write space can produce ordinary progress before an operation deadline failure. An earlier operation deadline remains recoverable.
- Current dial checks `ctx.Err()` before topology/listener admission (`simulation_network.go:403`). Keep that order. An already-completed context wins before heal-based connection admission. Otherwise heal and the dial stall event follow the existing deterministic model order. The chosen stall error must retain timeout classification through process transport.
- Expiry carries stable connection identity, both endpoint incarnations and the stalled-direction epoch. Recheck them under the local model lock. Close, crash, graceful stop, restart, heal and later partition cannot let an obsolete event reset a replacement connection. Cancelled or stale events release their work without adding a semantic timeout record.
- Preserve current revocation behavior. Both graceful stop and harsh crash discard retained queued bytes. Graceful stop supplies EOF where the current contract does; harsh crash supplies reset. A partition does not turn graceful stop into delivery of previously held data. Timeout reset is an explicitly new terminal reason, separate from those outcomes.
- A model-owned virtual expiry must fire when the accepted writer has returned and no application Read/Write is active. Process time participates through the existing arbiter/progress owner. Native timers remain runtime-owned; host pipe readiness and wall time must not select expiry identity.
