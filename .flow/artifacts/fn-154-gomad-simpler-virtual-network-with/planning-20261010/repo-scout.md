# fn-154 network source survey

At source HEAD `73c507fbf09318f36ae6ddf30ad8a917d801e868`, fn-154 can remove the partition-induced stream gaps by replacing two local connection loops with one byte-queue owner. Three inferred requirements need correction before implementation. R5 adds a new dial timeout, R6 needs explicit omitted-field semantics, and R11 currently conflates blocking connection buffers with global resource exhaustion.

This report records read-only source inspection. No tests, product edits, lifecycle operations, native gates, git writes or external actions ran. Requested research routing was gpt-6-astra/high; the dispatch retained the session fallback after `jev-unavailable(no_key)` and this scout did not retry routing. Paths below are repository-relative. `io/` abbreviates `tools/gomad3/toolchain/runtime/overlay/src/internal/gomadio/` only within this report.

## Current behavior and requirement conflicts

**Partition gap is confirmed.** `simulation_handles.go:162` accepts a write while its peer has fewer than 64 chunks. A disabled/missing directional link records `partition_drop`, advances the delivery identity, returns success, and retains no bytes (`:166`, `:183`). Read dequeues already submitted traffic based only on its ready time (`:102`), without checking the link. `simulation_network.go:737` changes enabled bits and signals only the network channel (`:1099`), whereas blocked connection reads/writes wait on their shared connection channel. R1-R3 require both changed retention and topology-to-connection wakeups.

**There are two capacity layers.** `network.go:33` defines a 64-connection accept backlog, 64 queued chunks per direction and 64 KiB chunk size. Local fullness blocks. `simulation_handles.go:168` returns `ErrResourceExhausted` immediately for global delivery-count or byte exhaustion. `spec.go:30` bounds listeners/connections/deliveries and bytes independently. R11's blanket resource-exhausted wording conflicts with R1's blocked writer at connection capacity. Byte-only stream capacity does not imply deleting listener, connection, transition or IPC frame bounds.

**Current byte accounting misses retained read tails.** Simulation Read transfers a whole chunk to `connection.pending` and releases its global byte charge before copying any bytes into the caller (`simulation_handles.go:121`). Short reads leave uncharged bytes in that pending slice. Byte-only accounting should charge every retained unread byte until consumption or discard. Decide explicitly that bytes already delivered into the receiver before partition remain readable; R2's prohibited crossing applies to in-flight/held bytes, not bytes already received. A distinction between delivered/readable and held bytes is still needed without delivery-history records.

**R5 is only partly existing behavior.** `simulation_network.go:398` waits for heal or caller context while the forward link is disabled (`:437`), and then checks listener availability. There is no internal dial stall timer. Process Dial transmits the context deadline (`process_network.go:73`) and reconstructs it (`:207`). R5's stall-bound dial is an inferred extension, not necessary to R4's established-connection stalled-data rule. A cancellation occurring after IPC starts has no separate cancellation command here. Preserve existing cancellation capability claims instead of broadening them by wording.

**R6 has a clear project convention but no duration precedent.** `DefaultLimits` fills explicit positive limits; `validateLimits` rejects zero and values above maxima. Strict canonical decoding (`spec.go:159`) does not insert defaults. A new scalar field cannot distinguish omitted from explicit zero. There is no evidence here for Linux's cited 15-minute value, and no existing network timeout default to preserve.

**Reset needs a typed reason.** Existing `connState.reset` is boolean and reads/writes return `ErrClosed`. R4 needs persistent timeout state visible at both ends after expiry, independent of cleared caller deadlines. `process_commands.go:116` maps known errors to wire codes, but a new generic timeout would lose its timeout identity through the generic message fallback (`:166`). Add a stable timeout error encoding or use a documented existing timeout classification with tests distinguishing persistent reset from a recoverable caller deadline.

**R9 must name the scope of consolidation.** Standalone and simulation local semantics can share one owner. `processConn` must still marshal remote commands; its continued existence does not violate one local connection model. Preserve half-close, empty I/O, partial writes, complete-operation direction locks and descriptor readiness while removing the duplicate local loops.

**R10 removes a real network replay detector.** Transitions currently include Delivery and PayloadSHA256 (`types.go:196`), and replay compares the complete transition before mutation (`simulation_network.go:958`). They contain neither payload bytes nor virtual timestamps. Replay presently reexecutes target code and checks transitions; it does not reconstruct data from a self-contained write log. `gomadtrace/trace.go:110` separately hashes network call arguments/content in the deterministic-I/O transcript, but `io/transcript.go:19` records only when deterministic I/O is enabled. The hash is SHA-256 (`internal/gomadwire/wire_generated.go:468`), and a successful simulation Write submits its exact input bytes at `simulation_handles.go:207`. `gomadio.go:28` initializes that transcript only with the runtime I/O profile; `NetworkEnabled` at `:54` independently enables simulation networking without it. Thus a direct `GOMADSEED` in-process simulation without the I/O profile has only the NetworkRecord write hash for this payload check. Removing network payload hashes intentionally reduces standalone network-record payload checking unless another observation detects the changed payload. Do not claim unchanged same-length-payload divergence detection from the simplified network record alone. Preserve structural before-mutation divergence and full-record consumption, and state that exact Runner replay composes separate evidence dimensions. Whether retaining the generic I/O content hash satisfies the owner's phrase “no payload hashes” needs the root's scope interpretation; it is outside network history today.

**R7 needs wording aligned with R10.** Topology heal can record one change and derive releases. Do not introduce a separate per-release/per-delivery history step while promising their removal. `simulationTransitionLane` currently orders topology separately from each connection (`simulation_network.go:1006`); these lanes are not a global timestamped delivery schedule.

**Revocation already discards queued data on graceful stop as well as crash.** `simulation_network.go:830` drops both incoming queues before selecting graceful EOF versus crash reset. Preserve this explicit existing behavior under R12 and test it during a partition. Incarnations are compared by node plus incarnation (`:1095`), and process resources add domain/handle ownership (`process_network.go:313`). Restart must never revive held bytes or a stale stall timer.

## Recommendations for the root's design

1. Keep R5 at its existing heal-or-caller-deadline behavior for the smallest scope. If retaining the inferred dial stall timeout, identify it as a deliberate new behavior with its own expiry start, error mapping and heal-versus-expiry test. Avoid a TCP handshake/retransmission model.
2. Put the positive duration alongside explicit Limits and have `DefaultLimits` supply a named default. Under the existing strict contract, omitted and zero both reject; document that canonical old specs/records require the versioned migration rather than silently inserting a new value. Recommend 10 virtual seconds as a practical initial default, explicitly a design choice rather than a measured production match. The representative model workload uses a 1 ms caller deadline (`temporal_scenario_toolchain_test.go:79`) and the process harness uses a 20 s virtual test timeout (`simulation_root_integration_test.go:88`). Use short explicit stall settings for regression tests so the default never controls their timing. Validate duration conversion and deadline addition against overflow.
3. Make per-direction connection occupancy byte-bounded and blocking, with a 4 MiB default preserving the existing 64 × 64 KiB maximum queued payload. Keep the shared network byte budget as an immediate resource-exhausted ceiling to preserve R12's exhaustion fault and avoid cross-connection global wakeup policy. Rewrite R11 to distinguish these outcomes. If the owner intends global exhaustion to block too, R1/R11 need that explicit decision and R12 must retain resource exhaustion through listener/connection/history limits. Do not preserve chunk-count admission under another name.
4. Start continuous stall time when undelivered bytes first encounter a disabled directional link, whether they were queued before partition or written after it. Healing ends that continuous interval; healed data becomes eligible after the link delay, with FIFO ordering preventing overtaking by fresh writes. Repartition starts a new interval. Expiry resets the entire connection if either direction remains stalled. Idle partitions create no connection-expiry work. Use virtual time and stable connection/incarnation identity for expiry ordering and reject stale callbacks after close/crash/restart. This needs an active expiry event when the accepted writer has returned and no reader is waiting.
5. Keep network semantic histories payload-free as requested, retain ordinary bounded I/O transcript behavior unless the owner explicitly broadens removal, and test the documented division of replay guarantees. Reject old network model identities before activation instead of claiming compatible replay after removing delivery records and fields.
