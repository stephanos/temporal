# Rust crate reuse review

The best line-reduction opportunity is to use the already pinned Serde stack for storage-model JSON and duplicated string escaping. Expected savings are tens of lines, not thousands. A second, smaller opportunity replaces the handwritten host `getrusage` ABI with the already locked `libc` package. No source or dependency changes were made.

## Ranked opportunities

### 1. Reuse Serde for Go-compatible storage JSON and string escaping

Code locations under `wasmhost`:

- `src/volume/config.rs:47-103`, `StorageModel::go_json`, manually emits object fields, arrays and omission rules. `VolumeConfig` and `VolumeLimits` already derive `Serialize` with the required Go field names in `src/volume/state.rs:32-48`.
- `src/volume/config.rs:250-274`, `go_string`, and `src/network/cluster/evidence.rs:78-106`, `json_string`, duplicate JSON string escaping. `src/conformance.rs:1047-1055`, `go_json`, already demonstrates Serde serialization plus Go's five extra HTML/Unicode escapes. Volume faults also call `go_string` at `src/volume/faults.rs:221-230`.

Add serialization-only omission attributes to the storage structs, preserving deserialization and `deny_unknown_fields`, and serialize their declared field order. Preserve `volumes: null` versus `[]`, omit both absent and empty faults/database lists, and omit zero fault bytes. Serde supports [conditional field serialization](https://serde.rs/attr-skip-serializing.html). Centralize the small Go-compatible escaping adapter over serde_json. Its pinned [serializer exposes `Formatter::write_string_fragment`](https://raw.githubusercontent.com/serde-rs/json/v1.0.149/src/ser.rs), allowing the five extra escapes while Serde owns quote, backslash and control-character handling. Prefer writing to the existing output buffer if this avoids new per-field allocations.

Estimated net removal is **35-65 lines** across the combined change, allowing roughly 25-40 lines for formatter/wrappers, 10-20 for derives/omission helpers and 20-35 for focused preservation cases. Moving functions alone counts as zero savings. Start with storage JSON; adopt shared escaping only if the actual patch remains smaller and allocation behavior is acceptable.

Compatibility risk is medium because these bytes bind identities and evidence. Keep exact key order, lowercase escapes, all control characters, U+2028/U+2029, HTML escaping, base64 conventions and nil/empty distinctions. `src/storage_transport/vector_corpus.rs:184` already compares literal model JSON and identity. Retain that comparison, Go differential corpora and independent raw-byte assertions. Do not change network `OperationResult`'s existing general-purpose serialization to base64 globally; `src/network/mod.rs:74-90` currently serializes its bytes as an array for other consumers. Replacing all network JSON with fresh mirror structs would consume much of the apparent saving and is outside this recommendation.

No new dependency or feature is needed. serde_json 1.0.149 requires Rust 1.68, offers `std` by default and is MIT OR Apache-2.0; it fits both maintained host platforms. Its dependency graph is already paid for. [Pinned manifest](https://raw.githubusercontent.com/serde-rs/json/v1.0.149/Cargo.toml). The upstream release page shows continuing releases through 1.0.154, supporting current maintenance; an upgrade is unnecessary for this change. [Upstream releases](https://github.com/serde-rs/json/releases).

### 2. Replace the handwritten host resource-usage ABI with libc

`src/metrics.rs:60-81` declares platform-specific `Timeval`, `Rusage`, musl/OHOS padding and `getrusage`; `sample` at lines 103-120 accesses positional counters. The layout-only assertions at lines 139-150 would also become unnecessary. Use `libc::getrusage(libc::RUSAGE_SELF, ...)`, `libc::rusage`, `ru_utime`, `ru_stime` and `ru_maxrss`, retaining the local checked unit conversions and optional result. The [upstream Unix declarations](https://raw.githubusercontent.com/rust-lang/libc/0.2.189/src/unix/mod.rs) own this platform ABI.

Estimated net removal is **25-40 lines**, including adjusted tests and imports. Its stronger benefit is removing manually maintained ABI layouts. This is an optional host-maintenance improvement rather than a large line-reduction project.

The existing rustix 1.1.5 [`process` API](https://docs.rs/rustix/1.1.5/rustix/process/index.html) does not provide `getrusage`. `libc` 0.2.189 is already present at `Cargo.lock:553-556`, but using it requires a new direct dependency declaration. That declaration is not authorized by this research request. Pinning the existing version should avoid another package version, subject to later lockfile verification. Its [manifest](https://raw.githubusercontent.com/rust-lang/libc/0.2.189/Cargo.toml) specifies Rust 1.65, MIT OR Apache-2.0, no required ordinary dependency, and Linux/macOS targets including the architectures used here. Default `std` is sufficient. Upstream continues releasing platform fixes, including 0.2.190 and 0.2.191. [Release history](https://github.com/rust-lang/libc/releases).

Keep the current target gating and failure behavior. In particular, retain Linux `/proc/self/status` `VmHWM` preference and fallback, checked RSS units, overflow checks, and `exec_does_not_inherit_parent_peak` at `src/metrics.rs:198-241`. Replacing all metrics with a generic process-monitoring crate could report the inherited parent peak again. The FFI call remains unsafe even with libc; this removes layout ownership, not the need to handle failure.

This is not a recommendation to add it to production cache publication.

## Adoption boundary

Any later implementation must preserve protocol/evidence bytes, strict unknown/duplicate-field refusal, bounded allocation and admission before mutation, replay identities, deterministic ordering, refusal stages, raw-byte comparators and Go differential oracles. Source and dependency changes rotate the helper identity even when logical behavior is preserved. They require fresh matching builds and applicable qualification; this report supplies neither an execution pass nor permission to add third-party dependencies.
