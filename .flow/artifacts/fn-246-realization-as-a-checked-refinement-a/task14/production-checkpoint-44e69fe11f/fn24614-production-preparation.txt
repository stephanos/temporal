Design amendment for observable-domain closure and canonicalization

The universal binary child-closure recommendation was too strong for task .5. Current feature/activity/model.rs:167-180 sets cancel_requested on cooperative Cancel while Started. Worker::Heartbeat at :223-230 preserves it, and the explicit heartbeat postcondition at :512-517 requires that preservation. clear_terminal at :298-305 resets it only while closing the task; successful retry without pending cancellation creates a new attempt, while retryable Fail with pending cancellation closes Canceled. Further Cancel while already pending rejects and cannot clear the bit. Thus, once a successful true heartbeat has identified pending cancellation for one still-running assignment, every later Model-feasible successful heartbeat on that same assignment returns true under the approved binding. A later false after true is outside that Model-observable domain. Terminal expiry/error is not an additional successful false result. Hidden timer branches can prevent a later success, but cannot justify a false bit.

Requiring h+[false] after every heartbeat chosen at a prefix already containing true would reject a complete Model-derived policy or force unreachable padding. Task .5 Approach 1-4 and acceptance define the policy domain using actual observable histories over all client/environment branches, enumerate policies consistently on equivalent histories, and canonicalize semantic duplicates. The spec's worker-strategy and executor-stage amendments require missing-continuation rejection, but do not require binary closure over Model-impossible successful results. Universal binary transport capability and a particular Model policy's feasible successor domain are separate properties.

Recommended contract: the feature-owned current program format carries an explicit finite observable successor declaration for each heartbeat decision, separate from the chosen response rows. Its schema placement is an implementation choice for the existing feature key/program owner. For example, a typed per-key successor manifest lists the allowed actual bool extensions, with nonempty unique values and exact key identity. It contains observable keys/bits only, no hidden state, budgets or Model callbacks. Go checks structural totality against that declared manifest. Each declared child has exactly one response row; every response row belongs to the declared reachable domain; roots/parents and finite depth/work are checked. Go cannot prove that a producer's declared domain covers the Model. The independent Rust construction owns that proof. Absence of a child alone cannot serve as its own proof of infeasibility.

Task .5 must derive each successor set from the union of all compatible full checked histories under all admitted client/environment branches for the observable key and selected policy. It must independently compare the domain and required decision inventory with the emitted graph, rather than reconstruct the domain from the already supplied rows. A singleton true domain after an observed true is legitimate because the monotone pending bit is already observed. A singleton false before true requires the same independent all-branches argument for that World/scope; choosing one convenient hidden representative is invalid. If a successor remains unresolved at a depth/work bound, refuse completeness instead of omitting it. Canonical names/identity include the feasible observable decision domain and typed choices; unreachable padding supplies neither new policies nor coverage. Distinct exact histories still cannot be collapsed to the last bit.

This preserves missing-continuation discrimination at both boundaries. Deleting a declared response row while retaining its domain entry fails Go startup admission. Deleting a feasible successor from the declaration fails independent Rust domain/coverage controls, even if Go structure is internally complete. Missing, duplicate, incompatible or altered choices remain errors. An unexpected but well-formed actual completion outside the declaration must be retained unchanged, halt progression without a fabricated terminal, and reach the existing fault/evidence owner. Go reports the mechanical domain mismatch; fn-237.4's feature judgment retains responsibility for classifying a contradictory notification as Unexplained. A contradictory in-scope actual bit cannot acquire Unsupported or coverage credit through this metadata.

Keep task .14's generic finite-history capability and native controls independently broad. The executor can follow both children whenever both are explicitly declared, singleton continuations when declared, repeated false, false-to-true and repeated after-true delivery. It must not hardcode monotone cancellation or infer hidden feasibility in Go. Native/mock capability programs can declare a transport history outside the feature Model to test faithful dispatch and retained actual evidence, with no Model coverage claim. Preserve the original max-one-heartbeat unknown/false/true regression as an explicitly binary domain where its approved witness requires both outcomes; terminal-only and after-true SDK terminal choices remain unchanged. No required capability, original live witness or independent Model law is narrowed by this amendment.
