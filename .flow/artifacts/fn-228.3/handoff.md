## Decisions on the owner's behalf
1. The `umpire` binary lives in the server module (`tools/umpire/cmd/umpire`) so .4 can register
   the Temporal Driver; its CLI logic is generic `runner.Main(ctx, args, stdout, stderr, drivers)`.
   It registers no Driver yet: question/replay work, explore/reduce/repeat exit 3 until .4.
2. Exit 3 for "the loop could not run" (usage, unreadable input, Host trap), separate from verdicts.
3. A non-refusal Host failure (trap, ABI error) aborts with an error, not a recorded verdict.
4. `runner.Run` is an alias of `runv1.Run`; `Runner.Run(ctx, mode, opts) (*Run, error)` returns the
   deciding Run (first Unexplained, else first Refused, else last); every Run goes to `Options.Record`.
   Batch exit code follows that order.
5. Propose seeds = splitmix64(run seed, request number); replay rejects other seeds. Reduce therefore
   reruns with proposal budgets 1..n (n = recorded proposal count), which equals replaying the recorded
   proposal-seed prefixes; it records only its result, and when nothing reproduces it returns the last
   candidate with its own verdict.
6. Annotate is a Driver event kind (EventAnnotate) so any Annotate goes through the one Host and is recorded.
7. The first terminal event decides the verdict; teardown faults (exchange/Driver close) are still
   recorded. Proposal/event budgets end Explained with that termination; a run time budget expiring
   during a wait is a DriverFault (Refused).
8. question: with `--run`, replays `--events n` (default all) and refuses a prefix that already ends
   the Run; without it, Resets with `--world`. `--world`/`--observation` are binary google.protobuf.Any files.
9. Publish is implemented in the runner package (the model module cannot import testpilot/publish),
   with the same link algorithm. `--store` is required for explore/reduce/repeat, optional otherwise.
10. Old commands deleted now; the packages they used (conformance, explore, testpilot replay/evaluation/
    campaign…) stay for .6. `umpire-rerecord-pinned-runs`/`UMPIRE_PINNED_RUNS` were removed because their
    only probe lived in umpire-assess; the pinned record file and live-test hook stay for .6.
11. Canary reduction to lease + policy is deferred to .6: the canary can only produce Runs through the
    Temporal Driver (.4), and .6 owns tools/canary deletions together with evaluation/casefile.
12. `proto-go.sh --check` excludes the hand-written `runner` directory from the generated-tree diff,
    keeping the spec's import path `umpire.local/model/umpire/runner`.
13. Redaction: `Options.Redact` marks events after judgment; replay refuses a redacted Run.
