## What was built
- **`Interpreted<M>`** (`umpire/checker/src/interpret.rs`, gated off wasm32) is a `Machine` that evaluates the embedded tree.
  - Steps: branch guards in written order, the first true guard wins. Then the branch `checks` run, for checked-arithmetic failures, followed by the outcome and updates.
  - Steps behave as compiled: a step that changes state and rejects returns `RejectedAfterMutation`, and a step that changes nothing is disabled unless it carries `stay!` or a rejection.
  - Arithmetic is done in i128 and range-checked against the expression's type. Failures panic with Rust's own messages (add, subtract, multiply, divide by zero or overflow, remainder by zero or overflow, negate).
  - Claims use `Claim::with_checks` and `StepClaim::with_checks`/`after_checks`. Progress uses `Progress::evaluated`, and assumptions come from the tree.
  - Claim callbacks are plain `fn` pointers, so each claim position gets its own const-generic callback. `CLAIM_LIMIT` is 64 per kind; a Model with more claims is refused at construction.
  - Starts come from the tree's `Value`/`Range` domains. Computed starts and declared-World starts delegate to the compiled Model.
  - Delegated to compiled: catalog (`actions`, `checked_catalog`, outcome/fault catalogs) and `claim_order`. World values and catalog inputs are imported once through the existing `Values`/`ActionValues` exports.
- **Typed state accessors.** `umpire_dsl::__lifted::Interprets` adds `__umpire_get/set/state`, outcome encode/decode and `__umpire_checks`.
  - `#[machine]` generates them in `lifted::embed`, beside `impl Lifts`, as `cfg(not(wasm32))`. They are generated only for admitted modules.
  - They are typed by the IR: integers decode through their exact Rust type, the stock Outcome/Rejection use absolute paths, and other enums use their qualified variant paths.
  - **Decision:** they are generated by `#[machine]` and not inside `derive(State)`. This keeps the derive and machine expansion snapshots byte-identical, and the derives inside `#[machine]` are the same declarations.
- **IR value**: `umpire_ir::value::Value` (Bool, Int, Enum by variant index, Text, Unit, Tuple, Seq).
- **Check text.**
  - **Decision:** new `ExprKind::Check(usize, Box<Expr>)` wraps each `check!` leaf. Without it a failed interpreted check could not reproduce the compiled `check!(...) failed at` text in reports and paths.
  - The front records each `check!`'s original tokens (`admit_checks`). The macro emits `__umpire_checks()` by re-stringifying those tokens through a `($e:expr) => stringify!($e)` macro_rules, the same capture `check!` uses, so the text is byte-identical. This includes `closable` laws.
  - Lift emission, naming and the Apalache safety walker read through `Check`, so TLA+ is unchanged.
- **Runner.**
  - `fixture!`/`lifted!` define `interpreted()`, probed by autoref like `__embedded!`.
  - `umpire_testing::interpreted(world_fn, starts, budget, negative)` and `compare(..)` explore both ways. They require every rendered checker file (report, states, rows, negative_report, paths) to be identical. Equal refusals count as agreement. A disagreement names the first differing file and line.
  - `discovery::generate_interpreted` is used only by umpire-fixtures, so the hand-written Temporal activity `tests.rs` (lane A's area) is untouched.
  - **Decision:** a fixture's negative claim is judged by the compiled World on the interpreted states, through `Interpreted::with_negative`. It is a test hook, not part of the Model, and the tree's hook negatives come from the lifter and are renamed.
- Docs: a README paragraph (fixture hooks) and a DESIGN.md "Interpreter as a differential check" paragraph with the timings.

## Decisions on the owner's behalf
1. Accessors are generated by `#[machine]` (embed), not `derive(State)`, so expansion snapshots stay byte-identical.
2. The new IR node `ExprKind::Check`, with a macro-generated text table, gives exact `check!` failure text. The IR changes only by this wrapper; emission reads through it.
3. Catalog, claim order and computed/declared-World starts stay compiled. fn-211 R6's lifted-start lowering has not landed (fn-211 is all todo), so there is no lifted-start evaluation per World. The `Value`/`Range` start domains are interpreted, and their order is compared through states.txt.
4. Negative fixture claims are judged by the compiled closure on interpreted states.
5. The differential is a separate test (`interpreted_agrees_with_compiled`) plus an `interpreted` test target, and it writes no goldens. Shared fixtures' `run()` is unchanged. The hand-written `run()` of the checker controls progress_bounds and progress_explicit_fairness, and (since the review) of the Temporal activity, each gained one `umpire_testing::interpreted(..)?` line; their outputs are unchanged. (Corrected per review nit 8.)
6. `imbl` is added as a dev-dependency of `umpire-fixtures` (workspace dependency, no new third-party crate) so the lifter's vector Models compile there. The guest is unaffected.
