# fn231 Rust minimizer design

The minimizer will inherit a scoped campaign artifact's authenticated search context, preserve its acceptance predicate, and explain accepted reductions with retained symbols. This design covers fn231.1 and .2 on the existing Rust implementation. Implementation waits for accepted predecessors, including fn230.1's public plan receiver in fn232.11. ## Decisions and actual public boundary

Choose an additive manifest-authenticated provenance payload plus a pinned minimizer ordering context. Reuse `campaign/exploration/site_scope.rs`, existing `State`, `Workspace`, `Opened`, and symbolizer. Reading the parent campaign on minimize was rejected because a detached artifact must work. Putting scope/symbols into `inspection::Minimization` was rejected because it changes the expressly preserved evidence block and its identities.

The current public path in `minimize/mod.rs` constructs only `State::choice`. `predicate::Parent::from_replay` refuses clusters and simulation evidence. `State::simulation` is available only under test/fixture configuration. Keep these public refusals and the choice-prefix suffix order. Add scoped category ordering to that existing simulation/controller surface without adding a second minimizer or new public simulation execution grammar. Public prefix minimization receives scope parsing/inheritance, pinned checkpoint context and reporting, while its attempts remain suffix-only.

This distinction defines the specified coverage. Controller fixtures prove category ordering and different greedy attempt counts. Public prefix fixtures prove the explicit suffix-only ordering exception, scope/error admission, inheritance, checkpoint binding and reporting. The spec's Architecture and Boundaries preserve prefix order and defer prefix-boundary ordering. They require no additional public simulation minimizer or owner-decision gate.

## Producing-round search context

fn230's current `Resolution` serializes a private `packages` map and fingerprint set. `ChoiceState::summary` exposes the latest accumulated resolution, which changes across rounds. `ChoiceState::commit` observes each result trace as it generates later candidates. `campaign/choice.rs` currently retains publications before committing the round, and discards the preliminary base `Resolution` after saving only its scope digest/count in `ChoiceConfig`. These are the insertion points.

Add `provenance/search-context.json` as an optional payload in the existing `Manifest.files` extension surface. The payload is canonical typed JSON with a versioned payload schema, normalized patterns, full immutable producing-round resolution snapshot, its domain-separated digest/count, canonical campaign plan digest, zero-based producing round ordinal, and target/module plus ChoiceIdentity binding. It contains no final journal hash or output artifact reference. Bound it at 16 MiB, within the existing plan/checkpoint envelope, and fail a producer that exceeds the bound. Validate map/set entry counts and total strings within the same byte envelope before allocating symbol work.

Freeze the snapshot before processing round completions. Every artifact from a given round uses that same snapshot, regardless of completion order or sites discovered in another completion. For round zero, retain the preliminary resolution computed from the already-executed base trace and used to construct `config.site_scope`; validate it equals that plan scope. For later rounds, clone the committed `state.site_scope_resolution` that selected the producing round. The current round's newly observed sites belong to the next round's snapshot. Preserve fn230's exploration algorithm and dynamic resolution accounting.

Derive the plan digest from `canonical::encode(journal.plan())`, the same bytes whose SHA-256 initializes `RoundJournal` storage. It is immutable before execution retention. The producer adds context to the publication before `retain` calls `Store::publish`. Journal open/append authentication checks its context's plan digest, module/choice identity and round ordinal against the event being authenticated, and compares its snapshot with the replayed pre-round state. Base context is checked against the retained base trace and declared initial scope. This proves the payload came from the correct round without a circular final-summary dependency.

The detached opener uses only the pinned `Opened` capability, its manifest and retained module/tape. Check canonical typed encoding, `deny_unknown_fields`, payload schema, byte limits, pattern grammar, canonical fingerprint/set representation, digest/count recomputation and module/choice identity. Check package observations against the retained module's symbolizer using the shared mapping rules. It need not reopen or reconstruct a removed campaign. The authenticated payload commits the producer's round snapshot; that snapshot is distinct from the minimizer's later parent-specific resolution.

Absence means the manifest does not list this payload. It supplies no inherited scope, even if a nearby directory or campaign summary contains one. A listed but missing, tampered, oversize, malformed, noncanonical or semantically inconsistent payload refuses with status 2 naming the parent, even when an explicit flag would override its patterns. Do not catch its error and downgrade it to absence. An explicit flag overrides only valid inherited pattern selection, retaining the authenticated source snapshot identity in the ordering binding.

## Publication equivalence without record changes

The existing artifact manifest permits authenticated files beyond `record.streams`. Use that surface. `Store::publish` includes all payload digests in `Manifest.files`, compares entire manifests before reuse and writes exclusively. Adding this payload to `record.streams` would change canonical record bytes and failure signatures; do not do that. No artifact-manifest version or minimization-evidence version bump is required. fn231 explicitly authorizes this additive provenance payload and a context-qualified publication key.

The current two destination names are the failure signature and `execution-<record hash>`. Two contexts can therefore exhaust both slots for the same execution. For context-bearing publications, use a deterministic `execution-<record hash>-context-<search-context digest>` name as the context-qualified destination and verify full manifest equality before reuse. Keep existing names for context-absent artifacts. Preserve exclusive rename, store locks, fsync and byte accounting. Never overwrite an existing variant.

Update `artifact_name`, retirement admission, `.retire-*` validation and live-reference checks together. Authenticate the context suffix against the manifest-listed payload digest. A same-record/different-context fixture must retain both variants, identical record hashes and failure signatures, different context digests, successful detached open and no overwrite. Unknown qualified names or a suffix/digest mismatch refuse. Do not weaken these checks to accept arbitrary suffixes.

## Parent-specific resolution and checkpoint key

Add `site_scope: Option<Vec<String>>` to CLI arguments with `site_scope::parse_patterns`; do not duplicate pattern grammar. Before entering `minimize::run`, open replay and search context, select explicit patterns or inherited patterns, and, if scoped, require module symbols and resolve the parent trace once. Use the parent's authenticated `target/module.wasm`, full raw choice trace and ChoiceIdentity. Keep the source snapshot and the parent resolution as separate fields.

Use one symbol map for all sites needed by scope classification and reporting. Refactor the narrow `Resolution::observe` seam to accept that map rather than independently symbolizing again. Classification calls existing `Resolution::allows`. Runnable decisions are in scope when any available alternative creation site matches, exactly as fn230; other decisions use their retained site. Missing/unavailable sites remain out of scope under that established rule. An empty matched set is valid for minimize and makes all removals out of scope. It does not trigger fn230's exploration-only `site_scope_empty` stop.

Pin a typed ordering key containing the ordering algorithm version, explicit versus inherited selection, normalized patterns, source-context payload digest or explicit absence, producing plan/round/snapshot identity when present, parent record and parent module/trace identities, and the recomputed parent `SiteScope` digest/count plus a bounded decision-classification digest. Include it in `checkpoint::Binding`, `State`, state hashing, `source_matches` and history reconstruction in `State::validate`. The classification map used by `proposal()` is pinned state, authenticated against the initial parent map on resume. Never consult changed ambient scope or mutable campaign state while replaying history.

`Workspace::open` already compares exact binding and returns `minimizer checkpoint binding changed`; `cli/minimize.rs` maps minimizer/workspace errors to status 3. Preserve that refusal for changed scope, context, parent, resolved map or bounds before any resumed attempt. Invalid new patterns, stripped scoped modules and malformed parent context are input admission failures with status 2, before a workspace or trial exists. Do not move them into the current blanket status-3 `minimize::run` error mapping.

Bump the minimizer controller implementation constants deliberately. Old checkpoints must fail through existing implementation/binding admission, not deserialize into a fresh ordering silently. Keep lock, atomic checkpoint publication, accepted-artifact verification and complete-resume no-op behavior. The per-parent workspace name may remain `.minimize-<parent record hash>`; distinct contexts in the same output root intentionally encounter changed-binding refusal and can use separate output roots.

## Stable proposal order and exact acceptance preservation

Keep `State::proposal`'s `choice_source` branch unchanged. It proposes effective prefixes by increasing length and stops after the first accepted prefix. No scope-based prefix-boundary ordering is introduced.

For simulation/controller proposals, preserve the existing generator's `schedule_suffix`, `schedule_range`, `fault_entries`, descending removal length and ascending start order. With a scope, select the first unseen proposal from these stable classes in order:

1. Every removed decision is out of scope.
2. The removed set contains both classes.
3. Every removed decision is in scope.

A bounded three-pass scan over the existing generator avoids collecting an unbounded proposal vector and preserves order within each category, including existing duplicate-candidate handling. Classify before expensive candidate construction where possible. Include every proposal class; sorting only within `schedule_suffix` would miss an out-of-scope range behind a mixed suffix. With no scope, take the original generator branch directly and preserve its proposal serialization byte sequence, evaluated candidate sequence, accepted identities, stop and attempts. Implementation/checkpoint hashes deliberately rotate as required; the no-scope sequence guarantee does not promise unchanged implementation digests.

Do not change `Parent::matches`, its immutable behavioral record handling, `parent.choice`, runtime prefix construction, exact replay check, failure grouping, fresh stores or simulation canonical candidate algorithm. Sorting never excludes in-scope removals. Preserve outcome equality, target-failure domain, original failure signature, no divergence and exact retained runtime replay. Existing simulation replay refusals remain explicit.

The present fixture input's `accepted_indices` is unsuitable for R3 because reordering changes which candidate a given index names. Add a bounded content-based predicate fixture alongside it. Use three canonical runtime decisions in ordinal order, A and C in scope and B out of scope. Accept exactly when the remaining overrides contain A or C, independent of attempt index, order and display symbols. With sufficient budget, the legacy generator rejects removal of all three, accepts removal of suffix B/C, and finishes with A in two attempts. Scoped ordering first accepts removal of B, then rejects removal of A/C, then accepts removal of C, finishing with A in three attempts. `canonical_candidate` excludes parent provenance from candidate SHA, so the seen-empty candidate is skipped as expected. Assert both sequences/counts and evaluate both final candidates with the same content predicate. A second fixture uses the same candidates/predicate with A out of scope and B/C in scope. Scoped order accepts removal of A, rejects removal of B/C, rejects removal of C, then accepts removal of B, finishing with C in four attempts. Legacy order still finishes with A in two. Assert both final candidates satisfy the predicate and deliberately do not assert equal final bytes.

This proves controller search behavior only. Separately, run public prefix minimization on an actual retained failure with and without explicit scope, and use the existing real `Parent::matches` plus exact replay path to prove its predicate is unchanged. Retain the unchanged public cluster/simulation refusal fixture. Do not claim the content predicate substitutes for public runtime acceptance.

## Detached symbolized reporting

Current removed entries carry only `(dimension, ordinal, identity)`. The accepted trial's trace can omit decisions removed from the original parent. `minimization/original-record.json` commits only the original behavioral record, not that source tape. Symbolization therefore needs an additional authenticated source payload.

For newly minimized results retain `minimization/source-choice.bin` containing the bounded original parent's raw choice trace and `minimization/source-choice.json` containing its exact ChoiceIdentity, original tape digest/count, raw-trace digest and original decision commitment. The source trace uses the parent's already-admitted choice limit; the descriptor is bounded at 16 MiB. Manifest-list both payloads without adding them to canonical record streams. Include their size in accepted/final publication byte caps. Retain valid search-context provenance unchanged on the final artifact. Continue writing `minimization/original-record.json` and its current record-stream commitment exactly as fn232.9 does.

The shared opener validates these optional payloads together, canonical descriptor and digests, then projects the source trace with `linked::project_choices`. Join removed decisions by dimension, effective tape ordinal and exact decision identity. Check identities before displaying any symbol. Never join on function name, infer an offset from an ordinal, or use a current/source-tree binary. For the public prefix lane `choice_candidate` retains `selected_identity`; use that exact current representation. A future simulation decision must use its authenticated canonical identity and retained site mapping; absent mappings cannot be guessed.

Build the symbol map once from the retained module and the union of original/final sites. Attach existing `Symbol` objects to each accepted reduction's removed decisions in a report-only projection. Preserve fn229's site choice and its `site_missing`, `no_symbols`, `offset_out_of_range`, `symbol_mismatch` and capacity reasons. Runnable scope membership still uses any creation site; display uses the existing authenticated decision/site projection and exposes unavailable when that projection has no singular site. It must not pick an arbitrary alternative just to obtain a package name.

For `minimize --json`, project accepted rows with `removed_in_scope` and `removed_out_of_scope`, and add the selected scope in the same `{patterns,resolved_sha256,resolved_count}` shape as explore. Emit the scope block only when one is selected. Report counts for each removed decision exactly once. In the unscoped report, emit zero in-scope and all removed decisions out-of-scope while omitting `site_scope`; this has no effect on the attempt sequence. `inspect` projects accepted removals with symbols and adds `final_forced_by_symbol`, sorted by package then function, with unavailable groups sorted by reason. Each final forced decision contributes once; group counts sum to `final_forced_decisions`.

Keep `inspection::Minimization`, `Reduction`, `Decision` and its validator unchanged. Add report wrapper types following `evidence/symbolize/inspection.rs::Symbolized`, rather than serialize new fields into retained `evidence/inspection.json`. Raw minimization evidence remains byte-identical before and after generating the new reports. For fixed algorithm result/implementation the producer keeps the same existing field meanings and predicate bytes; scoped ordering may legitimately change attempts/reductions, and the mandated implementation digest changes deliberately.

Legacy artifacts with neither source payload still inspect. Resolve only decisions whose retained tape supplies an exact identity/site join; report other removals as unavailable using the existing `site_missing` representation, without inventing a new public reason. If either new source payload is present, both must validate. Malformed or tampered present payloads fail closed through the shared opener with status 2. Stripped modules remain inspectable with `no_symbols`; supplying a scope for minimization still refuses before attempts. No campaign or source checkout is required for any reporting join.
