# fn-232.13 Rust qualification implementation and verification map

Design recorded on 2026-10-22. This document changes no task state and records no passing gate. Implementation and the qualification window wait for fn-232.10, .11 and .12 acceptance. The conductor owns integration, Flow lifecycle and acceptance. The bounded 39-root source survey used the repository's research tier, `gpt-6-astra` at medium.

The final release needs additional executable gates. Existing Rust parity exercises useful parts of the contract, but its fixture SQLite cell, frontend-system-info cell and small durable scenario do not establish the mandatory SQLite durable recovery, unchanged workflow-type smoke or actual Temporal replication cells. ## One-hour execution design

Retain the current resource-aware scheduler and 3,600-second acceptance ceiling. Its 96 stages already overlap independent checks, enforce fixed per-workload chains and run busy/timing checks exclusively. The existing driver's optional `--deadline-s` must not permit a larger accepted .13 window. Wall time includes preamble and final checks, and host suspension still counts. Exit 3 after a complete overrun is failure, even if all subcommands passed.

The port needs a reviewed stage mapping, not a shorter stage set. Preserve all old gates/subgates through the tables above and the live map below, then include new Rust host/parity/regression and transferred ringpop/preservation requirements explicitly. Replace obsolete helper-process/Go producer commands with their release-linked counterparts and preserve original postchecks. Keep independent source checks separate from candidate execution.

- Freeze source and driver inputs once. Run the recorded driver copy with fresh evidence and native scratch, unchanged source checks before/after stages, exact input/role hashes and one result pair per measured fresh process. Finish all fixture and source staging before freeze or record strictly bounded allowed scratch as the current driver does.
- Keep one Cargo workspace/target and isolate feature outputs so a fixture build cannot replace the release binary. Build/admit the actual release once per cycle; reuse only authenticated immutable compilation caches/preparations that the source contracts permit. A cache hit never supplies guest-state reuse or another process's cold costs.
- Serialize heavy compilation and respect at most two resident guests within each measured workload cell. Admit simultaneous cells only under the existing conductor-approved budgeted-cell policy and actual host memory/core caps. Keep compiler <=6 GiB, single-guest cold <=6 GiB/warm <=4 GiB, cluster <=8 GiB, operator-only attributed phase <=2 GiB, preparation <=10 min, execution/replay <=15 min and nonzero per-store memory within its own limit. Preserve larger correctness-only inspection/ringpop watchdogs without relabeling them as cost budgets.
- Start heavy correctness paths by critical path. The existing Temporal inspection is the longest stage; the original 2026-10-19 observations estimate 46.4 min at 15 GiB cap, but worst retained durations estimate 60.4 min and add no allowance for newly mapped Rust work. These historical estimates are planning inputs only. Measure current durations during focused development, update scheduler estimates and simulate the complete mapped DAG before admitting the frozen cycle.
- Preserve success-before-canary ordering and shared-cache locks within each workload. SQLite selections depend on the authenticated primary, and the catalogue depends on all four. Runtime shards can overlap light static work while retaining the original 8 GiB memory guard. Pure Go oracle and source checks may overlap within safe resource limits.
- Keep busy12, terminal timing and any measured-cost preservation windows exclusive as their existing assertions require. Split independent inspection owner cases or other previously combined processes only when freshness, shared-state and original evidence assertions remain intact. Record all three owner subgates and never drop the onebox case.
- Before the final hour, complete local public Go/Rust parity and fault/golden regeneration acceptance on the same source revision. The final qualification executes release-owned cells alone. Do not repeat expensive equivalent guest executions under separate lane names when one authenticated execution genuinely satisfies both rows; maintain explicit one-to-many evidence references and preserve distinct fresh-process/repetition requirements.
- A simulated critical path over 3,600 s or unimplemented gate is a readiness failure. Improve orchestration, preparation or the real implementation under existing bounds before the window. No timeout increase, repetition reduction, unsupported/skip substitution, or external reuse of old qualification receipts can produce acceptance.
