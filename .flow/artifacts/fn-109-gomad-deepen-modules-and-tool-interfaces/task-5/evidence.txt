Design
- cli.go: `parseCampaignRequest(operation, arguments, stdout, stderr, dependencies)` holds the
  shared explore/plan grammar: flag definitions, presence-sensitive validation in the old order,
  working-directory resolution, installation resolution (task 4's application `install` seam)
  and CampaignSpec assembly. It returns a `campaignRequest{campaign, output, json, reporter}`.
  `runExploreWith` calls dependencies.explore (runner.Explore) and `runPlanWith` calls
  dependencies.plan (runner.CreateCampaignPlan). Each does only its own result reporting.
  `runPlanWith` keeps "gomad plan requires --output FILE" after installation resolution, as before.
- Plan's fixed failure policy: `flags.Set("on-failure", "all")` before Parse. This is the same as
  the old prepended `--on-failure=all` argument: an explicit --on-failure still overrides it, and
  the help default stays "first".
- The hidden `--__plan` flag is gone, so `gomad explore --__plan` and `gomad plan --__plan` fail
  with "flag provided but not defined: -__plan" (invalid_input, status 2, usage on stderr in text
  mode) before the installation is resolved.
- Semantic normalization: the CLI's own strategy reading (empty means seed, unknown is rejected)
  and coverage-mode reading (only the four names; empty rejected) were copies of Runner rules.
  They are now runner.ParseStrategy and runner.ParseCoverageMode. validateConfig also uses them
  (unknown-strategy default branch; coverage switch). The CLI calls them at the point where it
  used to apply its copies, so first-error precedence is unchanged. The CLI keeps flag-presence
  checks and their flag-named messages (resolveExploreStrategy bounds, resolveExploreSeeds,
  resolveExploreGuidance, --require-probe needs --coverage=semantic, resolveChoiceTrace,
  --coverage=choice needs --choices, --diagnostics needs seed, --output only with plan).
  Rules that already had one owner were left alone: on-failure, keep-successes and clock-tick are
  passed through raw and checked only by Runner. Probe names are checked by
  deterministicio.MissingRequiredSemanticProbes. Choice-trace bounds use runner's exported
  constants.

Intended grammar change (required by R6, "a hidden plan-only argument route fails acceptance")
- `-__plan  create a campaign plan` leaves the explore and plan help output (both goldens).
- `--__plan` on explore or plan was accepted and is now an unknown flag (status 2, not 3 or 0).
- Nothing else changes. Plan's usage header still reads "Usage of gomad explore:", as before.
