# Umpire Generator Command Migration Design

## Goal

Move the two remaining Umpire-owned Lean generators out of the repository-wide `cmd/tools`
namespace and into `tools/umpire/cmd` with names that match the existing Umpire command family.
The migration is a hard cutover with no compatibility wrappers:

- `cmd/tools/genleandynamicconfig` becomes
  `tools/umpire/cmd/umpire-gen-dynamic-config`.
- `cmd/tools/genleanmodeldescriptors` becomes
  `tools/umpire/cmd/umpire-gen-model-descriptors`.

The change preserves command behavior, generated bytes, flags, validation, failure handling,
fixtures, tests, and existing comments. It changes only command ownership, paths, and names.

## Command Boundaries

The generators remain separate `main` packages because they produce independent artifacts and
have different dependencies.

`umpire-gen-dynamic-config` discovers production dynamic-configuration registrations, initializes
the Go registry through its temporary helper, projects the catalog, renders the three generated
Lean modules, validates the candidate Lean output, and publishes the complete module set.

`umpire-gen-model-descriptors` discovers generated protobuf packages, selects registered files by
protobuf path prefix, exports a deterministic `FileDescriptorSet`, and atomically publishes the
requested descriptor file. The root Makefile continues to use that descriptor set as an input to
`umpire-gen-api`.

No shared orchestration package is introduced. The generators already share the generic
`tools/common/artifactio` publication module, while the descriptor generator also uses
`tools/common/protofile`. Their remaining workflows are unrelated and stay command-local.

The descriptor exporter does not merge into `umpire-gen-api`. Keeping descriptor acquisition
separate preserves the existing Make dependency boundary, allows the descriptor file to remain an
independent artifact, and keeps API rendering independent of Go package discovery.

## Migration

Move each complete package, including tests and test fixtures, to its new command directory. Keep
the moved Go files in `package main` and preserve existing comments.

Update the dynamic-config generator's command-local references:

- stderr and flag-set command names become `umpire-gen-dynamic-config`;
- its temporary helper directory and `go run` package path use the new command directory;
- temporary helper filenames use an underscore-safe form of the new command name; and
- tests and glob assertions use the relocated directory and helper filename.

Update the descriptor generator's command-local references:

- stderr and flag-set command names become `umpire-gen-model-descriptors`;
- temporary directory labels use the new command name;
- fixture import paths point at the relocated `testdata` packages; and
- command-usage tests expect the new binary and diagnostic names.

Update the root Makefile so `UMPIRE_GEN_DYNAMIC_CONFIG_COMMAND` invokes the relocated dynamic-config
command. Rename `GEN_LEAN_MODEL_DESCRIPTORS_COMMAND` to
`UMPIRE_GEN_MODEL_DESCRIPTORS_COMMAND` and point it at the relocated descriptor command. Existing
Make targets and generated artifact paths remain unchanged.

Update current documentation and runnable command examples to use the new paths and command names.
Older design documents may retain old names only when describing historical source locations; they
must not advertise an obsolete runnable command or current ownership boundary.

Delete both old command directories after all references have moved. Do not add forwarding
packages, deprecated aliases, symlinks, or compatibility Make variables.

## Data and Behavior Preservation

The dynamic-config command continues to accept only `--output-root` plus its private registry
helper argument. It still locates the module root, discovers production registration sites, runs
the helper with the `test_dep` tag, reconciles runtime registry metadata with discovery, renders
and validates the complete candidate, and publishes atomically.

The descriptor command retains its repeatable `--package-pattern` and `--file-prefix` flags and
required `--output` flag. Package selection, internal-package filtering, transitive descriptor
closure, deterministic ordering, serialization, and atomic publication remain unchanged.

Generated Lean files and the public descriptor set must be byte-identical before and after the
migration. The generated markers already use Umpire-facing names and require no compatibility
text.

## Errors and Failure Modes

All existing validation remains in place. Invalid flags, missing inputs, unsafe paths, discovery
failures, helper failures, malformed helper output, projection errors, candidate validation
failures, cleanup failures, and publication failures continue to return non-zero without partial
publication.

Diagnostics change only where they identify the executable or its temporary helper. The new names
must appear consistently so failures do not direct users to removed command paths.

Relocating the dynamic-config helper is the primary migration risk because it writes a temporary
Go file into its own package and recursively invokes that package. Both the helper directory and
the invoked Go package path must change together. Tests continue to prove helper cleanup on success
and failure.

## Testing and Verification

Run the original focused tests at their old paths before moving code, then run the same tests at:

```sh
go test -count=1 -tags test_dep ./tools/umpire/cmd/umpire-gen-dynamic-config
go test -count=1 -tags test_dep ./tools/umpire/cmd/umpire-gen-model-descriptors
```

Run the full Umpire Go scope and focused vet checks:

```sh
go test -count=1 -tags test_dep ./tools/umpire/...
go vet -tags disable_grpc_modules,test_dep \
  ./tools/umpire/cmd/umpire-gen-dynamic-config \
  ./tools/umpire/cmd/umpire-gen-model-descriptors
```

Invoke both relocated commands with Makefile-shaped arguments into temporary outputs and compare
their bytes with the checked-in generated artifacts. Run `make umpire-gen-dynamic-config` and the
relevant Umpire generation/check targets when feasible, then confirm that generation leaves no
unexpected working-tree changes.

Search the repository for obsolete runnable paths, package imports, diagnostic names, helper
filenames, and the removed Make variable. Run `git diff --check` and `make lint-code`; report any
unrelated repository-wide lint failure separately rather than changing out-of-scope code.

## Trade-offs

Two standalone commands create slightly more command surface than a multiplexer, but keep outputs,
dependencies, tests, and failure domains explicit. A single Umpire generator with subcommands would
add dispatch machinery without meaningful shared orchestration.

Keeping descriptor acquisition separate from API rendering retains one intermediate artifact and
Make dependency. That small cost avoids coupling `umpire-gen-api` to Go package discovery and
preserves independent descriptor generation and testing.

A hard cutover requires every in-repository reference to change in one patch, but avoids permanent
wrappers and duplicate names. The commands are repository-local tools, so no external compatibility
contract justifies a transition layer.
