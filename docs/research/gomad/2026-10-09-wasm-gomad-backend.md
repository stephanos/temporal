# Temporal WASM as a Gomad execution backend

Assessment date: 2026-10-09. This is source research and artifact inspection. No guest execution, startup, functional-test pass, performance result, or determinism qualification was produced.

Temporal's WASI artifact makes a credible second Gomad execution backend. Its strongest advantages are a finite host-import boundary, one guest execution thread, and fresh memory and package state per instance. Matching Gomad's schedule exploration, fault models, and replay evidence still needs guest runtime and network integration. Start with a stock-runtime repeatability experiment, then port the smallest proven Gomad runtime hooks if the experiment justifies it. Maintain one Gomad product and evidence system rather than a separate simulator.

## What stock WASI already changes

Go 1.27's [WASM runtime](https://github.com/golang/go/blob/go1.27.0/src/runtime/os_wasm.go) reports one CPU, cannot create an OS thread, and disables asynchronous preemption. Goroutines still run concurrently through the guest scheduler. A host function blocks that guest until it returns; the [Go WASI introduction](https://go.dev/blog/wasi) explains this limitation. This removes native races between multiple Ms returning from host syscalls, but a CPU loop can still starve every other guest goroutine.

The networking detail is particularly useful for Temporal. Go 1.27 selects [net_fake.go](https://github.com/golang/go/blob/go1.27.0/src/net/net_fake.go) for `wasip1`. Its socket registry, queues, connection establishment, and deadline timers live inside the guest. Ordinary `net.Listen` and `net.Dial` can connect code in the same instance. This is a test-oriented implementation, not connectivity to the host or other instances. It rejects some raw-control operations and has its own buffering semantics.

At the syscall layer, [Socket, Bind, Listen, and Connect return ENOSYS](https://github.com/golang/go/blob/go1.27.0/src/syscall/net_wasip1.go). Preview1 provides accept/shutdown operations for inherited sockets, but no standard socket creation/connect boundary. Consequently an external SDK client cannot simply dial the current guest's fake listener, and two guest instances cannot communicate through their separate fake socket registries. A WASIp2-capable host does not add Preview2 socket imports to this already compiled Preview1 module.

Inference from those sources: a server, SDK workload, and workers compiled into one WASI test binary are a better first functional experiment than running `temporal-server.wasm` beside a native client. The current CLI artifact can first establish instantiation, configuration loading, and startup behavior. Existing functional tests then provide the application/client pair in one address space without rewriting their bodies. Their compilation and execution remain unverified.

## Instruction determinism and runtime control

| Goal | Stock WASI opportunity | Additional contract needed |
| --- | --- | --- |
| Same-seed repeatability | A single execution thread and deterministic imports could repeat a fixed guest instruction path. | Qualify fresh instances under host load and compare application outcomes, I/O, runtime state, and terminal evidence. |
| Scheduler and select exploration | Seeding `random_get` affects runtime randomness, including randomized select polling. | Guest hooks must expose enabled goroutines/cases, stable logical IDs, forced prefixes, tape validation, and complete consumption. Stock Go's `randomizeScheduler` is tied to race builds. |
| Clock and timers | `clock_time_get` and `poll_oneoff` are host imports. | Declare one virtual clock, nonblocking-poll behavior, timer ties, cancellation, and runtime quiescence. A host clock that ticks on every read differs from Gomad's strict clock. |
| Maps and randomness | Go runtime startup entropy passes through WASI; map iteration uses runtime random state. | Record stream identities and draw ordering. Seeded entropy alone supplies neither runtime choices nor their diagnostics. Separate application entropy from scheduling in the qualified profile. |
| GC and allocation | Single-threaded execution removes several native timing channels. Guest time can also control elapsed-time inputs. | Qualify automatic GC, allocation pressure, pacing, cleanup/finalizers, and memory growth. Preserve the collector policy; do not infer deterministic GC from compilation. |
| Addresses and ASLR | Go heap pointers address guest linear memory, independent of the host mapping address. | Repeat guest allocation/layout and exclude host pointers from imports and ordering. Pointer-keyed maps still depend on allocation history. |
| Disk and network simulation | Host file imports are interceptable; internal fake networking can support same-instance traffic. | A versioned filesystem/durability model and a guest network hook or custom broker transport. Host imports do not observe fake-network packets. |
| Replay and oracles | Fresh instances can rerun immutable modules and captured inputs. | Bind backend, guest/runtime/engine identities, fault and choice tapes, observations, capacity limits, and first-divergence handling. |

Go's [runtime PRNG initialization](https://github.com/golang/go/blob/go1.27.0/src/runtime/rand.go) calls `readRandom`, which [WASI implements using random_get](https://github.com/golang/go/blob/go1.27.0/src/runtime/os_wasip1.go). Per-M generators and cheap random state derive from this initialization. [Map iteration](https://github.com/golang/go/blob/go1.27.0/src/internal/runtime/maps/table.go) draws its starting offsets from runtime randomness. This supports testing a stock guest with seeded host entropy; it does not establish that draw order stays stable through Temporal's entire runtime lifecycle. Explicitly seeded application PRNGs remain workload inputs.

[Wasmtime's determinism guidance](https://docs.wasmtime.dev/examples-deterministic-wasm-execution.html) requires deterministic imports and addresses observable NaN payloads, relaxed SIMD, and memory/table growth. For the experiment, pin engine options, canonicalize NaNs, disable unused nondeterministic proposals, and provide a reviewed memory-growth policy. Go's [WASM allocator](https://github.com/golang/go/blob/go1.27.0/src/runtime/mem_wasm.go) calls `memory.grow`; a growth failure caused by host memory pressure must remain an infrastructure/capacity outcome. A fixed numeric cap alone cannot promise successful allocation below that cap. Up-front backing allocation is one approach described by Wasmtime. Host ASLR does not itself randomize guest offsets.

The [Go collector](https://github.com/golang/go/blob/go1.27.0/src/runtime/mgcpacer.go) uses runtime time and worker-pacing state. A controlled host removes real-time input, but choosing an artificial clock also changes the collector's pacing inputs. The WASM experiment must compare enabled collector profiles explicitly. Disabling GC can help diagnose a channel within a bounded fixture; it cannot qualify long-running Temporal or substitute for the native collector contract.

## Host boundary and model design

The inspected import set supports a compact host-side inventory.

| Imports | Proposed responsibility |
| --- | --- |
| `args_*`, `environ_*`, `proc_exit` | Immutable argv/environment and typed terminal outcome. Supply captured configuration explicitly; never inherit the host environment wholesale. |
| `random_get` | Seeded, advancing entropy with stream/version identity and recorded request order. Reject malformed memory ranges and failures before writing guest bytes. |
| `clock_time_get`, `poll_oneoff`, `sched_yield` | Virtual wall/monotonic time, ordered readiness, and a declared yield policy. Interpret relative/absolute clock subscriptions correctly. |
| `fd_read`, `fd_write`, `fd_pread`, `fd_pwrite`, `fd_seek`, `fd_close`, `fd_sync`, `fd_fdstat_*` | Stable descriptor identities, bounded buffers, partial-I/O/error semantics, and transcript recording. Output capacity must not silently discard evidence. |
| `fd_filestat_*`, `fd_readdir`, `fd_prestat_*`, `path_*` | In-memory namespace, stable metadata and directory order, captured read-only inputs, writable virtual volumes, and rights checks. |
| `sock_accept`, `sock_shutdown` | Reject unless the execution profile explicitly supports a modeled inherited descriptor. These imports do not replace fake-network integration. |

Preview1's [pinned ABI specification](https://github.com/WebAssembly/WASI/blob/a2b96e81c0586125cc4dc79a5be0b78d9a059925/legacy/preview1/docs.md) owns argument layouts, descriptor rights, errno values, and poll subscriptions. The host should implement or explicitly deny each imported operation. Unsupported operations must fail closed rather than fall through to live files, DNS, sockets, clocks, or entropy. Preopening a real writable directory gives containment, but its metadata, ordering, durability and readiness still belong to the host OS.

The [Go WASI poller](https://github.com/golang/go/blob/go1.27.0/src/runtime/netpoll_wasip1.go) submits clock and descriptor subscriptions. A host can return deterministic readiness and advance to the next event for a blocking poll. It must return immediately for a zero-time poll without skipping runnable work. [WASI lock waits](https://github.com/golang/go/blob/go1.27.0/src/runtime/lock_wasip1.go) can instead loop over `sched_yield`, `Gosched`, and clock reads. Therefore a permanently frozen host clock can stall valid waits, while advancing every clock read lets runtime bookkeeping change logical time. Matching Gomad's strict time and coordinating multiple nodes needs an explicit guest idle/timer handshake, not a clock callback alone.

Use separately testable modules for the namespace/volume model, network broker, clock/event arbiter, and execution lifecycle. Reuse Gomad's [World ordering and transcript contracts](../../../tools/gomad3/ARCHITECTURE.md#world). Keep the translation of WASI layouts at the boundary. Synchronous file operations need no event scheduler until their semantics include delayed readiness or competing operations. Faults should match stable resource, operation and occurrence identities. Stream truncation is not a TCP packet-loss model; define connection reset, delay, partition/heal and backpressure separately.

Wasmtime can bind custom imports with its [Linker](https://docs.wasmtime.dev/api/wasmtime/struct.Linker.html) and provides a [Preview1 implementation](https://github.com/bytecodealliance/wasmtime/blob/774338bb9637dafb1d40a158c632a540859292e7/crates/wasi/src/p1.rs). Wazero offers Go embedding and explicit `WithWalltime`, `WithNanotime`, `WithNanosleep`, `WithOsyield`, and `WithRandSource` controls in its [inspected configuration API](https://github.com/wazero/wazero/blob/e234f6fe6ecd4589dd0c643b641bd38f6d826ee5/config.go). Its default fake clocks advance on reads; its default sleep returns immediately. Those defaults are not Gomad's clock model. A full fault-aware filesystem/poll contract needs custom boundary work beyond setting those callbacks. Neither host is currently a repository dependency; adopting one requires an explicit implementation decision.

## Scheduling, isolation, and persistence

Wasmtime's [fuel interruption](https://docs.wasmtime.dev/examples-interrupting-wasm.html) can trap or asynchronously yield at a deterministic execution point for the same guest path and engine profile. Epoch interruption is nondeterministic and is suitable for an external watchdog, not replay ordering. Fuel consumption measures engine-defined work, not elapsed application time or a portable instruction count. Pin its engine identity in replay evidence.

A fuel yield suspends the current guest continuation. Resuming it continues the same Go goroutine; the host cannot choose another Go goroutine from that suspension. Deterministic host round-robin or seeded fuel slices can explore order between multiple guest nodes, once a broker exists, but guest scheduler hooks are still necessary to explore alternatives within each node. In a single instance fuel provides a bounded-progress watchdog, not internal Go preemption. Compiler checkpoints would be a separate profile with their own overhead, source-fidelity and replay evidence.

| Cluster shape | Benefit | Boundary and limitation |
| --- | --- | --- |
| One instance with testcore/server/SDK/workers | Closest first step to existing one-box tests; same-guest fake TCP works without host socket creation. | Shared package globals and runtime. A node crash cannot reset only that node's arbitrary globals; guest network faults require hooks. |
| One fresh instance per node incarnation | Separate guest heap/package state and explicit instance disposal on crash. | Requires custom guest dial/listen integration, ordered host broker, clock arbitration, persistent volume attachment, stale-handle rejection, and fresh restart. Compilation alone supplies none of these. |

The host must serialize visible broker effects in modeled order; completion order from concurrently executing host futures cannot become scheduling input. Async host calls can allow another instance to run while one awaits a response, but they do not make another goroutine run inside the blocked instance. Fresh instantiation is preferable to arbitrary heap snapshots initially. Linear memory alone omits globals, tables, execution stacks, host handles and pending events; it is insufficient for complete restore or visited-state pruning. The [Gomad roadmap](../../../.plans/GOMAD_NEXT.md) likewise requires complete future-relevant state for pruning and preserves independent model/choice/execution identities.

[ncruces v0.35.6](https://github.com/ncruces/go-sqlite3/blob/v0.35.6/README.md) translates SQLite WASM into Go with wasm2go. The server guest does not contain a second WASM interpreter. Its translated SQLite code and memory still execute inside the outer guest. Keep FTS5, shared named `memdb`, timestamp compatibility, transaction cancellation, and visibility tests from the [compilation report](2026-10-09-wasi-compilation.md).

For disk-fault research, use a file-backed database on a virtual volume. The driver's `memdb` implementation can complete storage operations inside Go memory without calling outer WASI file imports. Host file interception cannot inject faults into those bypassed operations. The [driver VFS](https://github.com/ncruces/go-sqlite3/blob/v0.35.6/vfs/README.md) supports custom VFS implementations, and `sqlite3_dotlk` selects portable locks and in-process WAL memory sharing. Cross-instance WAL-index sharing needs its own design; do not share one dotlk WAL database between nodes merely because they can see the same host path.

The volume model must distinguish visible writes from durable writes, implement `fd_sync`, and define crash persistence before claiming crash-after-ack durability. Restarting a fresh guest against an unchanged real filesystem tests that filesystem's behavior, not a seeded disk-fault model. Inject short writes, I/O errors, sync failures, space exhaustion and reviewed torn-write candidates only through declared fault semantics. Validate them against SQLite recovery expectations and independent Temporal history/progress oracles.

## Reusing Gomad and configuring Temporal

Port the semantic runtime hooks for runnable/select choices, virtual timers, random-stream diagnostics and goroutine classification from the [runtime overlay](../../../tools/gomad3/toolchain/runtime/overlay/src/runtime/gomad.go). Preserve choice IDs, validation rules, generated codecs and canonical evidence where their meaning matches. WASI transport should use bounded guest buffers and host imports instead of native inherited descriptors and `mmap`. The overlay currently invokes `mmap`, native descriptor I/O and reserved-M machinery; it cannot be enabled unchanged for WASM. Its [toolchain descriptor](../../../tools/gomad3/toolchain/version/version.json) and boundary inventory qualify native source sets, so WASM needs its own source inventory, build identity and admission rules.

The compiler's existing typed standard-library interception machinery is a candidate for routing `net` calls to Gomad's model while preserving Temporal test source. It needs fingerprints for the WASI-selected definitions and new generated validation. Alternatively, an additive WASI-specific `net` implementation could call a narrow host broker through `go:wasmimport`. Both choices involve guest standard-library work. A separate runtime fork would duplicate the version-upgrade and diagnostic obligations without resolving these interfaces.

Reuse host-side artifact publication, campaign limits, fault/choice frontiers, minimization lineage, semantic probes, oracle collection and qualification reports where the schemas permit a backend-specific identity. Bind module bytes, Go/runtime profile, dependency/adapter versions, engine version/options, clock/entropy policies, import inventory, captured inputs, broker/volume semantics and limits. Reject incompatible native/WASM tapes before visible effects. Cross-backend comparison should use detached histories and normalized outcomes; each artifact initially replays on its recorded engine/platform profile.

Temporal configuration needs a source-bound support profile. [testcore](../../../tests/testcore/onebox.go) already uses static membership, and [Temporal wiring](../../../temporal/fx.go) accepts injected `StaticServiceHosts` through [WithStaticHosts](../../../temporal/server_option.go). The current server CLI does not expose that option as a YAML setting; static membership therefore needs the existing testcore path or an embedded harness. Use fixed loopback addresses within one guest. Supply schemas, dynamic configuration and other required files as captured inputs. Review Ringpop discovery, interrupt handling, SDK/FX shutdown, socket control/channelz, external archival, worker compute providers, authorization keys, and OTLP/StatsD export before startup. Existing `gomad` provider seams can inform dedicated WASI choices, but enabling that tag wholesale would change more than network or binary size.

Keep metrics enabled. The [Prometheus listener](../../../common/metrics/opentelemetry_provider.go) can serve an in-guest scraper through fake TCP; external scraping needs a broker/export boundary. Host CPU/process metrics are unsupported or outside deterministic outcome evidence. Record deterministic application probes separately from informational host wall time, compile time, fuel, and RSS. The [size report](2026-10-09-wasi-binary-size.md) explains why runtime YAML selections do not eliminate provider constructors from the linker graph.

The relevant precedent is Polar Signals' [2024 FrostDB study](https://www.polarsignals.com/blog/posts/2024/05/28/mostly-dst-in-go). Its pinned [runtime commit ea083ca](https://github.com/polarsignals/go/commit/ea083ca4892a62eb229c1886517e1cdb575ee19a) adds early environment loading, seeded runtime startup, always-on randomized run queues and WASI lock changes; its tests also use `faketime`. The authors report five data-loss/duplication bugs and occasional unreproduced executions. This supports a small-runtime prototype, not a full Temporal determinism claim or copying the older fork onto Go 1.27 unchanged.

## Evaluation and staged prototype

The native backend runs native machine code and already has its review, simulation, choice and evidence machinery. WASM adds engine validation/compilation, indirect calls, memory checks, host-call marshaling, and optional fuel overhead. Actual Temporal slowdown is unknown. The artifact's 227.04 MiB file and 96.125 MiB initial memory are different measurements; engine code/cache, guest heap/stacks, SQLite connection memory, and host model state add more. Memory32 has a 4 GiB address space, and [Wasmtime reservation settings](https://docs.wasmtime.dev/api/wasmtime/struct.Config.html) distinguish reserved virtual address space from committed memory. Ten concurrent nodes can multiply initial linear-memory and heap costs even when compiled engine code is shared.

WASM cannot establish native data-race or weak-memory coverage. Keep native tests and the [Go race detector](https://go.dev/doc/articles/race_detector), whose supported platforms exclude WASI. Retain unstripped module names for trace attribution; Go and engine stack views, debugger support and profile formats need qualification on this large module. Do not assume a native debugger or CPU profile maps directly onto guest goroutines.

| Measurement | Experiment and retained acceptance |
| --- | --- |
| Guest viability | Instantiate the exact current artifact, run its help path, then attempt SQLite startup with captured files and explicit bind addresses. Retain exits, import calls and the first unsupported boundary. Static-membership startup belongs to the subsequent testcore/harness gate. |
| Same-input replay | Run map/select/random/timer/GC fixtures and one-box smoke tests in fresh instances with a pinned host. Require identical canonical outcomes and model transcripts under bounded host load. |
| Choice diversity and replay | Reuse the native `select`, `timer_ties`, `runq_shuffle`, `maps`, and `automatic_gc` conformance shapes. Require alternate reachable outcomes plus exact tape replay and rejection of mutated/extra/missing decisions. |
| Fault fidelity | Compare virtual file/TCP sequences with the declared native models; test delay, cancellation, half-close, short write and sync failure, including negative/capacity cases. |
| Temporal coverage | Run workflow start/complete, activity retry/cancel, timers, visibility/FTS5, persistence cancellation and shutdown first. Record unsupported suites individually before extending to the full functional workload. |
| Cost and bug yield | Compare native, stock WASI, controlled-host WASI, and hooked WASI at equal wall/CPU budgets. Retain cold compile/start, warm start, peak memory, fuel cost, virtual/wall time ratio, trace bytes, distinct replayable failures and semantic outcomes. |
| Portability and crash isolation | Repeat qualified fixtures on supported host architectures and engines separately. Exercise dispose/reinstantiate, stale broker handles and declared durable state before making cross-host or node-crash claims. |

1. Inspect and execute the present artifact with one pinned host and explicit resource bounds. Capture argv, environment, filesystem inputs, import inventory and engine identity. Keep this startup gate separate from determinism. A native client reaching a fake guest listener is not an acceptance criterion.
2. Build a small stock-Go WASI fixture containing two ready select cases, maps, timers and random reads, plus an in-guest loopback exchange. One select branch emits a named intentional invariant failure. Find and retain that seed, replay it in 100 fresh instances under host load, and reject a modified captured input before execution. This first failure tests evidence and repeatability; it establishes no general runtime guarantee and supplies no forced goroutine replay. Also run the already compiled SQLite guest tests for FTS5/schema, shared memory and transaction cancellation.
3. Compile the unchanged functional-test package with `test_dep,sqlite3_dotlk` and run the smoke selection through `testcore` in one guest. Start with deterministic host entropy and an explicit coherent clock policy. Retain every mismatch, including runtime/GC diagnostics if available. Progress to Gomad hooks only after source evidence identifies an exploration requirement or a repeatability gap. Measure 32 seeds with 100 fresh repetitions per fixture; these are proposed acceptance budgets, not observed results or a statistical bound.
4. Port the choice/timer/diagnostic hooks and transport, add a qualified guest network boundary, and verify the canary's alternate branch through a forced choice prefix. Require exact tape consumption and matching outcome/I/O evidence. Add one file-backed SQLite fault canary at a stable `fd_pwrite` or `fd_sync` occurrence and replay its named result. Then test a Temporal retry/recovery oracle with the same fault, retaining actual failure evidence if an invariant breaks.
5. Add separate-node instances only for a workload requiring partition/heal or fresh node restart. Start with two communicating service fixtures, an explicit broker, one globally ordered virtual clock and separate virtual volumes. Qualify crash cleanup and SQLite recovery before multi-node Temporal. Publish measured support/cost comparisons before considering backend replacement.

The recommendation is to fund the one-instance viability and repeatability gates first. Continue only if WASM unlocks a named Temporal workload, removes a demonstrated native nondeterminism channel, or improves replayable bug yield per compute-hour. Keep the native backend and its deferred qualification owners intact. This report supplies research for a future WASM scope; it changes no task status, runtime code, CI policy or qualification claim.
