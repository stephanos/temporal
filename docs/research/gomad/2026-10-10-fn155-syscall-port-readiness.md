### Back the descriptors with the current model

The standalone model already owns listener ports, client ports, connection state, queued accepts, half-close, EOF, per-direction deadlines, and bounded chunks. Its limits are 64 pending connections, 64 pending chunks, and 64 KiB per chunk. `Listener`/`Conn` already dispatch to standalone, simulation, and process implementations. Keep those ownership boundaries so .4 can connect descriptors to the existing incarnation and coordinator semantics. [network.go](../../../tools/gomad3/toolchain/runtime/overlay/src/internal/gomadio/network.go), [simulation handles](../../../tools/gomad3/toolchain/runtime/overlay/src/internal/gomadio/simulation_handles.go), [process network](../../../tools/gomad3/toolchain/runtime/overlay/src/internal/gomadio/process_network.go)

The required extraction is a nonblocking operation that returns a modeled result or would-block, followed by notification of state transitions. `standaloneListener.Accept`, `standaloneConn.Read`, `standaloneConn.Write`, and `DialTCP` currently loop and wait on `changed` channels. Their state mutations are usable, but calling these blocking methods from the syscall edge defeats `internal/poll` readiness ownership. In particular, full listener queues need a defined nonblocking connect outcome and a later wakeup; full write queues need partial writes/EAGAIN and a write wakeup when reads free capacity. Close and half-close must wake the affected directions in stable order.

Extract shared state transitions so legacy blocking operations retain their existing lock order, checks, record count, error precedence, and queue bounds. The descriptor backend should avoid emitting duplicate `net.*` records when .3 installs descriptor events. `connShared.signal` and `standaloneListener.signal` currently close and replace their channels while holding model locks. A new readiness callback must have an explicit lock/lifetime contract; it must not reenter the model or run arbitrary application callbacks. No per-socket goroutine or second byte queue is required by the current model.

The current standalone model supports `tcp`/`tcp4` at loopback and maps wildcard listen to `127.0.0.1`. The spike's `10.77.0.x` and IPv6 behavior is broader. Preserve current standalone address scope, adapt the .3 demo to loopback, and leave multi-node addresses to .4. Upstream `net` probes IPv4/IPv6 socket support when selecting an address family, so test that probe under the selected boundary and refuse unsupported families without a host socket. [Go `net/ipsock_posix.go`](/home/agent/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.27.1.linux-arm64/src/net/ipsock_posix.go), [task .4](../../../.flow/tasks/fn-155-gomad-syscall-level-io-boundary-from.4.md)

### Readiness and moving stacks are acceptance gates

The spike calls `netpollready`, adjusts global waiters, and uses `injectglist`. Its virtual waits still increment the same counter as host waits. Gomad's `gomadCheckDeadTime` refuses standalone clock advancement while `netpollAnyWaiters()` is true; a blocked virtual accept therefore prevents its own deadline from firing. Gomad also explicitly treats host netpoll batch admission as host timing. [spike runtime hook](/Users/stephan/Workspace/skunkworks/gomad-syscall-spike.wt/tools/gomad3/spikes/syscallboundary/goroot/src/runtime/vkernel.go), [Gomad runtime](../../../tools/gomad3/toolchain/runtime/overlay/src/runtime/gomad.go)

A minimal candidate retains native `pollDesc` and its deadline implementation. On virtual readiness, call the equivalent of `netpollunblock(..., ioready=true)` and `netpollgoready` in a fixed read/write order from the goroutine causing the transition. In `netpollblock`, select a virtual park-commit function that performs the existing semaphore CAS without incrementing host waiters. In `netpollunblock`, omit the matching decrement for virtual descriptors. This covers readiness, `poll_runtime_pollUnblock`, `poll_runtime_pollSetDeadline`, and `netpolldeadlineimpl` uniformly while preserving `netpollAnyWaiters` as the host count. Verify the descriptor registration cannot race close/reuse and deliver to a recycled `pollDesc`. This is a source-grounded design candidate, not executed proof. [Go netpoll implementation](/home/agent/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.27.1.linux-arm64/src/runtime/netpoll.go)

Generic pointer safety remains a separate implementation gate. Go explicitly documents that `uintptrkeepalive` does not make stack copying adjust uintptr arguments, hence its syscall bridges are `nosplit`. The spike calls a splittable `vkGenericSlow` with those raw values. Moving that whole call onto g0 is not a valid shortcut: existing backend methods use ordinary mutexes, channels, heap copies, transcript locking, and potentially blocking waits, while the system stack is fixed-size, non-preemptible, and unscanned. A bounded staging or typed-pointer bridge needs an explicit proof of when every buffer, length pointer, sockaddr, and nested iovec pointer becomes safe before any stack growth, and when output is copied back. The dedicated design investigation owns that choice. Do not declare this resolved from ordinary TCP or heap-buffer tests. [Go syscall pointer contract](/home/agent/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.27.1.linux-arm64/src/syscall/syscall_linux.go), [runtime stack contract](/home/agent/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.27.1.linux-arm64/src/runtime/HACKING.md)
