# Go WASM scheduling and compiler emission for Gomad

Assessment date: 2026-10-09. Gomad developers can obtain controlled goroutine choices with a WASM runtime patch before changing compiler emission. Compiler checkpoints become useful when the supported profile must switch goroutines inside long computations that otherwise never yield. The engine, runtime controller, host models and checkpoint policy must jointly define the replay contract.

This report contains source analysis and one compile-only probe. It establishes no guest execution, Temporal startup, same-seed replay, performance result, native qualification or general determinism bound. Recommendations and predicted outcomes below are proposed experiments.

## Direct answers

| Question | Finding |
| --- | --- |
| Is the WASM scheduler deterministic? | WebAssembly supplies instruction semantics. Go implements its own goroutine scheduler inside the module. Stock Go WASI exposes random and clock imports and makes runtime decisions from their results. Ordinary hosts therefore supply no same-seed scheduler guarantee. A fully controlled host and pinned single-threaded module can plausibly repeat its fixed path; that remains a qualification hypothesis for Temporal. |
| Can changing Go's emitted WASM make scheduling deterministic? | A compiler can emit resumable checkpoints whose deterministic runtime controller chooses the next enabled goroutine. This adds controllable suspension sites. The controller still needs controlled entropy, time, readiness, maps, collector behavior and replay validation. |
| Are compiler changes necessary? | Existing blocking/yield points support a runtime-only cooperative profile, including seeded runnable/select choices and forced replay. A call-free loop cannot acquire a new Go scheduling point through a runtime patch that it never calls. Covering such loops requires existing experimental checks, additional emitted checks, source instrumentation or another resumability-aware transformation. |
| Would canonical code or optimizer flags solve the problem? | Reproducible module bytes fix code identity. They do not fix host inputs, runtime state, GC decisions or enabled goroutines. Optimization changes can also move/eliminate calls and alter allocation and checkpoint frequency. |
| Does engine fuel switch Go goroutines? | Engine fuel can interrupt or suspend the current WASM continuation. Resuming that continuation continues its current Go goroutine until Go itself switches. Fuel becomes a guest scheduler only when an additional guest-aware protocol enters a valid Go scheduling point. |

These answers follow the owners identified below. Go's language specification permits unspecified map iteration and random selection among multiple ready select cases. A supported deterministic testing implementation must supply its own qualified policy for those freedoms. [Go specification](https://go.dev/ref/spec#Select_statements), [map range rules](https://go.dev/ref/spec#For_range).

## Three different claims

**Instruction determinism** says equal machine state and equal imported responses produce equal subsequent execution under the declared engine profile. Wasmtime documents remaining hazards from NaN payloads, relaxed SIMD, memory/table growth and imports. A host must remove live clock, entropy, filesystem and readiness inputs. A numeric memory cap alone cannot guarantee successful growth below the cap when host resources differ. [Wasmtime deterministic execution](https://docs.wasmtime.dev/examples-deterministic-wasm-execution.html).

**Same-seed repeatability** says a fresh execution of a particular target/profile produces equal retained evidence for the same seed and captured inputs. Repeating a fixture establishes that observed result for its retained repetitions. Extending that claim requires a source inventory plus a qualification corpus covering the declared support boundary, including failures and resource behavior. The [Gomad runtime contract](../../../tools/gomad3/SPEC.md#runtimescheduling-scheduling) fixes target, toolchain, platform, inputs and seed; it also explicitly excludes fairness for CPU loops that never yield.

**Controlled exploration** lets Gomad enumerate enabled alternatives, select another rank, force a retained prefix and detect divergence. One perfectly repeatable FIFO schedule supplies limited interleaving coverage. Changing only startup randomness can explore select/map outcomes while leaving most runnable dispatches unchanged. Gomad's [choice contract](../../../tools/gomad3/SPEC.md#runtimechoices-choice-evidence) requires stable decisions and full tape validation in addition to repeating a seed.

## Actual scheduler and nondeterminism paths

Stock WASM reports one CPU, cannot create OS threads and disables asynchronous preemption. `haveSysmon` is false. `runqput` disables `runnext` without sysmon, preventing a ping-pong pair from monopolizing that shared time slice. `runqget` takes the local queue head; randomized enqueue/batch behavior is conditional on `raceenabled`. `findRunnable` considers timers, GC workers, the global queue's periodic fairness check and local/global work. Blocking channels, synchronization, explicit `Gosched`, assists and runtime transitions can transfer control; ordinary function calls are only potential synchronous preemption points when a request is armed. A call-free CPU loop can starve the guest. These are source-derived properties of this port, rather than a claim that every dispatch is randomized or that single-threaded execution serializes away concurrency. [Go WASM OS runtime](https://github.com/golang/go/blob/go1.27.1/src/runtime/os_wasm.go), [scheduler](https://github.com/golang/go/blob/go1.27.1/src/runtime/proc.go), [synchronous preemption](https://github.com/golang/go/blob/go1.27.1/src/runtime/preempt.go).

| Input or runtime path | Owner and implication |
| --- | --- |
| Startup randomness | `runtime.randinit` calls `readRandom` when startup entropy is absent. WASI routes it through `random_get`. A failed or all-zero read falls back to `nanotime`; a deterministic host must make the failure policy explicit. Per-M ChaCha and cheap random state derive from bootstrap randomness. [rand.go](https://github.com/golang/go/blob/go1.27.1/src/runtime/rand.go), [os_wasip1.go](https://github.com/golang/go/blob/go1.27.1/src/runtime/os_wasip1.go). |
| Ready selects | `selectgo` shuffles its poll order through `cheaprandn`; channel lock order uses channel addresses. Same entropy can repeat a path only while creation/allocation and draw order also repeat. Forced replay needs the actual enabled alternatives and stable select/case identities. [select.go](https://github.com/golang/go/blob/go1.27.1/src/runtime/select.go). |
| Maps | Creation and resets use runtime random hash seeds; iteration initializes random directory/entry offsets. Pointer keys also couple results to allocation history. Canonicalizing emitted bytes supplies neither a fixed seed nor fixed allocation history. [map.go](https://github.com/golang/go/blob/go1.27.1/src/internal/runtime/maps/map.go), [table.go](https://github.com/golang/go/blob/go1.27.1/src/internal/runtime/maps/table.go). |
| Clocks and readiness | WASI `clock_time_get` feeds runtime time; `poll_oneoff` returns events whose order feeds ready lists. Capture/model event readiness and ordering, including zero-time polls. Host completion races cannot become implicit choices. [os_wasip1.go](https://github.com/golang/go/blob/go1.27.1/src/runtime/os_wasip1.go), [netpoll_wasip1.go](https://github.com/golang/go/blob/go1.27.1/src/runtime/netpoll_wasip1.go). |
| Timer ties | The stock timer comparator uses a per-timer random value at equal deadlines only for fake-time timers. Controlling an outer host clock does not itself activate all fake-time semantics. Port stable timer identities and the admitted tie policy separately. [time.go](https://github.com/golang/go/blob/go1.27.1/src/runtime/time.go). |
| WASI notification waits | `notetsleepg` computes a deadline, calls imported `sched_yield`, invokes Go `Gosched` and reads `nanotime` in a loop. A frozen clock can leave this timed wait runnable forever. Idle-only time advancement therefore needs a wait-path adaptation rather than assuming every wait parks. `beforeIdle` is currently a stub. [lock_wasip1.go](https://github.com/golang/go/blob/go1.27.1/src/runtime/lock_wasip1.go). |
| GC, scavenging and callbacks | GC pacing and fractional-worker selection consume elapsed time; scavenging uses measured work/sleep ratios. Allocation triggers, assists, weak references, finalizers and cleanup callbacks can affect future allocation and runnable work. Single-threaded execution removes parallel races but still requires a declared clock/collector profile and coverage of these channels. [mgcpacer.go](https://github.com/golang/go/blob/go1.27.1/src/runtime/mgcpacer.go), [mgc.go](https://github.com/golang/go/blob/go1.27.1/src/runtime/mgc.go), [mgcscavenge.go](https://github.com/golang/go/blob/go1.27.1/src/runtime/mgcscavenge.go). |

For the first controlled-host experiment, a versioned advancing `random_get` stream can establish startup repeatability. The qualified hooked profile should keep application entropy separate from runtime choices. One generic host import does not identify whether a call comes from runtime startup or `crypto/rand`, so split their guest interfaces or define a reviewed request classification. Preserve the [draw inventory](../../../tools/gomad3/toolchain/draw_inventory_test.go) and [stream contract](../../../tools/gomad3/SPEC.md#runtimestreams-seeded-stream-isolation).

Strict time should leave application wall/monotonic reads observational and advance only after application work cannot proceed. Checkpoints can improve goroutine fairness while an infinite computation remains runnable. They do not establish quiescence or permit delivery of a future timer under that policy. Advancing application time from instruction counts, fuel or CPU-work budgets would define a different declared profile. If collector bookkeeping requires deterministic work time, its policy needs a separately specified clock channel or a demonstrated compatible shared policy. A clock that advances on each read can repeat, but couples scheduling to incidental bookkeeping and differs from Gomad strict time. Disabling GC can isolate a channel in a bounded experiment; it cannot qualify Temporal. Collector-file changes remain subject to the existing patch policy.

## Emission owners and resumability

Go's WASM backend stores Go stacks in linear memory and uses a synthetic PC containing a function identity and block identity. Calls can unwind the WASM call stack with a returned flag; the runtime dispatcher then resumes the saved Go frame. Compiler-managed call sites supply stack arguments, spill/reload state and a resume address. A host suspension preserves the engine continuation, which is a different mechanism from unwinding Go frames to dispatch another goroutine. [Compiler ABI explanation](https://github.com/golang/go/blob/go1.27.1/src/cmd/compile/internal/wasm/ssa.go), [Go switching assembly and dispatcher](https://github.com/golang/go/blob/go1.27.1/src/runtime/asm_wasm.s), [WASI entry](https://github.com/golang/go/blob/go1.27.1/src/runtime/rt0_wasip1_wasm.s).

| Layer | Existing owner | Available intervention |
| --- | --- | --- |
| Generic SSA | `cmd/compile/internal/ssa/compile.go` and `loopreschedchecks.go` | Insert a normal runtime call on admitted backedges before lowering/liveness/register allocation. Existing experimental checks provide a starting point for CFG/memory-phi repair. |
| WASM SSA lowering/emission | `cmd/compile/internal/ssa/_gen/Wasm.rules`, `cmd/compile/internal/wasm/ssa.go` | Lower normal calls through Go's resumable ABI; use source positions and inlining metadata. Blindly adding a raw call after register allocation loses compiler knowledge of live state. |
| WASM object preprocessing | `cmd/internal/obj/wasm/wasmobj.go` | Expand `obj.ACALL` into saved resume addresses and unwind checks, construct resume tables, expand stack checks and import wrappers. This owner has instruction/ABI information but less high-level safety context. |
| WASM linker | `cmd/link/internal/wasm/asm.go` | Assign synthetic function PCs, resolve relocations and write code, table, import, export and name sections. Retain a site manifest/custom section here; choosing semantic checkpoints here would require new metadata. |
| Guest runtime | `runtime/proc.go`, `select.go`, `time.go`, `rand.go`, WASI lock/poll owners | Choose enabled goroutines/cases, arm/consume requests, defer unsafe yields, own time transitions and expose bounded records. |

The [SSA pass list](https://github.com/golang/go/blob/go1.27.1/src/cmd/compile/internal/ssa/compile.go), [WASM lowering rules](https://github.com/golang/go/blob/go1.27.1/src/cmd/compile/internal/ssa/_gen/Wasm.rules), [object preprocessing](https://github.com/golang/go/blob/go1.27.1/src/cmd/internal/obj/wasm/wasmobj.go) and [linker](https://github.com/golang/go/blob/go1.27.1/src/cmd/link/internal/wasm/asm.go) own these seams.

Two real existing switches need separate treatment.

- `GOEXPERIMENT=preemptibleloops` enables `insertLoopReschedChecks`. It skips `NoSplit` functions and inserts a stackguard test plus `runtime.goschedguarded` on loop backedges. The check reacts to a poisoned guard. WASM has no sysmon to periodically arm it. Enabling the experiment alone supplies no deterministic quantum or choice policy. [loopreschedchecks.go](https://github.com/golang/go/blob/go1.27.1/src/cmd/compile/internal/ssa/loopreschedchecks.go).
- The compiler's `-d=maymorestack=<symbol>` debug mechanism can insert a function-entry hook. WASM object preprocessing explicitly uses `CALLNORESUME` because that hook lacks complete stack information and must not preempt. It can investigate counting/request generation, subject to its restrictions; calling `Gosched` directly there is unsafe. The hook also misses call-free loops. [wasmobj.go](https://github.com/golang/go/blob/go1.27.1/src/cmd/internal/obj/wasm/wasmobj.go).

An experimental controller might reuse `preemptibleloops` without adding compiler source changes, provided it demonstrates a safe deterministic request-arming mechanism. Poisoning the stackguard at every dispatch is not an established solution. Entry checks and `morestack` also consume that guard, and restart/reset behavior can remove the loop request or produce repeated entry handling. Qualify that interaction before adopting it. An explicit budget check at an ordinary SSA call site has a clearer ownership path when loop progress is required. [stack growth/preemption handling](https://github.com/golang/go/blob/go1.27.1/src/runtime/stack.go), [WASM morestack](https://github.com/golang/go/blob/go1.27.1/src/runtime/asm_wasm.s).

## Comparing the intervention choices

| Approach | What it can provide | Coverage, safety and cost |
| --- | --- | --- |
| Minimal runtime hooks | Seed/tape-controlled local runnable and select choices at existing scheduling points, stable timer policy, diagnostics and idle handshake. | Uses compiler-generated resumable calls already present. No checks inside call-free loops. Cost follows actual choice points and bounded transport; unmeasured. This is the first recommended profile. |
| Compiler-emitted checkpoints | Deterministic work budgets and additional goroutine interleavings at admitted function entries/backedges. | Normal SSA calls preserve stack maps, spill state and resume metadata. Each executed check adds budget/branch work; slow paths add scheduling and records. Apply an explicit package/site policy and measure emitted size and hot-loop cost. |
| Post-link instrumentation | Module validation, import auditing, counters or engine-level interruption without rebuilding Go. | A raw imported call can observe/pause the engine, but a Go context switch requires spill/root information, synthetic PCs, resume tables and unwind propagation. Rewriting arbitrary instructions into valid Go suspension sites requires Go-specific continuation conversion and metadata repair. It also needs original-to-transformed debug mapping and distinct artifact identity. This is a larger research branch. |
| Fuel scheduling | Repeatable bounds and resumable host scheduling between independent guest instances under an explicit controller. | Engine async yielding preserves the current continuation. A trap ends it. Fuel work units depend on engine configuration/version and do not equal logical time. Guest goroutine switching requires additional safe-point coordination. Use epochs/wall watchdogs only for infrastructure termination. |

The fuel distinction is grounded in [Wasmtime interruption semantics](https://docs.wasmtime.dev/examples-interrupting-wasm.html), [Store fuel yield API](https://docs.wasmtime.dev/api/wasmtime/struct.Store.html#method.fuel_async_yield_interval) and the [pinned Store source](https://github.com/bytecodealliance/wasmtime/blob/774338bb9637dafb1d40a158c632a540859292e7/crates/wasmtime/src/runtime/store.rs). A host must not re-enter the suspended guest's Go runtime or mutate private goroutine structures to select another stack. A proposed request-bit protocol would ask a guest checkpoint to perform the switch after resumption; it still needs emission coverage and deterministic request identity. Stock engine fuel alone supplies none of that protocol.

### Safety requirements for checkpoints

The proposed checkpoint slow path must verify that it runs on an admitted user goroutine, with an attached running P, before entering the scheduler. It must skip g0/system-stack execution, startup, foreign/import wrapper transitions, runtime critical sections, allocation internals and `preemptoff` intervals. Go's `canPreemptM` checks locks, allocation, preemption inhibition and processor/goroutine state, but callers still need a safe stack and valid P before invoking it. Runtime locks on WASI assume no competing execution while held and throw on self-deadlock. A blind yield can violate that assumption. [preempt.go](https://github.com/golang/go/blob/go1.27.1/src/runtime/preempt.go), [WASI lock implementation](https://github.com/golang/go/blob/go1.27.1/src/runtime/lock_wasip1.go).

Insert normal calls while the compiler still owns memory effects and liveness. Preserve roots through stack movement, GC scan and the WASM unwind/resume path. Do not insert calls inside a write-barrier sequence, an unsafe region or a function whose `nosplit`/`nowritebarrierrec` contract excludes the new call. Package-level runtime exclusions alone are insufficient for compiler-generated barriers in user code. Preserve existing unsafe-point annotations and barrier lowering. [Write-barrier pass](https://github.com/golang/go/blob/go1.27.1/src/cmd/compile/internal/ssa/writebarrier.go), [liveness](https://github.com/golang/go/blob/go1.27.1/src/cmd/compile/internal/liveness/plive.go), [runtime HACKING.md](https://github.com/golang/go/blob/go1.27.1/src/runtime/HACKING.md).

A deterministic budget should count declared executed checkpoints or weighted blocks, rather than host nanoseconds. Exhaustion sets a pending request; an unsafe site defers it until a permitted site. Record the realized suspension site and skipped/deferred policy so replay cannot assume the requested and realized sites coincide. Prefer a cheap non-allocating guard and bounded buffers. These are design requirements, not a tested implementation.

Backedge checks cover loops in admitted compiled functions. Entry checks cover recursion and call-heavy work. Inline bodies need the resulting CFG's checks. Assembly, excluded runtime functions, long bulk instructions, synchronous host imports and uninstrumented dependencies retain gaps. A loop bound in checkpoint units gives no wall-time bound for a single long import or bulk operation. Fuel and a host watchdog still protect non-progress in those regions. Initial scope should keep unsafe/runtime regions excluded and report their coverage gaps explicitly.

## Site identity and tape compatibility

The native [gomadChoiceSite](../../../tools/gomad3/toolchain/runtime/overlay/src/runtime/gomad.go) maps a caller PC through `firstmoduledata.textOff`. WASM uses synthetic function/block PCs; the port must validate that mapping rather than treating a WASM byte offset as a native text address. A manifest should bind each emitted checkpoint's normalized package/function, inlined source position, site kind and per-function ordinal to its synthetic PC and transformed module location. Source line alone collides when several checkpoints share a line. IDs need only be stable within a frozen build/profile; cross-build stability would be a separate contract.

Keep unstripped names and a source mapping artifact. If a transformer changes code offsets or function indices, retain both original and final module digests plus its mapping. Bind compiler version, optimization/experiment settings, dependency closure, checkpoint selector version, budgets and engine profile into target/controller identity. Changing emitted sites changes scheduling opportunities, synthetic PCs, allocation effects and draw order. Old tapes must fail identity validation before execution. [WASM linker address/name ownership](https://github.com/golang/go/blob/go1.27.1/src/cmd/link/internal/wasm/asm.go), [choice execution identity](../../../tools/gomad3/choice/tape.go).

Reuse `CanonicalDecision`, `ProjectReplayPlan`, `ValidateReplayPlan` and `BuildForcedRankPrefix` where decision meanings match. A checkpoint can deterministically trigger an existing Runnable decision once multiple admitted goroutines are queued. Making yield/continue itself an explored choice changes the choice vocabulary and requires a versioned schema/controller decision. Do not pretend fuel exhaustion is a ready-select or runnable-rank record. Exact replay must verify kind, site, ordinal, alternatives, selected identity/rank and complete consumption, and reject changed/missing/extra decisions. Use separate bounded diagnostics for allocation count, GC phase/cycle, time and draw counters. [choice tape](../../../tools/gomad3/choice/tape.go), [diagnostics](../../../tools/gomad3/choice/diagnostic.go), [runtime decision owner](../../../tools/gomad3/toolchain/runtime/overlay/src/runtime/gomad.go).

Preserve Gomad's current local-queue policy. A runtime-owned head runs without a user choice; a user head chooses among queued users; every dispatch advances the head. Finalizer/cleanup classification changes while running user callbacks. Global queues, collector workers selected outside the local queue and timer delivery retain their owned rules. Checkpoints must respect those distinctions rather than randomly choosing any known goroutine. [Scheduling contract](../../../tools/gomad3/SPEC.md#runtimescheduling-scheduling), [gomadChoiceRunqIndex](../../../tools/gomad3/toolchain/runtime/overlay/src/runtime/gomad.go).

## Minimal recommended patch set

1. **Controlled-host stock profile.** Capture inputs and provide deterministic entropy, clock/poll ordering, files and capacity outcomes. Pin module/engine identity and qualify startup plus bounded repeated fixtures. Use fuel for progress bounds. Advertise empirical seed repeatability only after retaining results.
2. **Cooperative runtime profile.** Add WASM-specific activation, stable goroutine/timer identities, seeded runnable/select policy, separate runtime/application entropy, tie ordering and non-allocating diagnostics. Adapt WASI notification waits and add a true idle/deadline handshake. Replace native descriptor/mmap transport with bounded versioned imports. Reuse host evidence/frontier owners and preserve native bytes. Compile the patch with the stock compiler.
3. **Optional checkpoint profile.** First test whether existing `preemptibleloops` plus a narrowly specified runtime request mechanism can meet the coverage requirement. If it cannot, add one opt-in SSA checkpoint pass emitting normal runtime calls on selected backedges and entries, a runtime budget/deferral hook, and a site manifest. Do not begin with linker-only coroutine rewriting or whole-runtime instrumentation.

No collector modification belongs in the initial patch set. Keep automatic GC enabled for admitted workloads and make GC/time repeatability an explicit gate. Start the hooked comparison with the native contract's `GOEXPERIMENT=nogreenteagc` profile, identity-bound separately from the stock build. Finalizers are outside the current native contract; callback/weak-reference fixtures investigate new WASM support rather than inheriting a native pass. A demonstrated collector-owned mismatch requires a policy decision under the existing restrictions. The native overlay's reserved-M and native transport machinery cannot be copied unchanged into WASM. [Native patch](../../../tools/gomad3/toolchain/runtime/go1.27.1.patch), [runtime overlay](../../../tools/gomad3/toolchain/runtime/overlay/src/runtime/gomad.go), [draw inventory](../../../tools/gomad3/toolchain/draw_inventory_test.go), [runtime contract](../../../tools/gomad3/README.md#contract).

## Plan implications

The [execution plan](../../../.turbo/plans/wasm-gomad-execution-backend.md) can keep its viability and evidence-first order. Phase 0 should use the corrected main-based candidate and freeze compiler/runtime/engine identities. Phase 1 must declare entropy and clock policies; timer-read behavior is part of semantics.
