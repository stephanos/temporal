# Gomad WASM

The execution host and engine live in the single [Rust workspace](../../../rust/README.md).
This directory retains the cooperative Go runtime overlay, guest fixtures,
determinism inventory and Go cluster conformance oracles. The Go CLI, Runner,
provider and measurement producers have been removed from the prospective
retirement candidate. Frozen Go executables and source remain external reference
inputs until final qualification passes.

| Path relative to `tools/gomad` | Owner |
| --- | --- |
| `rust/gomad/` | Preparation, campaigns, artifacts, inspection, replay and qualification |
| `rust/wasmhost/` | Linked Wasmtime engine, scheduling and modeled WASI operations |
| `internal/model/` | Retained Go models, reference corpora, schemas and protocol generator |
| `internal/backends/wasm/toolchain/` | Go 1.27.1 cooperative runtime overlay |
| `internal/backends/wasm/cluster/` | Go World, clock and network conformance checks |
| `internal/backends/wasm/determinism/` | Reviewed inventory and append-only identity/review history |
| `internal/backends/wasm/testdata/` | Go guest fixtures |

Guest files use captured immutable bytes and an in-memory namespace. Network,
clock, volume and entropy operations use explicit models. A linked execution
creates fresh engine, store and guest state. The Rust helper's public linked
interfaces and retained-record contracts are documented in the
[Rust host guide](../../../rust/README.md); its standalone framed transport is
specified in [the helper protocol](../../../rust/wasmhost/protocol.md).

Forced replay admits retained raw Choice Trace bytes and their expected digests
through the helper's preflight validator. It does not accept a host-projected
decision tape. Inspection and replay authenticate Rust-lineage artifacts and
refuse historical Go-lineage manifests. The public command contracts are in
[the maintainer CLI guide](../../../CLI.md).

The workspace pins Rust 1.99.1 and Wasmtime 47.0.3, with one `Cargo.lock`,
`rust-toolchain.toml` and shared `rust/target` directory (or explicit
`CARGO_TARGET_DIR`). Only `gomad` is a default member. The standalone
`gomad-wasmhost` binary requires `reference-helper`; it exists for oracle
fixtures. The `conformance` feature enables that binary's model driver and
`serde_json/raw_value`. Neither is an installed host or qualification producer.
Build identities bind source/build inputs, compiler, target and enabled features;
changing those inputs requires fresh identities and qualification.

Run from the repository root:

```sh
make -C tools/gomad build
make -C tools/gomad validate
make -C tools/gomad fmt-rust
make -C tools/gomad lint-rust
make -C tools/gomad test-wasm GOMAD_STOCK_GO=/absolute/stock/go1.27.1/bin/go
```

`make generate` renders shared Go/Rust wire codecs from the retained schemas;
`validate-protocol` checks their generated bytes. `validate-replay-plan` compares
two fresh Go corpus generations and runs the Rust replay-plan tests.
`validate-model-corpora` builds the conformance driver, preserves it as
`gomad-model-conformance` under the shared target, restores the ordinary reference
transport, and runs retained Go and linked Rust model checks twice.
`test-rust-engine` runs the standalone transport corpus with `reference-helper`
and repeats it in the supported diagnostic/profile modes. Cargo's default
workspace build produces the Rust host without that standalone binary.

The shared helper transcript fixtures live in
`rust/wasmhost/tests/testdata/helper_transcript`. After reviewing an intended
semantic change, regenerate from the repository root:

```sh
GOMAD_HELPER_CORPUS_REGENERATE=1 cargo +1.99.1 test --release --locked \
  --manifest-path tools/gomad/rust/Cargo.toml -p gomad-wasmhost \
  --features reference-helper --test helper_corpus
```

Regeneration checks repeated executions for equality. A second regeneration must
leave the corpus byte-identical. Passing a model or projection corpus does not
establish live-runtime, replay or performance qualification.

## Determinism contract

The checked-in [inventory](determinism/inventory.json)
(`gomad.wasm-determinism-inventory/v1`) records influences as `controlled`,
`recorded`, `rejected` or `escape`. Rust inventory tests derive helper imports,
engine configuration and source sites and compare them with reviewed rows.
Retired Go sites retain their historical identities; the final Rust host site
inventory and receiving live regressions remain qualification obligations.

The inventory pins the cooperative compiler guard, workspace lockfile engine
version and Rust toolchain with a review date. Dependency changes require
reviewing the rows and appending a version review to
`determinism/review-history.json`. The accepted ledger prefix is independently
anchored; routine changes preserve that prefix. The append-only
`determinism/identity-history.json` preserves accepted ID/site pairs. Retired
sites retain their original identities and explicit refusal disposition; their
history grants no wildcard coverage to current source hits.

`make -C tools/gomad validate-wasm-determinism` runs the Rust inventory tests.
Final acceptance also requires the named live regressions, complete host-site
coverage, authenticated candidate identities and retained runtime/workload/replay
receipts. Quote a determinism bound only for the exact candidate, host, profile
and workload named in those receipts.
