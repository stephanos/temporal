# Testpilot schema simplification research

The strongest opportunities are to adopt the already accepted CEL and Duration representations, consolidate the two evidence-lifting representations, and normalize repeated correlated states and results. Several smaller declarations also encode information that admission already derives. These changes can reduce both the schema and the implementation without reducing supported behavior. Replacing every domain message with a generic standard message would obscure the remaining execution and verification contracts.

This sweep covers all ten files under [testpilot/v1](../proto/internal/temporal/server/api/testpilot/v1), their execution and verification consumers, lowering, conformance, and runtime tests. It is research only. The architectural constraints are the [specification](UMPIRE4_SPEC.md), [vision](UMPIRE4_VISION.md#high-level-architecture), and [module map](UMPIRE_MODULES.md): a Case is standalone and producer-neutral; Testpilot does not import Umpire; provenance does not determine runtime behavior; admission precedes Driver I/O. The [IR schema research](UMPIRE_IR_SCHEMA_RESEARCH.md) and [CEL investigation](UMPIRE_CEL_RUNTIME_RESEARCH.md) already establish adoption of canonical CEL AST plus native evaluation and migration to `google.protobuf.Duration`.

The inventory is **1,621 lines, 115 top-level messages and 26 enums**; 608 lines (37.5%) are comments. The largest file is 264 lines. Preserve the comments: file size here is not evidence of excessive behavior. The main opportunity is fewer competing representations and repeated artifacts, rather than another broad file split.

## Standard representations

**Replace the expression language with CEL, including its native evaluator.** `expression.proto` defines eight expression alternatives plus custom operators and references. Those expressions serve instruction inputs, guards, Contract predicates, evidence guards, and correlated conditions. Some sites admit only a restricted shape: correlated triggers and responses are currently presence/equality tests, and evidence field assignments are literals or paths. CEL supplies the common representation; each domain still determines which variables, functions, types, and AST forms are authorized. The separate correlated evaluator is another migration target, not a reason to retain a second Boolean language. [Expression schema](../proto/internal/temporal/server/api/testpilot/v1/expression.proto), [correlated admission](../common/testing/testpilot/internal/verification/correlated_prepare.go), [correlated evaluation](../common/testing/testpilot/internal/verification/correlated.go), [evidence binding](../common/testing/testpilot/internal/execution/dataflow.go).

Do not stop at wrapping existing expression nodes in CEL leaves. Let CEL own ordinary operations, while descriptor admission, scope restrictions, exact capture ordinals, and model-fact collection semantics remain explicit bindings. The accepted investigation records intentional semantic choices still needed for absence, enum equality, numbers, errors, and resource charging. CEL integration must also replace expression walkers in lowering, instance expansion, environment-reference discovery, and canonicalization. [CEL migration decisions](UMPIRE_CEL_RUNTIME_RESEARCH.md), [rule expansion](../common/testing/testpilot/internal/ir/rule_instances.go), [localization](../tools/umpire/lower/internal/producer/localize.go).

**Co-design runtime value migration with CEL.** The custom `Value`, `EnumValue`, `ValueList`, `ValueMap`, and `ValueMapEntry` are close to CEL's standard runtime value family. Standard signed and unsigned integer fields remove custom decimal-string validation; CEL's enum representation carries type and numeric value. This is a credible replacement to investigate as part of adoption, rather than indefinitely maintaining parallel value containers. The boundary adapter must preserve authoritative descriptor lookup, opaque `Any` handling, bytes, typed maps, unknown enum policy, and narrowing for protobuf fields. A stock CEL conversion helper is not automatically that adapter. [Current values and types](../proto/internal/temporal/server/api/testpilot/v1/value.proto), [runtime values](../common/testing/testpilot/internal/ir/runtime_value.go), [descriptor binding](../common/testing/testpilot/internal/ir/type.go).

CEL's [runtime-value schema](https://github.com/google/cel-spec/blob/master/proto/cel/expr/value.proto) covers signed/unsigned integers, bytes, objects, lists, maps and typed numeric enums. An isolated probe against CEL-Go v0.32.0 verified exact `MinInt64`, `MaxUint64` and list-contained `9007199254740993` round-trips. It also confirmed two adapter gaps: `ProtoAsValue` rejects the schema's enum arm, and an unregistered opaque `Any` cannot be decoded. The [implementation](https://github.com/cel-expr/cel-go/blob/v0.32.0/cel/io.go) uses global protobuf resolution and discards unknown object fields when decoding. Consequently, reuse the value schema with an explicit descriptor-aware conversion policy; do not route opaque or catalog-only messages through that helper indiscriminately. This result supports value-schema reuse while identifying necessary boundary work.

`ModelValue` is different: its definition ID and finite-domain spelling identify a model atom. Correlated states, actions, outcomes, and facts use it; it is not a boxed protobuf runtime value. Keep that distinction through both migrations. Likewise `ValueType` expresses descriptor-exact request/response admission, including integer wire kinds, singular/list/map restrictions, and opaque handles. CEL's expression types alone do not replace that contract. [Value schema](../proto/internal/temporal/server/api/testpilot/v1/value.proto), [correlated state matching](../common/testing/testpilot/internal/verification/correlated.go).

**Use Duration for elapsed-time quantities.** The seven fields are instruction timeout, polling interval, wait-hint bound, the two Program duration ceilings, Contract elapsed deadline, and RunEvent elapsed coordinate. Event counts, attempt counts, source ordinals, correlated transition bounds, and percentages remain numbers. Validate nonnegative/positive values as appropriate, whole-millisecond precision where current consumers require it, and conversion overflow. A Run's elapsed coordinate remains monotonic time since opening, not a `Timestamp`. Preserve the distinction between absent/default and explicitly supplied values. [Instruction schema](../proto/internal/temporal/server/api/testpilot/v1/instruction.proto), [Program limits](../proto/internal/temporal/server/api/testpilot/v1/program.proto), [deadline](../proto/internal/temporal/server/api/testpilot/v1/contract.proto), [RunEvent](../proto/internal/temporal/server/api/testpilot/v1/run.proto).

The schema already reuses Temporal `Command`, Nexus response/error, `Payload`, `Failure`, and protobuf `Any`. Continue that approach. `google.protobuf.Struct` would lose typed integer/bytes/message distinctions; `FieldMask` does not describe Testpilot's selectors, presence, oneof arms, or wildcard reads. `google.rpc.Status` does not directly replace `InstructionOutcome`: protocol, SDK, timeout/cancellation, value, activity-attempt, and delivery-admission information have different meanings, and some current protocol-code strings are Driver codes rather than gRPC codes. [Instruction payloads](../proto/internal/temporal/server/api/testpilot/v1/instruction.proto), [path grammar](../proto/internal/temporal/server/api/testpilot/v1/expression.proto), [delivery codes](../common/testing/testpilot/temporal/delivery_control.go), [polling codes](../common/testing/testpilot/temporal/server/session.go).

Do not replace `ValueType` with `google.protobuf.Type`: the [upstream schema](https://github.com/protocolbuffers/protobuf/blob/main/src/google/protobuf/type.proto) now explicitly discourages new use as a descriptor substitute. Reusing `FieldDescriptorProto.Type` just for `ScalarKind` is possible but low priority: enum numbers differ, its default is not our unspecified sentinel, and non-scalar kinds need rejection. Keep descriptor-exact admission unless a replacement demonstrably removes more translation than it adds. Likewise, [google.rpc.Status](https://github.com/googleapis/googleapis/blob/master/google/rpc/status.proto) could represent a deliberately separated RPC failure, but is not a generic Testpilot outcome. The existing `protocol_code` comment promises gRPC names more narrowly than current Driver behavior; resolve that naming/contract discrepancy if redesigning outcomes.

## One declaration for evidence lifting

Today an RPC response can spell a lift inline with `CorrelatedEvidenceRule.scope/source/operation/kind/fields/guard`, or name `evidence_id` and obtain that information from `Program.evidence`. The binder has separate paths, and explicitly rejects mixing both spellings. That is genuine representational duplication. A declaration-backed lift is already the producer's normal form. [Inline/declaration schema](../proto/internal/temporal/server/api/testpilot/v1/correlated.proto), [dispatch between forms](../common/testing/testpilot/internal/execution/dataflow.go), [exclusive-form check](../common/testing/testpilot/internal/execution/evidence.go), [producer](../tools/umpire/lower/internal/producer/build.go).

Make all lifts refer to one generalized declaration. Move the inline form's capabilities into that declaration before retiring the inline fields: arbitrary admitted projected-value guards, scope values read from paths, constant evidence fields, and ordered first-match selection. Existing declarations have literal scopes and path-only fields; history declarations derive a presence guard from an event arm. They cannot represent all currently supported inline lifts unchanged. The runtime tests exercise two overlapping scheduled-event guards where the first wins, integer operation keys, unclaimed records, and absent paths. Those are supported capabilities even though generated model Cases generally use references. [Declaration schema](../proto/internal/temporal/server/api/testpilot/v1/program.proto), [evidence lift tests](../common/testing/testpilot/internal/execution/evidence_lift_test.go).

A useful target is a declaration that owns source identity, projected-value schema/source, operation key, scope/field expressions, and guard; a response lift owns an ordered list of declaration IDs plus its Observation destination. Preserve source-specific selection rules: inline response lifts use first-match order, while overlapping RunEvent declarations fail the Run. Preserve the single emitter's dense ordinal stream, controller ownership, causal parent construction, and read/poll behavior. Unification should eliminate duplicate shape binding, not silently unify different selection policies. [Evidence-source admission](../common/testing/testpilot/internal/execution/evidence.go), [response projection](../common/testing/testpilot/internal/execution/response_read.go), [source tests](../common/testing/testpilot/internal/execution/evidence_source_test.go).

Do not automatically delete the Contract's evidence policies after consolidating Program declarations. Program fields describe extraction; `RETAIN`, `REDACT`, and `REJECT` govern evidence admissibility and what a correlated rule may retain. Contract source/scope checks also validate externally supplied evidence. The current runtime admits correlated Contracts without `Program.evidence`, so deriving every Contract catalog from that list would remove a supported authoring path unless its information is migrated explicitly. [Correlated admission](../common/testing/testpilot/internal/verification/correlated_prepare.go), [evidence validation](../common/testing/testpilot/internal/verification/correlated.go), [generic correlated fixture](../common/testing/testpilot/internal/verification/correlated_test.go).

## Normalize correlated state and result data

`CorrelatedTransition` serves two roles: a complete transition-table row and a projection output with no prior state. Projection outputs repeat action, resulting state, state fields, outcome, and facts from the full table. Admission checks equality of that repeated result, and execution searches for the same result at the operation's current prior state. This suggests an explicit result table: transitions reference `(prior_state, result_id)`, and projection rules carry ordered result IDs. A result owns action, destination state, outcome, and facts once. [Schema](../proto/internal/temporal/server/api/testpilot/v1/correlated.proto), [`sameResult` and membership checks](../common/testing/testpilot/internal/verification/correlated_prepare.go), [runtime continuity checks](../common/testing/testpilot/internal/verification/correlated.go), [producer construction](../tools/umpire/lower/internal/producer/correlated.go).

Referencing an arbitrary full transition row would be wrong: one result may be legal from several prior states, and a projection output deliberately does not choose its prior. Preserve the ordered output sequence because one evidence item may produce several semantic steps. Keep full transition authorization and causal submission checks. This normalization removes repeated results while retaining the independent checks the runtime currently performs.

A state table can further store each complete `(ModelValue atom, ordered fields)` once, replacing `initial_state` plus `initial_state_fields` and repeated prior/result state-field lists with local state references. The complete pair is the identity: a test explicitly proves that equal atoms with different fields are different runtime states. Do not derive fields solely from an atom or discard the atom for structured states; predicates can read both. Interning by the full state value preserves current support while making the wire shape and continuity checks simpler. [State schema](../proto/internal/temporal/server/api/testpilot/v1/correlated.proto), [state identity test](../common/testing/testpilot/internal/verification/correlated_state_test.go).

A corpus measurement shows why this is worth investigating: the 20 generated Cases contain 112 transition rows and 65 projection-output rows. Transition arrays occupy 105,988 bytes and output objects 37,958 bytes out of 415,843 compact-JSON bytes (34.6% together). This is their current footprint, not an achievable savings estimate. Removing prior-state fields yields 105 distinct transition results when counted separately within each Case, so repeated projection outputs and state fields are the more obvious duplication than transition-result repetition alone.

Measure artifact-size and admission-cost improvements before introducing a separate global table of every `ModelValue`. State/result normalization follows existing semantic boundaries; universal interning would add indirection throughout the schema. Keep local IDs deterministic and charge referenced/expanded work so compression does not evade existing limits.

## Smaller simplifications with concrete support

| Candidate | Recommendation and boundary |
| --- | --- |
| `ContractRule.kind` | Remove in the next format: deadline present means bounded liveness; absent means safety. Admission currently enforces exactly this equivalence, and execution uses the admitted deadline. Keep deadline target and clock validation. |
| `CorrelatedRule.clock` / `CorrelatedClock` | Remove the field and single-choice enum; define the bound as operation transitions in the schema. No other clock is admitted. A future distinct clock should have a distinct typed bound. |
| `ContractSupportKind` | Replace its two meaningful values with an explicitly present Boolean if explicit declaration remains required. The evaluator only tests whether to add the matching event to support. |
| `ReadSource.single` | Derive singular-versus-repeated message selection from the bound response path. Both forms already have descriptor-checked behavior; eliminate the redundant Boolean. |
| `ReadEvidence.once` and interval | Consolidate into one read policy during Duration migration: for example, absent interval means one read and present positive interval means polling. This intentionally changes how omitted policy is admitted; document it and retain timeout/interval bounds. An explicit oneof is an alternative if omission must still reject. |
| `After.instructions` / `AwaitInstruction.instruction` | Use local instruction IDs where admission already requires the enclosing entrypoint. Keep cross-entrypoint references at sites that actually admit them. Preserve the `After` wrapper: absent means previous instruction, while present-empty means no dependencies. |
| Six singleton oneofs | Replace scalar-only presence wrappers with proto3 `optional`; timeout becomes message presence through Duration. This reduces generated wrapper APIs, not domain expressiveness. |
| Eight empty marker messages | Reuse `google.protobuf.Empty` for surviving oneof markers whose arm already identifies the meaning. Several reference markers disappear with CEL. This is small cleanup, not the main payoff. |

Evidence: [rule admission](../common/testing/testpilot/internal/verification/prepare.go), [support evaluation](../common/testing/testpilot/internal/verification/evaluator.go), [correlated clock admission](../common/testing/testpilot/internal/verification/correlated_prepare.go), [read policy checks](../common/testing/testpilot/internal/execution/evidence.go), [dependency admission](../common/testing/testpilot/internal/execution/prepare.go), and the [Case](../proto/internal/temporal/server/api/testpilot/v1/case.proto), [instruction](../proto/internal/temporal/server/api/testpilot/v1/instruction.proto), [Run](../proto/internal/temporal/server/api/testpilot/v1/run.proto), [value](../proto/internal/temporal/server/api/testpilot/v1/value.proto), and [expression](../proto/internal/temporal/server/api/testpilot/v1/expression.proto) schemas.

Rule instances are already a useful condensation: one machine and typed parameters replace repeated near-identical rules. Their expansion-equivalence and expanded-ceiling tests justify keeping that support. Ordinary single-assignment captures and correlated occurrence streams likewise differ in ownership, lifetime, and addressing. A generic capture bag or universal opcode payload would save declarations while moving essential distinctions into scattered checks. [Instance tests](../common/testing/testpilot/internal/verification/instances_test.go), [ordinary capture schema](../proto/internal/temporal/server/api/testpilot/v1/contract.proto), [correlated capture schema](../proto/internal/temporal/server/api/testpilot/v1/correlated.proto).

## File organization and compatibility

All ten files have a coherent owner, but `correlated.proto` currently mixes evidence extraction, evidence transport, and verification. Extract a leaf `evidence.proto` containing the common evidence identity/value and lifting declarations, and leave correlated state/rule semantics together. Move the generic `ModelValue` declaration beside its correlated consumers if `value.proto` becomes primarily a standard-value adapter. `event.proto` usefully breaks the dependency between expression references and Run payloads; reconsider it after CEL removes those references, not by merging it into `run.proto` first. Keep Program/Instruction and Contract/Run boundaries visible. File count is not a success metric. [Import graph and definitions](../proto/internal/temporal/server/api/testpilot/v1), [module ownership](UMPIRE_MODULES.md).

`SourceLocation` includes producer-relative coordinates and provenance; standard descriptor source locations do not directly express the same contract. Keep it local unless a genuinely common leaf emerges. Case provenance contains definition bindings, local-name mappings, value fingerprints, correlated property bindings, gaps, and abstraction claims. Runtime indifference does not make them dead: lowering and conformance interpret them, and they participate in canonical Case identity. Projection identity/fingerprint repeated between Contract and provenance is a possible later ownership cleanup, but moving it requires updating those checks and preserving generic Cases. [Case provenance](../proto/internal/temporal/server/api/testpilot/v1/case.proto), [lowering admission](../tools/umpire/lower/lower.go), [conformance evidence](../tools/umpire/conformance/evidence.go).

Admission currently accepts exactly format 1.0. CEL types, Duration, normalized tables, enum replacements, or changed defaults need a deliberate new-format conversion. Integer-to-message and differently numbered enum substitutions are not in-place wire migrations. Reserve retired field numbers/names, regenerate Go and Scala APIs, update canonical Case generation and identities, and preserve historical Case/Run pairs for replay. A singleton-oneof-to-optional change can preserve field wire values but still changes generated APIs and descriptors. Even a declaration-only file move changes descriptor file identity and generated file layout. [Format checks](../common/testing/testpilot/internal/execution/prepare.go), [recorded Case identities](../common/testing/testpilot/recordedrun/recordedrun.go), [protocol tests](../common/testing/testpilot/protocol_test.go).

The acceptance evidence should include generated Cases and hand-authored runtime fixtures, online/offline evaluation agreement, correlated causal buffering, same-atom/different-fields states, exact capture ordinals, overlapping lift rules, default/presence handling, and Profile ceilings. Ordinary and correlated monitor machines should retain their different clocks and evidence lifecycles. Runtime tests were inspected, not rerun. The only new executable check was the isolated CEL value-conversion probe: `mise exec -- go test -tags test_dep -run TestValueReuseBoundary -count=1 -v .` passed in `/var/folders/k8/tl9x33wj7mz_cw1z_420xzs80000gn/T/umpire-cel-probe-t8lpj7f5` (`value_reuse_test.go`). No production source, schema or dependency changed.

## Prioritized recommendations

1. **Implement the accepted CEL AST and native-evaluation direction**, co-designing a standard runtime-value adapter and retiring duplicate predicate machinery. Keep model atoms and descriptor-exact admission separate.
2. **Migrate the seven duration fields together**, preserving defaults, monotonic elapsed coordinates, supported precision, and overflow rejection. Include polling-policy simplification and singleton-presence cleanup in the versioned design.
3. **Unify evidence declaration and lifting**, carrying forward inline guards, dynamic scopes, literal fields, ordered matching, and source-specific ambiguity rules before deleting the old representation.
4. **Normalize correlated results and complete states**, with ordered result references and state identity over atom plus fields. Demonstrate unchanged continuity, causal authorization, verdicts, and bounded work.
5. **Remove derived fields and redundant wrappers**: rule kind, fixed clock, read cardinality Boolean, redundant local entrypoint references, and surviving empty markers. Preserve meaningful absence and explicitness where required.
6. **Reorganize files around evidence versus verification after those changes**, avoiding new Umpire↔Testpilot dependencies and generic-message substitutions that merely move checks elsewhere.
7. **Gate the migration on full supported-surface fixtures and historical artifact handling**, not generated-corpus frequency. Version, regenerate, compare categorized semantic differences, and verify execution, conformance, replay, and identity boundaries together.
